# Scoped updates

Read this when revising an existing brief or incorporating feedback.

Find the exact requested change and its source. Compare it with the canonical decision before editing. A comment about one visual layer does not authorize a different task flow, access rule, persistence policy or completion condition.

Keep a compact change record: affected decision or section; before; after; reason and source; decision status. Separate a proposed improvement from the user's selected change. Reuse stable IDs when they exist. Preserve the rest of the accepted contract, including reasons and exclusions.

Check directly dependent observations, completion criteria, experiment tasks and design/domain artifact pointers for contradictions. Identify which objects, actors, states, invariants and return paths the change affects. Pass that bounded impact to the owning role; do not redesign unaffected flows. An update to intent does not update the observed implementation state until there is evidence. If a new canonical file is necessary, link its predecessor as superseded and mark the older file as historical when it is in the authorized edit scope. Otherwise record the replacement relation in the current brief and handoff.

Done when the scoped change and reason are traceable, unaffected decisions survive, and readers can find the current authority without treating a historical document as instructions.
