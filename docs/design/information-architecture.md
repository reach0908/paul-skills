## What it does

Organize agreed product content into destinations, labels and navigation. Every scoped content type has a traceable home; keeping an existing structure is a valid result.

## When to reach for it

Type `/information-architecture`, or the agent reaches for it automatically when a task fits.

Use it when the product scope is settled but people still need clear places to find its information. It defines destinations, not screen layouts.

## Common questions

**Can it start without a separate product brief?**

Yes, if the conversation already supplies the audience, retrieval tasks and fixed decisions. Missing access or ownership policies stay open instead of becoming invented navigation rules.

## It's working if

- A content-to-destination map shows stable IDs and user-facing labels.
- Each retrieval task has an entry, target and return path, or a named unresolved dependency.
- The next step can reuse the map without repeating the product interview.

## Where it fits

It is the first design chain step when information structure remains open. Pass its destinations to [user-flow](https://github.com/reach0908/paul-skills/blob/main/docs/design/user-flow.md), which owns task transitions, then [wireframe](https://github.com/reach0908/paul-skills/blob/main/docs/design/wireframe.md), which owns screen composition. See [ask-matt](https://github.com/reach0908/paul-skills/blob/main/docs/engineering/ask-matt.md) for the full routing map.
