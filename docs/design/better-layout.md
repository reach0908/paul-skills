## What it does

Reviews grouping, alignment, reading order, spacing and responsive structure. It tests whether the layout still works when resized, translated or mirrored. An existing spacing scale or usable density is respected; a different preferred gap is not a finding.

For competing emphasis and simplification, it compares intended communication with a labeled observation and preserves required information, frequent actions and the approved visual identity. Action visibility follows the task rather than a fixed count.

## When to reach for it

Type `/better-layout`, or the [agent](https://www.aihero.dev/ai-coding-dictionary/agent) reaches for it automatically for clipping, ordering, grouping or responsive structure. Use [better-typography](https://github.com/reach0908/paul-skills/blob/main/docs/design/better-typography.md) for wrapping and truncation within text.

## Hold structure until it breaks

Breakpoints follow the content and task. Related controls stay grouped, primary actions remain distinct, and translated or longer content gets room to grow. The report needs a visible failure such as overlap, clipping, a broken mirror or a misleading group.

## Common questions

**What if I mention this domain while reviewing staged changes?**

The automatic catalog makes the change-review route take priority over the domain words, before this domain document is loaded. [better-interface](https://github.com/reach0908/paul-skills/blob/main/docs/design/better-interface.md) first supplies the explicit change-review command. This domain resumes after the authorized handoff; ordinary screen audits and requested fixes still enter it directly.

**Must the mobile page look like a smaller desktop page?**

No. Reading order and task importance govern the narrow layout. The [skill](https://www.aihero.dev/ai-coding-dictionary/skill) preserves useful structure and changes it when the content no longer fits.

**Will it replace our spacing tokens?**

It uses the project scale and density. Its example numbers are defaults for projects without a system.

**Can an AI review pass the three-second test?**

It can provide an untimed precheck or a fresh AI observation. A human three-second result needs an actual timed exposure and recorded response. Missing or stale screenshots leave visual conclusions unverified.

**Will unfinished prototype links or deliberate empty space block a review?**

The review checks what the artifact promises to implement. A destination outside a partial prototype's scope remains pending; a missing required implementation is still actionable. It distinguishes source inspection from an observed interaction. Approved composition stays intact unless specific evidence connects it to a task or communication problem. Unconfirmed risks remain verification notes.

## It's working if

- Requested widths and content states are named in the evidence.
- A proposed change fixes a demonstrated grouping or space problem.
- Translated text and reading order remain usable where they were in scope.

- First-impression claims identify the method, exact screen and evidence limits; a clear screen can stay unchanged.
