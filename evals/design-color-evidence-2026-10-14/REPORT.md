# 색상 답변의 검증 범위 일관성

완료. 수정본은 새 Codex 세션 6/6, Claude 세션 6/6에서 통과했다. 원래 모순은 수정 전후의 같은 요청 3회씩에서 재현되지 않아 원인을 확정하거나 제거했다고 판단하지 않는다. 검증 범위를 명확히 하는 예방 보완으로 정리했다. 전역 설치는 0.4.2를 유지한다.

## 관찰된 문제와 재현

[0.4.2 배포 검증](../design-routing-0.4.2-release-2026-10-14/REPORT.md)의 Codex `normal-better-colors` 답변은 투명색·이미지 위 색상을 선언값만으로 검증할 수 있다고 적은 뒤 실제 배경의 최악 조건을 별도로 측정해야 한다고 했다. 입력이 없고 실제 화면을 관찰하지 않은 준비 단계에서 검증 범위를 일관되게 설명하지 못했다.

기존 실패 세션 `01a13ab6-e536-7791-8e91-0a07d0bc6453`의 [답변과 판정](../design-routing-0.4.2-release-2026-10-14/codex/normal-better-colors.json)을 그대로 보존한다. 이 세션은 올바른 SKILL.md와 여섯 참고 문서의 전문을 읽었다. 따라서 이 관찰에서 잘못된 설치, 스킬 미발견 또는 참고 문서 누락은 원인으로 뒷받침되지 않는다.

기존 버전의 새 Codex 세션에서 같은 한국어 요청을 3회 반복했으나 해당 모순은 0회였다. 같은 모델 `gpt-5.6-sol`과 `xhigh`를 사용했다. 새 시험은 개인 호스트 문맥을 한 번 복제한 격리 환경이므로 기존 전역 세션과 경로까지 동일한 재현은 아니다. 두 비교군은 같은 복제 문맥을 사용한다.

## 결과

| 도구 | 기존 0.4.2 | 수정본 | 원래 모순의 같은 요청 재현 (기존 → 수정본) |
| --- | --- | --- | --- |
| Codex | 6/6 | 6/6 | 0/3 → 0/3 |
| Claude | 5/6 | 6/6 | 0/3 → 0/3 |

총 24개 새 세션에서 23개가 통과했다. 수정본만 보면 12/12이다. 실패한 기존 Claude `baseline-original-3`은 원래 모순의 재현이 아니다. 그 답변은 `text-disabled`, `border-separator`를 실제 비활성·장식 용도 확인 없이 이름만으로 면제했다. [실패 답변](claude/baseline-original-3.json)과 [전체 의미 판정](manual-review.json)을 남겼고, 수정본의 같은 요청에서는 이 단정을 관찰하지 않았다. 작은 표본으로 이 부수 오류까지 일반적으로 해결됐다고 주장하지 않는다.

수정본에서 확인한 동작은 다음과 같다.

- 원래 준비 요청 3회씩: 생성·계산·화면 확인을 완료했다고 주장하지 않고 필요한 입력과 예정된 순서를 설명했다.
- 불명확한 사진 배경: 명시한 조건에서의 최악 값 계산과 실제 카드의 미확인 상태를 구분했다.
- 명시 호출: 주어진 불투명 쌍과 합성 쌍의 계산을 허용했다. 전체 `contrast.md` 로드를 확인했고 활성 placeholder·readonly와 실제 disabled 면제, APCA의 보조 역할을 구분했다.
- staged 리뷰: 두 도구 모두 `better-interface`만 먼저 읽고 `interface-review staged` 명시 호출로 넘겼다. 색상 도메인 선행 로드, 저장소 검사나 사용자 전용 리뷰의 무단 실행은 없었다.

모든 새 세션에서 올바른 비교군의 원문 로드, 자동 디자인 목록 12개, 도구 오류 없음, 입력 파일 보존을 확인했다. Claude의 명시 호출 목록 17개도 일치했다. 목록 확인은 17개 스킬 각각의 행동을 다시 시험했다는 뜻이 아니다. 관찰된 Claude 도구는 Skill·Read·Glob이며 Codex는 네이티브 실행 도구였다. 별도 브라우저 실행은 관찰되지 않았다.

[RESULTS.json](RESULTS.json), [검증 코드](verify_evidence.py), [소스와 실행 환경](environment.json), [도구 범위](tool-scope.json)에서 근거를 추적할 수 있다.

## 원인 판단과 보완

| 가설 | 확인 결과 | 판단 |
| --- | --- | --- |
| 올바른 절차를 읽었지만 최종 요약에서 표현이 뒤집힘 | 과거 답변은 앞부분의 합성·측정 절차와 마지막 문장이 충돌한다 | 설명 가능한 가설이며 확정 원인은 아님 |
| 선언된 쌍의 계산과 실제 UI 검증의 경계가 약함 | 기존 Verification 문단은 두 작업을 나열하지만 결론에 남길 증거 상태를 정의하지 않는다 | 예방적으로 명확히 할 문서상 여지 |
| 실행 설정 차이 | 이번에는 xhigh를 고정했고 기존 실패도 xhigh였다 | 설정이 오류를 유발했다는 증거 없음. 노력 수준별 실험은 하지 않음 |

따라서 이번 변경은 **재현된 결정적 버그의 수리**가 아니라 **관찰된 응답 위험을 줄이는 검증 설명 보완**이다. 소수 표본의 통과로 재발 가능성이 사라졌다고 주장하지 않는다.

`better-colors/SKILL.md`의 Verification 문단만 바꿨다.

- 계산한 쌍: 색상과 합성 조건을 명시하고 그 조건에서의 대비만 설명한다.
- 실제 화면 확인: 실제 배경, 이미지 영역, 상태와 테마의 확인 범위를 기록한다. 면제는 실제 용도로 정당화한다.
- 미확인: 빠진 입력이나 관찰을 적고, 마지막 요약에서도 미확인 상태를 유지한다.

전체 플러그인의 파일 175개 중 변경한 설치 파일은 이 SKILL.md 한 개다. `contrast.md`, 여섯 분야의 자동 발견 설명, 명시 호출 정책, 라우터와 나머지 스킬은 동일하다. 문서 페이지, 출처의 로컬 digest, patch Changeset을 함께 갱신했다. `ask-matt`의 경로와 역할은 그대로 유효하므로 변경하지 않았다. 원본 출처의 import/review revision은 전진시키지 않았다.

## 고정 시험과 판정 방법

[PROTOCOL.md](PROTOCOL.md)와 [cases.json](cases.json)을 새 세션 실행 전에 고정했다. 각 도구에서 기존 버전 6회와 수정본 6회, 총 24개의 독립된 네이티브 CLI 세션을 사용했다. 기존 버전 시험 완료 후 수정본을 작성했다. 답변을 고르거나 실패를 지우기 위한 재실행은 하지 않았다.

각 비교군의 여섯 사례는 동일 요청 3회, 사진·알파 배경이 불명확한 경우, 합성 조건이 모두 주어진 경우 및 명시 호출, staged 변경 리뷰다. 마지막 두 사례는 활성 placeholder·readonly·disabled의 기준 구분과 라우터 선행 로드도 검사한다. 실제 브라우저와 제품 수정은 허용하지 않는다.

기계 검증은 실제 로드된 원문, 설치 파일 해시, 자동 발견 목록, 도구 오류, 입력 파일 보존과 독립 세션 ID를 확인한다. 의미 판정은 유지보수 에이전트가 답변 전체를 읽어 기록하며, 답변 해시와 연결한다. 외부의 독립된 사람이나 블라인드 심사자의 평가가 아니다. 자동 언어 판정기를 만들거나 호출 성공을 답변 품질로 대체하지 않았다.

기존 실패 답변을 실패로 유지하고, 누락·수정된 답변에 이전 판정을 붙이면 실패하는 회귀 검사를 추가했다. 이는 판정 연결의 무결성 검사이며, 새로운 한국어 모순을 자동으로 알아내는 검사가 아니다.

재사용한 배포 수집기는 처음에 전역 설치를 요구해 격리 시험을 실패로 분류했다. 해당 조건만 실제 프로토콜에 맞게 교정했다. [초기 수집기](initial-collect.py.txt), [변경 이유와 초기 판정](grader-amendment.json)을 남겼으며, 의미 판정 기준은 바꾸지 않았다.

## 표준과 계산 범위

[WCAG의 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)은 전경과 배경 색상으로 대비를 평가하며 활성 입력의 placeholder도 포함한다. [W3C 합성 규칙](https://www.w3.org/TR/compositing-1/#simplealphacompositing)은 색상·알파·배경이 알려진 경우의 계산을 정의한다. 따라서 투명색은 언제나 계산 불가라고 막는 대신, 주어진 조건에서의 계산과 그 조건이 실제 화면에 적용됐다는 확인을 구분했다.

기존 Codex의 사진 사례는 단순 sRGB 합성이라는 가정 아래 흰 사진의 최악 값을 계산상 약 3.35:1로 제시하고 실제 측정과 구분했다. 계산 도구 호출은 관찰되지 않았으므로 모델이 도구로 측정했다고 기록하지 않았다. 유지보수자가 별도로 계산한 결과는 [numeric-check.json](numeric-check.json)에 있다. Claude의 부가적인 손계산 APCA·알파 조정 추정값 전체는 이번 검증 범위가 아니다.

## 한계

- 원래 모순의 정확한 내부 생성 원인은 알 수 없으며, 최소 재현 조건이나 개선 효과의 통계적 유의성을 입증하지 않았다.
- 세 번의 동일 요청은 재현 관찰이다. 전체 디자인 스킬의 원본 동등성, 모든 17개 역할의 재검증, 모델 추천의 근거가 아니다.
- 토큰 의미, 도메인 지식과 장문의 모든 부가 수치까지 완전 검증한 시험이 아니다. 관찰한 추가 과장은 별도로 실패로 기록한다.
- 브라우저 렌더링, 제품 접근성 인증, 실제 화면 대비 통과를 수행하거나 주장하지 않는다.
- 수정본은 세션별 격리 설치에서 검증하며, 공개 배포 및 일상용 전역 설치 갱신은 이번 작업에 포함하지 않는다.

## 검증과 최종 판단

- `npm run check`: 38개 테스트 및 56개 출처 기록·44개 정식 스킬의 패키지 일관성 통과.
- 새 판정 무결성 테스트: 5/5. 과거 실패 유지, 누락·stale·실패 판정 차단, 답변 해시가 일치하는 통과 판정을 확인했다.
- `claude plugin validate . --strict`, `git diff --check`: 통과.
- `verify_evidence.py`: 24개의 고유 세션, 원문 및 답변 해시, 두 비교군의 한 파일 차이, 과거 실패 보존, 두 전역 설치 파일 175개씩의 불변을 확인했다. 이 무결성 통과가 기존 Claude의 의미 실패를 지우지 않는다.

Codex CLI 0.146.0의 gpt-5.6-sol/xhigh와 Claude Code 2.1.296의 claude-opus-5-5/xhigh에서 수행했다. Claude가 보고한 전체 금액은 **USD 8.1314994**이며 청구서가 아닌 호스트의 목록가격 추정치다. Codex의 금액과 실제 청구액은 확인하지 않았다. 전역 모델 설정은 바꾸지 않았다.

이번 수정은 범위가 작은 **정식 패치 후보로 수용 가능**하다. 근거는 새 문서의 실제 적용과 수정본 12개 사례의 통과이며, 오류 제거율 또는 전체 원본 대비 우월성의 증거는 아니다. 공개 게시, 릴리스 태그 생성과 전역 설치 변경은 수행하지 않았다. 일상 세션은 기존 0.4.2를 사용하며 이번 수정본의 결과는 격리된 새 CLI 세션 결과다.
