# 첫인상 관찰과 단순화 워크플로우 비교

2026-10-15. 상태: **5개 동작 파일 구현, 제한된 비교 평가 완료, 전면 통과 아님**. 병합·배포·전역 설치·사람 수용 확인은 별도다.

## 결론

수정판은 화면 의도, 보존할 정보, 관찰 방식과 미확인 사항을 더 명시적으로 연결했다. 동일한 low 설정에서 완료된 **8개 사례, 8쌍**의 답변을 비교했다. 수정판은 관련 7개 사례 모두 새 참조 전체를 읽었고, 와이어프레임은 화면별 첫 메시지를 명세에 남겼다. 와이어프레임 사례는 관찰을 요청하지 않아 새 참조를 읽을 필요가 없었다.

다만 **전반적인 디자인 품질 향상이나 전체 워크플로우 통과는 입증하지 못했다.** 브랜드 사례에서 수정판이 부분 구현 링크를 HIGH/Block으로 취급하고 취향에 가까운 제안을 섞었다. 낮은 추론 수준의 통합 리뷰 3개 사례에서는 양쪽 모두 기존 여섯 담당 스킬 호출 계약을 완수하지 않았다. 읽은 참조 수와 답변 내용의 개선을 전체 실행 성공으로 바꾸어 기록하지 않는다.

## 구현 범위

기준 main은 `154c1a615fa973cefaf7a046fa074082417e91d5`(0.4.3)이다. 동작 파일 차이는 다음 다섯 개뿐이며, 세 실행 프로필 모두 같은 수정판 바이트를 사용했다.

| 파일 | 바뀐 동작 |

| `skills/design/better-layout/SKILL.md` | 보조 행동 3개 초과 시 메뉴로 숨기던 일률적 규칙을 과업·빈도·상태 판단으로 교체; 조건부 참조 읽기 |
| `skills/design/better-layout/first-impression.md` | 의도·정확한 화면·관찰 종류·여섯 법칙의 담당·보존·재확인 절차의 단일 참조 |

문서 3개, 출처 등록, Changeset, 평가 자료와 평가 색인을 함께 갱신했다. 새 스킬이나 일곱 번째 리뷰 분야를 추가하지 않았다. `ask-matt`를 다시 읽었으며 역할과 경로가 같아 수정하지 않았다. 플러그인 명세, 호출 정책, `better-interface`의 진입 본문, `interface-review`, 나머지 스킬은 바이트 단위로 기준판과 같다. 기존 upstream import/review revision과 reconciliation digest는 유지했다. 이번 로컬 수정은 upstream 재조정 완료를 뜻하지 않는다.

설계 아이디어는 [Impeccable의 고정 소스](https://github.com/pbakaus/impeccable/tree/abf5779cabc20147fd9c013fa4705088c200bf8a)와 [Duarte glance test](https://www.duarte.com/resources/guides-tools/the-glance-test/)에서 선별했다. 원문·엔진·검출기 코드를 이식하지 않고 프로토콜을 독립 작성했다. 슬라이드의 glance test가 모든 UI에서 유효하다는 검증은 아니다.

## 평가 방법과 실행 제한

합성 HTML 6개를 Chrome 152.0.7977.82로 캡처하고, 화면이 없는 설명과 예약 흐름 명세를 추가했다. 입력 파일, 스킬 트리, 질문, 실행 코드, 프로토콜을 모델 실행 전에 해시로 고정했다. 각 세션은 별도 폴더와 세션용 플러그인 사본을 사용했다. 모델에는 과업과 원자료만 제공했고 정답·판정표·이전 답변은 주지 않았다.

실제 모델은 모두 `claude-opus-5-5`, 모델 실행 호스트는 Claude Code `2.1.300`이었다. Skill/Read/Glob/Grep만 허용하고 MCP와 hooks를 끈 세션에서 파일을 수정하지 않는 검토 또는 명세를 요청했다. 자동 발견 시험이 아니라 명시 호출 시험이다. 기준판과 수정판의 질문·입력·호스트 버전·모델·설정은 각 쌍 안에서 같다. 원본 작업 폴더와 전역 스킬 설치는 수정하지 않았다.

| 프로필 | 실행 / 완료 | 유효한 완료 쌍 | 실행 조건과 결과 |
| --- | --- | --- | --- |
| 초기 상속 설정 | 6 / 3 | 1 | 실제 추론 수준 값은 미노출. 240초 제한에 기준판 2개 시간 초과, 수정판 1개 비용 제한. 중단 |
| 명시 high | 4 / 2 | 0 | 양쪽 같은 500단어 응답 제한. 기준판 2개 비용 제한으로 중단. 완성된 모양의 답변이 있어도 native 실패는 완료로 세지 않음 |
| 명시 low | 16 / 16 | 8 | 양쪽 같은 500단어 제한, 180초/세션. 8개 사례 완료 후 합산 비용 여유 기준으로 중단 |

프로필을 바꾼 이유와 조건은 각각 [초기 계획](PROTOCOL.md), [high 보정 계획](CONTROLLED-PROTOCOL.md), [마지막 low 계획](BOUNDED-PROTOCOL.md)에 남겼다. 스킬과 의미 판정 기준은 바꾸지 않았다. 실패를 없애기 위한 합격률 재집계나 서로 다른 프로필의 결과 합산은 하지 않는다. 마지막 프로필은 예산 제약 조건의 비교이며 기본 설정의 성능을 대신하지 않는다.

총 26회 중 21회가 native 완료됐다. 최종 비용이 보고된 합계는 **USD 8.8712806**이다. 최종 비용 미보고 시간 초과 2개에 각 USD 1을 보수적으로 예약한 합계는 **USD 10.8712806**이다. 실제 청구액은 알 수 없다. CLI의 세션 비용 한도는 마지막 요청으로 초과될 수 있어, 마지막 프로필은 다음 두 실행의 한도 외에 USD 0.60 여유도 요구했다. 합산 USD 12 기준 안에서 멈췄다.

## 같은 low 조건에서 확인한 차이

아래 평가는 유지보수 에이전트가 답변 전체를 읽고 고정 기준으로 판단한 것이다. 사람의 블라인드 평가나 보정된 독립 심판은 아니다. 각 판정은 [응답 해시와 근거](manual-review.json)에 묶여 있고 [원 답변](responses/)과 [도구 영수증](receipts/)을 보존했다.

| 사례 | 기준판 | 수정판 | 해석 |
| --- | --- | --- | --- |
| 복잡한 랜딩 | 배지/장식 강조 문제를 찾고 요금·동의 유지 | 같은 원인을 찾고 의도·사전 예측·보존·재확인 pending을 연결 | 기록 계약 개선; 실제 전달 개선은 미측정 |
| 이미 명확한 화면 | 주요 위계 유지, 복구 링크 묶음 변경 제안 | 위계 변경 불필요, 보존과 관찰 한계 기록 | 불필요한 변경 감소 가능성. 기준판 대안이 나쁘다는 실증은 없음 |
| 전문가 대시보드 | 자주 쓰는 행동을 메뉴로 숨기지 않음. 확인이 필요한 fixture 누락을 조건부 HIGH/Block으로 제시 | 같은 행동을 유지하며 의도·예측·필수 정보와 미확인 누락을 구분 | 원래도 필요한 행동을 보존했으므로 숨김 문제를 고쳤다고 주장하지 않음 |
| 모바일 경고 | 정책보다 넓게 말하는 제목을 발견. 미구현 도움말 링크 삭제도 대안으로 제시 | 같은 제목 문제를 발견하고 정책·경고·두 버튼·도움말·포커스 보존 명시 | 필수 정보 보존이 더 분명함. 실제 수정/접근성 검증은 없음 |
| 읽기 화면 | CTA 불필요. 근거 없이 사람 테스트의 추가 가치가 적다고도 단정 | 읽기 목적에 맞춰 CTA를 만들지 않고 사람/새 AI 관찰 not_run 기록 | 근거 경계가 더 분명함 |
| 승인된 브랜드 | 정체성 유지, 미구현 링크를 fixture 한계로 유보 | 정체성은 유지하지만 미구현 링크를 HIGH/Block 처리; 빈 공간의 느낌을 이유로 시각적 추가 제안 | **부정적 관찰.** 부분 구현 범위와 취향을 더 엄격히 구분할 필요. 한 쌍으로 원인이나 발생률 확정 불가 |
| 현재 화면 없음 | r1 설명으로 r2 결과를 만들지 않음 | 동일하게 보류하고 unknown/not_run, 중립 관찰 절차를 구체화 | 양쪽 모두 결과 날조 없음; 새 절차 인계는 더 구체적 |
| 예약 와이어프레임 | 상태·행동·실패 복구·미결정 정책 전달 | 같은 내용에 화면별 첫 메시지와 의도/관찰 구분 추가 | 이번 변경의 직접적인 인계 효과 확인 |

요소 수 감소, 새 표의 존재, 법칙 이름 언급만으로 성공을 채점하지 않았다. 기준판이 동일한 의미를 충족하면 다른 표현이어도 통과로 보았다. 전체 승패 점수 대신 근거 보존, 과업 결과와 실행 계약을 나눠 보고한다.

## 실제 참조 읽기와 남은 실패

- low 수정판의 관련 첫인상 사례 **7/7**에서 `first-impression.md`의 모든 원본 줄과 일치하는 native Read 결과를 확인했다. 와이어프레임에는 요청되지 않은 테스트를 강제하지 않았고, 해당 참조를 읽지 않은 것이 맞다.
- 통합 리뷰 3개(랜딩, 경고, 화면 없음)는 low에서 **양쪽 모두 여섯 담당 전체 호출 0/3**이다. 일부 영역을 읽거나 읽지 않았음을 밝혔더라도 기존 실행 계약을 충족한 것은 아니다. low에서 완료한 답변을 전체 통합 리뷰 통과로 세지 않는다.
- 초기와 high의 수정판 랜딩은 여섯 담당을 호출하고 새 참조도 전부 읽었다. 하지만 같은 프로필의 기준판이 미완료여서 품질 비교 쌍으로 쓸 수 없다.
- low 기준판 8개 보고 비용 합계는 USD 1.4451416, 수정판은 USD 1.5825144다. 실행 시간 중앙값은 약 27.50초와 30.50초다. 표본이 작고 사례가 달라 일반적인 비용/시간 우열로 확장하지 않는다.
- 기본 명시 명령의 전체 주입 본문은 stream에 노출되지 않았다. 해당 플러그인 경로·버전·고정 해시·명령 확장 영수증과 후속 Read/Skill 호출을 확인한 것이며, 보이지 않는 본문을 직접 관찰했다고 주장하지 않는다.
- staged 진입과 동일 대시보드 반복은 마지막 비용 경계에서 **not_run**이다. 진입 본문과 호출 정책의 바이트 보존은 정적 증거이며 native 실행을 대신하지 않는다.

## 검증과 재현

[무결성 결과](VERIFICATION.json)는 질문/입력/스킬 해시, 정확한 5개 파일 차이, 프로필별 실제 시도와 미실행 목록, 동일 쌍의 모델/호스트, 응답 해시에 연결된 판정, 비용 경계를 검사한다. `integrity_pass: true`는 실패 기록까지 충실하다는 뜻이며 `full_workflow_pass`는 **false**다. [집계](RESULTS.json)에서 구분한다.

```bash
npm run check
claude plugin validate . --strict
claude plugin validate .claude-plugin/plugin.json --strict
python3 -m unittest discover -s evals/design-first-impression-2026-10-15 -p 'test_*.py' -v
python3 evals/design-first-impression-2026-10-15/verify.py
```

패키지 검사 38개, 무결성 경계 검사 4개, 수정한 스킬 3개의 quick validator, 두 플러그인 명세 검사와 변경 문서의 로컬 링크 14개를 확인했다. 무결성 테스트는 답변 변조, 오래된 의미 판정, 미완료 실행의 성공 취급, 부분 참조 읽기를 거부한다. 동작 문장의 문자열 일치를 품질 테스트로 쓰지 않았다.

native 원시 로그는 ignored `.scratch`에만 있다. 공개 자료에는 합성 입력, 정제한 최종/부분 답변, 필요한 호출·해시·판정만 넣었다. 실패 영수증은 원래대로 보존한다. 모델 재실행 스크립트는 원시 기록 덮어쓰기를 거부한다.

## 적용 판단과 다음 확인

이 패치는 사용자 검토가 가능한 상태다. **전면 통과, 기본 설정에서의 안정성, 실제 사용자 이해 향상을 주장할 근거는 없다.** 이번 작업은 기존 스킬 5곳을 수정하고 비교 증거를 남기는 범위이며 전역 설치나 릴리스로 이어지지 않았다.

다음 확인은 부분 구현 프로토타입의 범위와 실제 제품 결함을 구분하는 판단, 그리고 비용 제약에서도 전체 리뷰 계약을 생략하지 않는 실행 경로다. 이 보완을 별도 고정 후보로 비교할 때는 이번 실패와 기준판 응답을 유지해야 한다. 실제 사람의 3초 관찰, fresh AI 관찰, 수정 후 재관찰, 브라우저 상호작용·접근성 검증은 모두 별도 미실행으로 남긴다.
