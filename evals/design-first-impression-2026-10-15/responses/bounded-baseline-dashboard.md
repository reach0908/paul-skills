## 첫인상

화면은 복잡하다기보다 **밀도가 낮고 구조가 흐릿합니다.** 큰 제목과 18px 본문, 44px 버튼이 위쪽을 차지해서, 1180×780 캡처에서 표는 24건 중 3행만 보이고 아래는 비어 있습니다(`screen.png`). BRIEF는 숙련 작업자가 하루 수십 번 쓰고 행끼리 비교하는 게 중요하며 모든 기능이 범위 안이라고 합니다. 그래서 기능을 빼는 것보다 **묶음을 분명히 하고 밀도를 높이는 쪽**이 이 작업에 맞는 단순화입니다.

## 발견 사항

| 심각도 | 위치 | 현재 | 제안 | 이유 |
|---|---|---|---|---|
| HIGH (확인 필요) | `index.html:2` table | 24건 중 3행만 있고 나머지 21건으로 가는 단서가 없음 | "3/24건 표시"와 더 보기·페이지 같은 단서를 넣거나 전체 목록을 표시 | 숨은 내용에 단서가 없음. 다만 fixture라서 의도된 생략일 수 있음 |
| HIGH (확인 필요) | `index.html:2` table, 액션 행 | 상태는 `selected`인데 행 선택 표시(체크박스·강조)와 선택 건수가 없음 | 첫 열에 체크박스를 두고, 액션 바에 "2건 선택됨"을 표시 | 주 동작 "선택 건 출고 확정"이 무엇에 적용되는지 보이지 않음 |
| MEDIUM | 필터 행 / `.panel` | 필터와 액션이 똑같은 흰 버튼이라 구분되지 않음. 필터는 적용된 값도 보이지 않음 | 필터는 "날짜: 오늘 ▾"처럼 값을 보여 주는 칩으로, "지연만 보기"는 토글로 | 컨트롤의 역할이 구분되지 않아 잘못 누르기 쉬움 |
| MEDIUM | `.panel .row` → table | 액션 버튼 바로 밑에 표 머리글이 간격 없이 붙음. 그룹 사이 20px는 그룹 안 12px의 2배에 못 미침 | 그룹 사이 24px 이상. 액션 바를 표 위의 고정 툴바로 | 그룹이 잘못 읽힘 |
| MEDIUM | 표 행 | "지연 위험"과 "확인 필요"가 일반 텍스트 | 상태 열에 배지·아이콘을 두고 해당 행 배경을 강조 | 행 비교가 핵심인데 예외 행이 눈에 띄지 않음 |
| MEDIUM | 전역 스타일 | h1 38px, 본문 18px, td 패딩 12px, 수량이 주문번호와 한 칸에 합쳐짐 | 제목은 한 줄 요약으로 줄이고 촘촘한 표 밀도 적용. 수량, 택배사, 마감시각을 각각 열로 분리 | 반복 작업에서 한 화면에 비교할 수 있는 행 수가 적음. 택배사 필터는 있는데 택배사 열이 없음 |
| LOW | `th,td{text-align:left}` | 물리 방향 속성 | `text-align: start` | RTL 미러링 대비 |

## 단순화 구성안

1. **상단 한 줄:** 제목 · 대기 24건 · 마감 16:00 · 지연 위험 3건. 지연 위험 3건은 누르면 바로 필터가 됩니다.
2. **필터 바:** 적용된 값을 보여 주는 칩 5개와 초기화.
3. **고정 액션 툴바:** 선택 건수 + 주 동작 "출고 확정" 하나 + 보조 동작 4개(송장, 라벨, 담당자 변경, 보류). 자주 쓰는 동작이라 메뉴에 숨기지 않습니다.
4. **촘촘한 표:** 체크박스, 주문, 수량, 택배사, 마감, 재고, 담당 순서. 상태 열에 배지를 두고 전체 건수와 페이지 단서를 표시합니다.

DOM 순서는 지금처럼 필터 → 액션 → 표로 유지하면 됩니다.

## 확인 한계

- 브라우저를 쓸 수 없어서 320px 폭, 200% 확대, RTL, 고정 툴바 동작은 **확인하지 못했습니다.** 정적 코드와 캡처 1장(1180px, selected 상태)만 근거입니다.
- 사람을 관찰한 자료가 없습니다(BRIEF 명시). "복잡해 보임"과 작업 효율에 대한 판단은 추론입니다.
- 행 생략과 선택 표시가 fixture의 한계인지 실제 결함인지는 판단할 수 없습니다.
- 파일은 수정하지 않았습니다.

**결론: Block.** 두 HIGH 항목이 실제 화면에서도 같다면 출시를 막아야 합니다.
