# B01 / F01 화면 명세: 동네 도서관 좌석 예약

**입력:** `BRIEF.md`(리비전 정보 없음). 구현물, 렌더링, 브라우저 확인, 사용자 승인 모두 **없습니다**. 파일은 수정하지 않았습니다.

## 흐름 매핑
| 흐름 단계 | 화면/상태 |
|---|---|
| 날짜 선택 | S01 |
| 좌석 선택 | S02 |
| 확인 → 예약 확정 | S03, 성공 시 S03-OK |
| 예약 실패 | S03-ERR (같은 화면 안의 상태) |
| 유료 결제·가입 유도 | **제외** (범위 밖) |

## S01 날짜 선택
**정보 위계**
1. 단계 표시 (1/3 날짜)
2. 날짜 목록이나 달력. 휴관일은 선택할 수 없는 상태로 두고 사유를 글자로 표시합니다
3. 선택한 날짜의 운영시간

**행동**
- 주요 행동: `다음: 좌석 선택`. 날짜를 고르기 전에는 비활성입니다.
- 보조 행동: 다른 날짜 선택

**상태**
- 미선택
- 선택됨: 운영시간이 표시됩니다
- 휴관일에 포커스: 선택할 수 없다는 안내가 나옵니다

**모바일:** 운영시간을 날짜 선택 바로 아래에 두고, 주요 버튼은 화면 하단에 고정합니다.

## S02 좌석 선택
**정보 위계**
1. 선택한 날짜 요약. 누르면 S01로 돌아갑니다
2. 필터 `휠체어 접근 좌석`
3. 좌석 목록이나 배치도. 상태는 사용 가능, 사용 중, 휠체어 접근 세 가지이며 색만이 아니라 글자로도 구분합니다
4. 현재 선택한 좌석

**행동**
- 주요 행동: `다음: 확인`. 좌석을 고르기 전에는 비활성입니다.
- 보조 행동: `선택 해제`, `이전`(날짜를 유지한 채 S01로)

**상태**
- 미선택
- 선택됨
- 사용 가능한 좌석 없음: 날짜 변경을 안내합니다
- 휠체어 접근 좌석 없음: 날짜 변경을 안내합니다

**모바일:** 배치도보다 목록을 먼저 보여 주고, 선택 요약과 주요 버튼은 하단에 둡니다.

## S03 확인
**정보 위계**
1. 날짜
2. 좌석(접근성 속성 포함)
3. 이용 시간
4. 취소 규정
5. 예약 유지 시간: **미결정**. 자리만 마련해 둡니다.

**행동**
- 주요 행동: `예약 확정`
- 보조 행동: `이전`(S02로, 선택 유지). 날짜나 좌석을 각각 수정하는 링크도 둡니다.

**상태**
- 기본
- 제출 중: 버튼을 비활성으로 바꿔 중복 제출을 막습니다
- **S03-ERR**: 같은 화면에서 오류 메시지를 보여 주고, 선택은 모두 보존한 채 `다시 시도`와 `이전 단계`를 제공합니다
- **S03-OK**: 예약 완료와 예약 요약을 보여 줍니다

## 확정되지 않은 결정
1. **예약 유지 시간 (미결정):** S02와 S03에서 타이머를 보여 줄지, 그리고 시간이 만료됐을 때의 상태가 이 값에 달려 있습니다. 만료 상태는 아직 명세하지 않았습니다.
2. **이용 시간의 단위:** 사용자가 고르는지, 하루 단위로 고정인지 알 수 없습니다. 지금은 S03에서 표시만 하는 것으로 가정했습니다.
3. **브리프에 정의되지 않은 내용**
   - 실패 원인 구분: 좌석이 이미 찼는지, 네트워크 문제인지
   - 성공 이후 화면의 내용
   - 취소 규정의 문구

## 핵심 근거와 확인 한계
- **근거:** 모든 화면, 요소, 실패 복구 방식, 범위 제외는 `BRIEF.md` 한 줄(B01, F01, S01–S03)에서 가져왔습니다.
- **추가한 부분:** 모바일 배치, 비활성 규칙, 빈 상태는 이 스킬의 기준에 따라 제가 정한 것입니다. 승인이 필요합니다.
- **한계:**
  - 브라우저를 쓸 수 없어 렌더링과 키보드, 반응형 동작을 확인하지 못했습니다.
  - 참가자가 없어 사용자 검증도 하지 못했습니다.
  - IA나 기존 제품 맥락 자료가 없어 경로와 컴포넌트를 재사용하지 못했습니다.
