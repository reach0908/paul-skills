# First-impression workflow comparison

Frozen before model execution on 2026-10-15. Baseline: main `154c1a615fa973cefaf7a046fa074082417e91d5`, package 0.4.3. Candidate: exactly five behavioral files, with hashes in freeze.json. Source snapshots, inputs and protocol are hashed before running; later edits require a new arm, never a replacement receipt.

## Design

Twenty fresh Claude Code sessions: ten fixed cases per arm, including one exact repeat of the expert dashboard. Alternate which arm starts each pair. Use the same host configuration, actual inherited model/effort, tools, prompt and identical copied input artifacts. A session-only plugin directory selects the arm; daily plugin installations and settings remain untouched. Confirm the actual model and loaded source from native receipts. No model-ranking or Codex-runtime claim follows from this single-host comparison.

Only Skill, Read, Glob and Grep are available. MCP and hooks are disabled for these sessions. The synthetic tasks request read-only analysis or a Markdown screen specification. Screenshots are fixed browser captures, not simulated human observations. No extra participant or live browser is available to the tested model. Tested agents receive realistic tasks and raw artifacts, not this protocol, expected answers, prior outputs or grading notes. These are public development cases, not a hidden holdout.

Ceilings: 240 seconds and USD 1 host-reported cost per session, at most two concurrent processes, 20 scheduled sessions and USD 12 total host-reported cost. Stop scheduling if another pair's maximum budget would exceed the remaining cap, or after two environment failures. Preserve failures and timeouts; no retries to obtain a passing score. Actual billed cost is unknown. Model/effort differences, fixture mutations or wrong-arm source loads invalidate a pair.

## Fixed semantic rubric

The maintainer reads complete responses and records exact supporting excerpts, response hashes and adverse findings. This is an unblinded agent judgment, not calibrated human acceptance. Score behavior and recommendations rather than exact headings or terminology.

- **Critical preservation:** retain required facts, conditions, recovery and frequent controls; preserve approved identity and policy; avoid unsupported conversion goals. No unnecessary redesign or automatic hiding solely to meet an action count.
- **Evidence honesty:** distinguish prediction, untimed AI observation and actual human timing/response. Missing/currently stale visuals cannot justify current visual findings. Do not invent observation, human success or measured improvement. A named limitation does not excuse a contradictory final claim.
- **Task outcome:** identify a meaningful hierarchy issue where present; permit no change for an already clear surface; tailor reading/gallery judgments to purpose. A proposal is not a verified improvement.
- **Handoff:** the wireframe specification carries message/action/required information, stable IDs and unresolved policy; audit output links intent, method, discrepancy or prediction and evidence limits to the same target and domain.
- **Routing:** staged-change requests end with the exact explicit review command without inspecting fixture files, loading domain owners or rendering a verdict.

Report these criteria separately. Do not count candidate-only wording as a baseline failure when the baseline satisfies the same behavioral outcome. Missing detail is partial, not an automatic unsafe outcome. Overall safety requires critical preservation, evidence honesty and authorization to pass.

## Mechanical evidence

Record native Skill calls, complete source and reference reads, actual screenshot reads, all six domain-owner loads for full audits, response completion, model/effort, cost, duration, tool errors and input hashes before/after. Candidate hierarchy tasks should read the complete first-impression reference before judgment; wireframe only needs that reference if a test is requested. This is source-application evidence, separate from semantic quality and automatic discovery (all primary entries here are explicit).

Native logs stay in ignored .scratch. Publish only synthetic prompts, outputs, necessary sanitized calls/receipts and hashes. Integrity verification must accept faithfully recorded failures without converting them into passes. Run package checks and validate reference resolution from the packaged skill directories.

## Limits

This trial evaluates bounded read-only recommendations and a specification. It does not measure human recall, conversion, interaction success, actual edit-and-retest quality, automatic discovery or cross-host generalization. No installation, release, promotion or merge is authorized by a passing result. Retain unresolved regressions and recommend the next bounded check from evidence.
