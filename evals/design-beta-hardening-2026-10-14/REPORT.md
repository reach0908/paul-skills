# 디자인 베타 보완과 정식 승격 재평가

2026-10-14. **로컬 반응형 웹과 Codex 사용 범위에서 남은 8개를 정식 승격 후보로 권고한다.** 앞선 `break` 탐지 공백과 `user-flow` 닫기·복귀 불일치를 보완했고, 이번에 추가로 발견한 호출 경계 실패도 보존한 뒤 재시험했다. 기존 6개 역할의 비교 결과에 최신 호출·단계 전달 증거를 더했으며, 이번 범위에서 남은 기술적 차단점은 없다.

실제 승격은 실행하지 않았다. 저장소의 `AGENTS.md`는 사용자 행동 확인과 명시적 승격 승인을 요구한다. 특히 variant의 비교 방식과 build의 시안 충실도에 대한 사용자 수용은 자동 검사로 대체하지 않는다. 승인되면 패키징·문서·설치 검증으로 이어갈 수 있는 상태다. 이 판단은 모든 입력·모델·호스트에서 원본보다 낫다는 보증이 아니다.

## 바뀐 것

- **break:** 브라우저 관찰 전에 제품 제약이나 기존 콘텐츠에 근거한 긴 값을 정하고, 같은 값을 가장 좁은 선택 컨테이너에도 넣게 했다. 실제 컴포넌트 import, 제품 CSS 보존, 한 번 관찰하는 원본 역할은 유지했다.
- **user-flow:** 작업 상태와 보기의 열림·닫힘을 분리하거나 적용 상태를 모두 명시하게 했다. 상태 표에 제공한 행동이 전이 표에도 있는지 점검하며, 요청 전에는 없는 키를 만들지 않고 성공 후에는 receipt를 보존한다.
- **호출 경계:** 흐름 설계에서 `state-machine`까지 읽는 실제 실패를 확인했다. user-flow의 자동 호출 설명과 첫 문단에 직접 담당 범위와 별도 작업대의 명시 호출 조건을 보완했다.
- 출처 기록, Changeset, 평가 입력·실행 기록·재사용 가능한 검증 도구를 추가했다. 원본 import/review revision, 정식 manifest, 전역 설치는 그대로다. `ask-matt`를 재확인했으며 아직 베타인 두 역할을 정식 라우터에 추가하지 않았다.

## 원본 재비교와 보완 효과

Jakub 기준은 `d574cc8a576dc24256ad38268b8d03d86724a1b3`이며 동결된 65개 원본 파일의 해시를 다시 확인했다. 이전 실패 과제와 새 과제, 각각 동일 입력의 원본/Paul 또는 무스킬/Paul 쌍으로 8개 실행을 했다. 모델은 이전과 같은 `gpt-5.6-sol`, 추론 수준은 `xhigh`다.

**break:** 기존 큐 카드에서 Paul의 긴 문장은 정상 폭에서 60.38px, 320px에서는 668.38px 넘쳤고 비분리 문자열은 320px에서 598.64px 넘쳤다. 보완본은 빈 제목까지 포함한 4개 현상을 정확히 보고했다. 이전에는 이 CSS 결함을 드러낼 만큼의 내용을 넣지 않아 놓쳤던 사례다. 새 첨부 과제는 최대 220자와 280px를 결합해 넘침을 드러냈고, 지원되는 wrapping 7개는 모두 정상으로 보고했다. 제품 파일은 4개 실행 모두 그대로였고 관찰은 각 한 번의 페이지 로드에서 수행했다.

원본도 오류가 없지는 않았다. 이번 큐 카드 원본은 카드 안에 들어간 비분리 문자열을 넘친다고 보고했다. 평가자는 실제 경계와 이미지로 확인해 그 지적을 유효한 기준에서 제외했다. 시나리오 수는 원본/Paul이 기존 과제 16/17개, 새 과제 18/19개지만 개수로 우열을 점수화하지 않았다. 문자열과 컨테이너 조합 자체는 실행자가 선택하므로 동일하지 않다. Paul의 기존 과제 라벨은 80자라고 적었지만 실제 문자열은 85자였으며 측정 기록에는 실제 길이를 남겼다. 제품 상한이 확정된 새 과제의 최대값은 실제 220자다.

**user-flow:** 기존 저장 과제에서는 모든 작업 상태에 닫기·복원을 적용하고, 요청 전 키 없음과 성공 후 `S-72` 보존을 경로로 확인했다. 새 내보내기 과제에서는 `O-00`~`O-05` 닫기·복귀, `J-44`와 `E-44`, 재다운로드 시 새 작업 미생성을 명세했다. 새 과제의 무스킬 대조군도 핵심 계약을 충족했으므로 Paul의 우위를 주장하지 않는다. 호출 경계 보완 후에는 최종 본문으로 저장 과제를 한 번 더 실행했고 같은 핵심 계약을 확인했다.

[산출물별 검토와 링크](SEMANTIC-REVIEW.md), [break 실제 측정](evidence/break-geometry.json). 각 실행의 본문·의존성·입력 해시는 [prepared.json](prepared.json)에 있다. 최초 행동 보완본과 후속 호출 보완본을 구분했으며 이전 결과를 최종 버전의 새 실행인 것처럼 바꾸지 않았다.

## 호출 경계

8개 모두 `$스킬이름` 명시 호출에서 호스트가 전달한 실제 본문과 로컬 파일이 일치했다. user-flow는 호출 설명을 바꾼 뒤 다시 확인해 명시 호출 실행은 총 9개다. 역할 경계 설명만 요청했으므로 이를 9개의 구현 품질 시험으로 세지 않는다.

첫 자연어 흐름 요청에서는 모델이 디렉터리를 탐색해 숨겨진 `state-machine` 본문까지 읽었다. 나중에 작업대를 만들지 않기로 했어도 **이 실행은 실패**로 남겼다. 보완 후 같은 요청과 별도의 업로드 닫기·복귀 요청에서는 user-flow만 읽었다. 나머지 세 이웃 요청도 break, explain-interface, variant 본문을 읽지 않았다. 부정 사례는 최초 4개와 재시험 2개로 총 6개이며, 최초 실패 1개를 없애고 6/6 성공으로 보고하지 않는다.

IA, flow, wireframe, build는 이름을 지정하지 않은 네 실제 단계에서 각자의 스킬을 자동으로 선택했다. 카탈로그 노출만으로 자동 호출을 판정하지 않았다. [상세 호출 기록](INVOCATION.md), [무결성 확인](evidence/integrity-check.json).

## 실제 단계 전달과 독립 Playwright 검증

```text
PB-72 brief → 실제 IA map → 실제 flow 계약 → 실제 wireframe와 screens 명세
            → 선택된 로컬 Markdown 시안 LC-72 → 기존 동작을 보존한 구현
```

각 단계는 새 문맥에서 바로 앞 단계의 실제 파일을 받았다. 다음 단계의 답안을 미리 넣지 않았다. 전달된 파일 인스턴스 8개의 해시를 확인했고, `D-LIB/D-ITEM/D-SAVED/D-HELP`, `R-72`, `T-SAVE`, flow의 `TS/TR/NAV` ID와 `OD-01`~`OD-04`를 이어받았다.

구현 과제는 실제 wireframe의 main 패딩만 기존 토큰으로 24px/16px로 바꾸는 로컬 명세다. 평가용으로 선택된 합성 명세이며 실제 사용자가 이 디자인을 수용했다는 뜻은 아니다. HTML 안의 스크립트와 마크업은 바이트 동일하고, 변경 파일은 `app/style.css` 하나다. 이미지가 없는 Markdown 기준이므로 픽셀 일치로 표현하지 않는다.

| --- | --- | --- |
| 폭 | 1280×900, 320×700 | 1280×900, 320×700 |
| 실제 main 패딩 | 16px, 12px | 명세대로 24px, 16px |

| 상태·입력 | 요청 전·pending·unknown·조회 중·완료의 닫기/복원, 초안·검색 문맥·reload 보존 | 같은 계약 보존 |

Tab뿐 아니라 Enter와 Space로 실제 행동을 수행했다. 본문 내부 링크 이동은 현재 자료와 초안을 바꾸지 않았다. 과제의 “내부 본문/출처 이동” 표현과 선행 명세의 외부 원문 규칙에는 모호함이 있었고, 결과는 선행 `NAV-06` 내부 본문과 `NAV-04` 외부 원문 링크를 따랐다. 내부 출처 구역 전이까지 검증했다고 세지 않는다. 평가자는 외부 링크의 목적지를 확인했으며 외부 사이트를 열지는 않았다.

## 증거와 한계

- 실행 전 고정한 [프로토콜](PROTOCOL.md)의 최초 24개와 최대 4개 재시험, 총 **28개 새 Codex 문맥**을 완료했다. 구성은 품질 비교·재시험 9개, 명시 호출 9개, 부정 사례 6개, 실제 단계 전달 4개다. 모두 프로세스 종료 코드는 0이지만 앞선 호출 실패는 별개로 실패다.
- 기존 6개 역할의 파일 해시가 직전 비교와 같음을 확인했다. 해당 역할의 전체 품질 과제를 모두 다시 실행한 것으로 세지 않았다. final user-flow 본문은 추가 저장 과제, 두 부정 재시험, 명시 재호출과 단계 전달에서 사용했다.
- PNG 경로는 40개, 중복을 제외한 이미지 내용은 33개다. 독립 단계 재검증 캡처는 16개다. 캡처 수를 테스트 케이스 수로 사용하지 않았다. [캡처 크기·해시 목록](evidence/captures.json).
- 도구 오류도 보존했다. 원본의 없는 package.json 조회, Git 저장소가 아닌 fixture의 git status, user-flow의 인용부호 오류, wireframe의 다른 화면에서 reset을 찾던 타임아웃이 있었다. 관련 출력과 후속 성공 관찰은 [실행 기록](run-integrity.json)과 각 artifacts의 commands.json에 있다. 종료 코드 0 안의 `### Error`도 별도로 수집했다.
- `npm run check`의 스킬·버전·출처 정합성과 **38개 테스트**, `claude plugin validate . --strict`, diff 공백 검사를 통과했다. 이는 AI의 원본 동등성 증명이 아니다.
- Claude Code는 정책·manifest 정적 검사만 했다. 실제 행동 증거는 Codex CLI 0.146.0, Playwright CLI 0.1.22, 동일 모델·추론 설정에 한정한다. 전역 스킬 메타데이터가 일부 노출되는 호스트라 완전한 보안 격리라고 주장하지 않는다.
- 모든 입력에 대한 통계적 비열등성, 특정 문장 수정의 인과 효과, 모델 비용·속도 우열은 측정하지 않았다. 실제 서버·계정·사용자 수용, 네이티브 및 전체 보조기기 조합은 이번 판정 밖이다. Figma는 사용자의 작업 범위 밖이므로 로컬 경로 승격 조건에 추가하지 않았다.
