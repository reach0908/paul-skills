## 2. 화면 계약

한 HTML 문서 안에서 기존 목적지를 교체 렌더링한다. 주소의 `?screen=`은 시안 관찰용이며, 화면에 표시된 정식 제품 경로를 변경하지 않는다.

| 목적지 | 정식 경로 | 시안 화면과 역할 |
|---|---|---|
| `D-LIB` | `/library` | 검색어 `작은 팀`, 태그 `운영`, 정렬 `newest`, 목록 위치 `R-72`를 보여 주고 상세 재진입을 연결한다. |
| `D-ITEM` | `/items/R-72` | 제목·요약·작성자·태그·본문·원문 URL과 `T-SAVE`를 한 화면에 둔다. |
| `D-SAVED` | `/saved` | `TS-40`과 `S-72`가 확인된 뒤에만 같은 `R-72`와 내 메모를 보여 준다. |
| `D-HELP` | `/help` | 기존 목적지만 유지하고, 입력에 없는 세부 분류는 추가하지 않는다. |

태그와 작성자는 목적지가 아니다. `운영 필터 보기`는 `D-LIB`로 이동하며 태그를 전역 메뉴로 만들지 않는다. `S-72`도 별도 목적지가 아니라 `R-72` 저장 성공의 유일 receipt다.

### D-ITEM 정보 순서

1. 확정된 검색 결과로 돌아가기와 정식 경로
2. `R-72` 식별 정보: 제목, 요약, 작성자, 태그
3. 같은 화면 내부 본문 링크와 새 탭 원문 링크
4. `T-SAVE` 상태, 메모, 현재 가능한 행동, 모의 경계
5. 자료 본문과 `OD-01`~`OD-04`

1280px에서는 본문 왼쪽, `T-SAVE` 오른쪽의 두 열이다. 620px 이하에서는 읽기 순서대로 `T-SAVE`를 본문보다 먼저 배치한다. 좁은 화면의 상단에는 `D-LIB` 검색 진입과 `D-SAVED`가 항상 노출된다.

## 3. T-SAVE 상태와 조작

| 상태 | 화면 피드백 | 가능한 핵심 행동 | 연결 전이 |
|---|---|---|---|
| `TS-00 / V-OPEN` | 아직 요청 전. 메모 편집 가능. `K`와 receipt 없음 | 저장, 닫기 | `TR-01`, `TR-02`, `TR-11` |
| `TS-10 / V-OPEN` | 최초 요청 1건의 `pending`. 메모 읽기 전용 | 기다리기, 닫기 | `TR-03`, `TR-08`, `TR-11` |
| `TS-20 / V-OPEN` | `timeout-unknown`. 실패·성공으로 단정하지 않음 | 같은 작업 상태 확인, 인증 필요 상황 모의, 닫기 | `TR-04`, `TR-08`, `TR-16`, `TR-11` |
| `TS-21 / V-OPEN` | 같은 `K`의 첫 상태 확인 중 | 기다리기, 인증 필요 상황 모의, 닫기 | `TR-05`, `TR-09`, `TR-16`, `TR-11` |
| `TS-30 / V-OPEN` | 첫 확인 결과 `pending` | 같은 작업 상태 확인, 인증 필요 상황 모의, 닫기 | `TR-06`, `TR-08`, `TR-16`, `TR-11` |
| `TS-31 / V-OPEN` | 같은 `K`의 두 번째 상태 확인 중 | 기다리기, 인증 필요 상황 모의, 닫기 | `TR-07`, `TR-09`, `TR-16`, `TR-11` |
| `TS-40 / V-OPEN` | `succeeded`, 유일 receipt `S-72` | `D-SAVED`에서 확인, 닫기 | `TR-10`, `TR-18`, `TR-11` |
| `TS-90 / V-OPEN` | 인증 복구 의존. 결과는 여전히 미확정 | 인증 복구 완료 모의, 닫기 | `TR-17 / OD-02`, `TR-11` |
| 모든 상태 / `V-CLOSED` | 작업 본문 대신 최신 상태와 다시 열기 표시 | 다시 열기, 명시적 초기화 | `TR-12`; 진행 중 사건은 `TR-13`~`TR-15` |

저장 시작 뒤에는 `OD-04`가 미결이므로 메모를 읽기 전용으로 표시한다. 저장·확인 중 버튼을 없애거나 비활성화해 `TR-08`~`TR-10`의 중복 입력이 새 네트워크 작업을 만들지 않게 했다.

### 모의 성공 경로

`NAV-01 → TR-01 → TR-02 → TR-03 → TR-04 → TR-05 → TR-06 → TR-07 → TR-18`

- `TR-02`: 현재 메모와 연결된 모의 작업 `K`를 만들고 저장 요청 수를 1로 고정한다.
- `TR-03`: 1.8초 뒤 `timeout-unknown`으로 이동한다.
- `TR-04`와 `TR-05`: 첫 조회 1건 뒤 `pending`을 반환한다.
- `TR-06`과 `TR-07`: 두 번째 조회 1건 뒤 `succeeded`와 `S-72`를 반환한다.
- `TR-18`: `D-SAVED`에서 같은 `R-72`와 메모를 표시한다.

닫힌 동안 타이머가 끝나면 `TR-13: TS-10→TS-20`, `TR-14: TS-21→TS-30`, `TR-15: TS-31→TS-40`으로 진행한다. 닫기는 서버 취소가 아니며 다시 열면 최신 상태와 초안을 보여 준다.

## 4. 목적지·본문·출처 전이

| ID | 구현 동작 | 보존 결과 |
|---|---|---|
| `NAV-01` | 확정 검색 결과의 `R-72`를 연다. | `TS-00` 또는 보존된 최신 상태를 연다. |
| `NAV-02` | `검색 결과로 돌아가기`를 누른다. | 작업 보기를 닫고 `q`, `tag`, 정렬, `R-72` 위치를 복원한다. |
| `NAV-03` | 복원된 목록에서 같은 `R-72`를 다시 연다. | `TR-12`와 함께 최신 작업 상태·초안을 연다. |
| `NAV-04` | 외부 원문 링크를 새 탭으로 연다. | 현재 탭의 자료·초안·작업 상태를 바꾸지 않는다. |
| `NAV-05` | 원문 탭을 닫거나 원래 탭을 다시 선택한다. | 같은 `D-ITEM` 문맥을 그대로 사용한다. |
| `NAV-06` | `본문으로 건너뛰기`를 누른다. | URL의 `#article-body`와 포커스 가능한 본문 위치로 이동하며 상태는 변하지 않는다. |
| `NAV-07` | `D-SAVED`에서 같은 `R-72` 상세를 연다. | 자료 ID는 유지하되 복귀 목적지는 `OD-03`으로 표시한다. |

선행 입력에는 실제 원문 URL 값이 없으므로 외부 이동 동작 확인용 URL로 `https://example.com/`을 사용했다. 새 탭과 `noopener noreferrer`를 사용해 시안 탭의 상태를 보존한다. 실제 콘텐츠 URL 확정으로 해석하지 않는다.

## 5. 모의 경계와 초기화

- 네트워크: 실제 요청 없이 1.8초 지연 타이머로 `timeout-unknown`, 첫 `pending`, 두 번째 `succeeded`를 순서대로 만든다.
- 저장: 현재 브라우저 탭의 `sessionStorage` 키 `chain-wire-t-save-v1`만 사용한다. 새로고침과 내부 목적지 이동에는 유지되지만 실제 서버나 다른 탭에는 저장되지 않는다.
- 인증: `인증 필요 상황 모의`는 `TR-16`으로 `TS-90`에 진입시킨다. 인증 복구 완료 뒤에도 `TR-17 / OD-02`에서 멈추며 새 저장, 성공, 실패를 추정하지 않는다.
- 중복 방지: 모의 계수는 저장 요청 1건, 상태 조회 최대 2건, receipt 1개다.
- 초기화: 화면의 `명시적으로 초기화` 버튼만 초안·`K`·receipt·모의 계수를 지운다. 닫기, 목적지 이동, 본문 이동, 원문 열기, 새로고침은 초기화하지 않는다.

## 6. 유지한 미결 정책

| ID | 미결 내용 | 시안에서의 처리 |
|---|---|---|
| `OD-01` | 만료된 초대 자료를 읽을 수 있는가 | 정책 목록에 표시하고 접근 허용/차단을 만들지 않음 |
| `OD-02` | 인증 복구 뒤 같은 `K` 재조회 API | `TS-90`에서 결과를 정하지 않고 멈춤 |
| `OD-03` | 직접 URL·추천·`D-SAVED` 진입 뒤 복귀 문맥 | `NAV-07`에 미결 표시. 검색 결과 진입의 확정 복귀만 구현 |
| `OD-04` | 저장 시작 뒤 메모 편집과 귀속 | `TS-10` 이후 읽기 전용. payload 귀속 규칙을 만들지 않음 |

검색 대상 필드, 작성자 필터 URL 표현, 필터 조합, 목록별 콘텐츠 분량, `D-HELP` 세부 분류도 결정하지 않았다.
