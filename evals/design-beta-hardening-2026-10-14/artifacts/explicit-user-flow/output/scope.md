# user-flow 역할 경계

## 이번 확인의 범위

이 문서는 `user-flow` 스킬의 역할만 설명한다. `TASK.md`가 실제 디자인 산출물, 구현, 브라우저 조작을 금지했으므로 특정 제품의 사용자 흐름, 상태 ID, 전이표, 화면 명세 또는 프로토타입은 작성하지 않는다.

확인한 로컬 입력은 다음 두 문서뿐이다.

- 과업 지시: `TASK.md`
- 역할 정의: `.agents/skills/user-flow/SKILL.md`

`TASK.md`에는 PM 결정, 정보 구조(IA), 기존 동작, 대상 사용자 또는 제품 시나리오가 제공되지 않았다. 따라서 실제 전이 계약을 만들 근거도 없다.

## 이 역할이 받는 입력

`user-flow`는 범위가 합의된 제품 과업을 입력으로 받는다. 정상적인 작업을 시작하려면 다음 정보가 필요하다.

- 행위자와 구체적인 진입 맥락
- 의도한 결과와 관찰 가능한 성공 조건
- 합의된 PM 결정 및 제품 정책
- 관련 정보 구조와 기존 목적지 ID
- 보존해야 할 기존 동작
- 필요한 경우 권한, 지속성, 커밋 시점에 관한 규칙

IA가 없다고 전체 사이트맵을 새로 만들지는 않는다. 해당 과업에 꼭 필요한 목적지만 식별하고, 남은 구조적 결정을 미결 사항으로 표시한다. 제품 정책과 설계 제안도 구분한다.

## 이 역할이 만드는 산출물

주 산출물은 사용자의 행동, 제품의 응답, 다음 상태를 검토할 수 있게 연결한 **전이 계약**이다. 일반적으로 다음을 포함한다.

- 과업 경계, 행위자, 진입점, 성공 조건
- 안정적인 흐름 ID와 상태 ID
- 출발 상태, 사용자 행동 또는 시스템 이벤트, 선행 조건, 피드백, 도착 상태, 유지·변경 데이터가 포함된 전이표
- 성공 경로와 중요한 실패·재시도·수정·취소·이탈·복귀 경로의 점검 결과
- 비동기 처리, 중복 입력, 중단, 확정 전·후 상태 등 실제 과업에 관련된 분기
- 미해결 정책, 명시적 가정, 확인하지 못한 경로와 관찰 한계
- 각 화면이 노출해야 하는 정보와 행동(시각적 배치 제외)
- 사용한 입력의 버전 또는 동등한 출처 식별자

전이표가 권위 있는 기준이며, 분기가 복잡할 때만 표와 일치하는 다이어그램을 보조로 붙인다. 작성자의 경로 점검은 내부 일관성 확인일 뿐 실제 사용자에게 과업이 성공한다는 증거는 아니다.

## 인접 역할과 소유권

| 역할 | 소유하는 것 | `user-flow`와의 경계 |
| --- | --- | --- |
| PM·제품 결정 | 대상 사용자, 문제 범위, 제품 정책, 권한·지속성·커밋 규칙 | `user-flow`는 합의된 결정을 보존하며 중대한 미결 정책을 임의로 확정하지 않는다. |
| 정보 구조(IA) | 목적지, 라벨, 내비게이션 구조와 목적지 ID | `user-flow`는 기존 목적지 ID를 재사용하며 전체 사이트맵을 설계하지 않는다. |
| `user-flow` | 과업의 행동, 결정, 제품 응답, 상태 전이, 복구·이탈 경로 | 화면의 시각적 구성이나 운영 코드를 소유하지 않는다. |
| wireframe | 화면 계층, 컨트롤 배치, 반응형 순서 등 화면 구성 | 전이 ID와 화면에 필요한 정보·행동을 받아 시각적 구조로 구체화한다. |
| 구현 | 운영 로직, 데이터 처리, API 연동, 실제 컴포넌트 동작 | 전이 계약을 기술적으로 구현하되, 미결 제품 정책을 구현 과정에서 조용히 결정해서는 안 된다. |
| 브라우저 검증 | 기존 구현의 관찰과 기대 전이에 대한 확인 | 기존 동작 확인이 필요할 때만 별도 검증 역할을 사용한다. 흐름 설계 자체의 필수 전제는 아니다. |
| 사용자 수용·연구 | 실제 사용자의 이해와 과업 성공 검증 | 작성자의 워크스루와 별도 상태이며, `user-flow` 완료가 사용자 수용을 의미하지 않는다. |

구현된 컴포넌트 상태를 표시하는 상태 머신 역할도 사용자 흐름 설계의 선행 조건은 아니다.

## 종료 지점

선택한 과업 경로가 전이표로 명시되고, 모든 범위 내 행동이 제품 응답과 연결되며, 도달 가능한 각 분기가 성공 결과·의도적 이탈·명시된 의존성 중 하나로 끝나면 하류 역할에 넘길 준비가 된 것이다. 고아 상태, 모순된 조건, 누락 전이는 기록하거나 해결해야 한다.

여기서 작업을 멈춘다. 별도 요청이 없는 한 화면 레이아웃, 시각 디자인, 프로토타입, 구현, 브라우저 조작, 실제 사용자 수용 판정으로 확장하지 않는다.

## 이번 실행의 한계

이번 실행은 역할 경계 확인만 수행했다. 제품 입력이 없었고 계정이나 라이브 API를 사용하지 않았으며, 브라우저 관찰·실사용자 검증·전이 워크스루를 수행하지 않았다. 따라서 특정 제품 흐름의 완전성, 사용성 또는 구현 일치 여부에 관한 결론은 내릴 수 없다.
