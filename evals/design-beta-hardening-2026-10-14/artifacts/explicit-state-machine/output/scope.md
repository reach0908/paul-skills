# `state-machine` 역할 경계

## 현재 요청에서 받은 입력

이번 실행의 입력은 `TASK.md`와 로컬 `state-machine` 스킬 설명뿐이다. `TASK.md`는 스킬의 현재 역할과 종료 경계만 설명하고, 실제 디자인 산출물 제작·구현·브라우저 조작은 하지 말라고 지정한다. 대상 컴포넌트, 소스 코드, 데이터 훅, 상태 목록 같은 구현 입력은 제공되지 않았으며 이 역할 경계 확인에는 필요하지 않다.

## 스킬이 실제 작업에서 받는 입력

`state-machine`은 한 번에 **하나의 기존 컴포넌트**를 입력으로 받는다. 입력에는 다음 맥락이 필요하다.

- 컴포넌트가 무엇을 보여 주는지
- 제품의 어느 위치에서 렌더링되는지
- 데이터가 어디에서 오는지
- 컴포넌트와 데이터 훅에 이미 존재하는 도달 가능한 분기
- 운영 화면에서의 실제 너비와 앱이 제공하는 레이아웃·글꼴·전역 스타일·프로바이더

“설정 페이지”처럼 여러 컴포넌트를 포함하는 범위는 바로 진행하지 않는다. 후보를 나열하고 사용자에게 한 컴포넌트를 선택해 달라고 요청한다. 상태는 코드에 이미 있는 데이터·계정·기능 분기에서만 찾으며, 코드로 도달할 수 없는 상태는 추가하지 않고 누락 상태로 기록한다. 조합 상태도 코드가 실제로 그 조합으로 분기할 때만 포함한다.

## 스킬의 출력

실제 실행 결과는 앱 안의 일회용 작업대다.

- 실제 컴포넌트를 수정하지 않고 가져오는 스크래치 라우트
- 제품과 같은 형태와 현실적인 수량의 고정 fixture
- `__state` 검색 매개변수로 한 번에 한 상태를 전환하는 고정 switcher
- 제품의 표현을 따른 상태 이름 목록과 제외한 상태 종류·이유
- 브라우저에서 각 상태가 빈 화면이나 실제 데이터가 아닌 mock 데이터로 렌더링됨을 확인한 결과
- 사용자에게 넘길 URL, 상태 목록, switcher 키

페이지·fixture·switcher는 한 폴더에 두어 사용자 요청 시 한 번에 제거할 수 있어야 한다. loading이나 pending 상태는 타이머로 풀리지 않고 switcher가 바뀔 때까지 유지한다. 데이터는 우선 컴포넌트의 props, 다음으로 앱의 기존 데이터 경계(예: seeded query cache, mock provider, request mock)에 공급한다.

이 스킬의 산출물은 완성 디자인이나 리뷰 보고서가 아니라, 각 기존 상태를 하나씩 시각적으로 다룰 수 있는 임시 작업 환경이다.

## 인접 역할

- `break`: 공격적이거나 극단적인 여러 시나리오를 한 화면에 쌓아 한 번에 점검하는 역할이다.
- `variant`: 대안 디자인을 탐색하고 비교하는 역할이다.
- `interface-review`: 완성된 인터페이스를 검토하는 역할이다.
- `design-browser`: 상태 작업대 자체의 역할은 아니며, 필요할 때 각 상태의 렌더링과 상호작용 증거를 수집하는 검증 지원 역할이다.

`state-machine`은 위 역할처럼 디자인을 바꾸거나 평가하지 않는다. 기존 컴포넌트의 도달 가능한 상태를 분리해 재현하는 작업대만 만든다.

## 중단 지점

정상적인 실행은 모든 상태를 브라우저에서 전환해 mock 데이터가 실제 컴포넌트에 나타나는지 확인한 뒤, URL·상태 목록·switcher 키를 사용자에게 전달하는 시점에 멈춘다. 그 뒤 상태의 외형을 변경하는 일은 별도 사용자 요청의 범위다.

다음 경우에도 구현을 확대하지 않고 멈추거나 확인을 요청한다.

- 여러 컴포넌트가 범위에 들어오면 하나를 선택해 달라고 요청한다.
- fixture를 넣으려면 실제 컴포넌트 수정이나 새 데이터 seam이 필요하면, seam을 추가하기 전에 사용자 승인을 요청한다.
- 디자인에는 있지만 코드로 도달할 수 없는 상태는 구현하지 않고 누락으로 기록한다.
- 작업대 삭제는 만든 직후 하지 않으며, 사용자가 삭제를 명시했을 때만 페이지 폴더와 승인된 seam을 제거한다.

## 이번 실행의 한계와 종료

이번 요청은 역할 경계 확인만 허용하므로 스크래치 라우트, fixture, switcher, 상태 목록, 핸드오프 URL을 만들지 않았고 브라우저도 실행하지 않았다. 제공된 URL base 역시 실제 라우트가 만들어지지 않았으므로 검증 가능한 작업대 URL로 사용하지 않았다. 따라서 렌더링 상태나 데이터 주입 성공 여부에 대한 브라우저 증거는 없다. 이 문서 작성이 이번 실행의 종료 지점이다.
