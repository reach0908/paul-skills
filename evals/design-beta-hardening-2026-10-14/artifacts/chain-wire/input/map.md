# 공유 자료함 정보 구조 맵

## 1. 기준과 범위

- **출처:** `BRIEF.md` — 「공유 자료함, 결정본 PB-72 revision 3」
- **대상 사용자:** 팀 읽기 목록에서 자료를 찾아 자신의 보관함에 저장하는 사용자
- **핵심 찾기 과업:** 자료 검색·필터링, 자료 식별과 상세 확인, 원문 열기, 내 보관함에 저장, 이전 목록 문맥으로 복귀
- **범위:** 콘텐츠와 기존 목적지의 대응, 검색·필터·직접 진입·복귀 경로, 좁은 화면의 정보 접근 우선순위, 구조에 영향을 주는 미결 정책
- **범위 밖:** 화면 배치, 메뉴·컴포넌트 형태, 코드, 새 전역 메뉴, 세부 작업 전이 설계, 새 권한 정책 결정

### 결정 상태

PB-72 revision 3에서 확정한 네 목적지와 용어를 그대로 유지한다. 태그·작성자는 목적지가 아니라 필터다. 아래 맵은 후속 화면 명세가 목적지 ID를 재해석하지 않고 사용할 수 있는 상태지만, 이 문서 자체에 대한 별도 승인 기록은 없으므로 **후속 작성 준비 완료**로 표시하며 **승인됨**으로 간주하지 않는다.

## 2. 정보 객체와 관계

```text
팀 읽기 목록
└─ 자료 R-72
   ├─ 식별·설명 속성: 제목, 요약, 작성자, 태그
   ├─ 외부 관계: 원문 URL
   └─ 사용자별 저장 관계
      ├─ 내 메모(사용자 소유)
      └─ 저장 요청 확인 receipt S-72
```

- 자료는 목록·검색·추천에서 같은 자료 ID를 사용한다. 진입 경로가 달라도 `R-72`의 정식 상세 목적지는 하나다.
- `R-72`의 확정 제목은 **작은 팀에서 실패 후 다시 시도하기**다.
- 작성자와 태그는 자료의 속성이며 `D-LIB`에서 범위를 좁히는 기준이다. 별도 카테고리 페이지나 전역 메뉴로 승격하지 않는다.
- 원문 URL은 현재 자료에서 외부 원문으로 이어지는 관계다. 본문의 출처 링크를 `D-LIB` 복귀 링크로 해석하지 않는다.
- 내 메모와 타인의 원문은 같은 자료와 연결되더라도 소유권이 서로 다른 객체다. 하나의 권한 규칙으로 합치지 않는다.
- `S-72`는 저장 성공을 확인하는 유일 receipt이며 독립 목적지가 아니다.

## 3. 기존 목적지

| ID | 사용자 표시명 | 경로 | 담는 정보 | 지원 과업 | 접근 조건·비고 |
|---|---|---|---|---|---|
| `D-LIB` | 자료함 | `/library` | 팀 읽기 목록, 검색 결과, 자료의 식별 속성과 검색·필터·정렬 문맥 | 자료 찾기, 검색, 작성자·태그 필터링, 결과에서 상세 진입 | 팀 자료 접근 여부는 권한 정책의 적용을 받는다. 검색은 좁은 화면에서도 도달 가능해야 한다. |
| `D-ITEM` | 자료 상세 | `/items/:id` | 자료의 제목·요약·작성자·태그·원문 URL, 현재 자료에 대한 `T-SAVE`와 메모 초안 | 자료 확인, 원문 열기, 내 보관함에 저장 | 모든 진입 경로가 같은 자료 ID로 수렴한다. 만료 초대 자료의 직접 접근 가능 여부는 미결이다. |
| `D-SAVED` | 내 보관함 | `/saved` | 사용자가 저장한 자료와 그 자료에 연결된 내 메모 | 저장한 자료 다시 찾기 | 좁은 화면에서도 도달 가능해야 한다. 내 메모의 소유권을 타인의 원문 소유권과 동일시하지 않는다. |
| `D-HELP` | 도움말 | `/help` | 기존 도움말 콘텐츠 | 사용 방법 확인 | 이번 입력에는 도움말 콘텐츠의 세부 분류가 없다. 목적지만 유지한다. |

새 목적지는 추가하지 않는다. 목록, 검색 결과, 추천, 필터 결과는 동일 자료로 가는 발견 문맥이며 각각을 별도 상세 목적지로 만들지 않는다.

## 4. 콘텐츠-목적지 대응

| 콘텐츠·상태 | 정식 위치 | 다른 목적지에서의 역할 | 명시적 제외·제약 |
|---|---|---|---|
| 자료 레코드 `R-72` | `D-ITEM` | `D-LIB`의 목록·검색·필터 결과에서 발견되고, 저장 뒤 `D-SAVED`에서 같은 ID로 참조됨 | 검색·추천마다 복제 ID를 만들지 않음 |
| 제목·요약 | `D-ITEM` | `D-LIB`와 `D-SAVED`에서 자료를 알아보게 하는 속성으로 사용 가능 | 각 목록에서 어느 분량까지 노출할지는 화면 명세 사항 |
| 작성자·태그 | `D-ITEM`의 자료 속성 | `D-LIB`의 필터 기준 | 새 전역 메뉴나 독립 목적지가 아님 |
| 원문 URL | `D-ITEM`의 현재 자료에 연결 | 없음 | `D-LIB`로 이동하는 링크가 아니며, 원문 이동 전후 현재 자료와 입력을 바꾸지 않음 |
| 내 메모 초안 | `D-ITEM`의 `T-SAVE` 작업 문맥 | 저장이 확인된 자료와 연결되어 `D-SAVED`에서 다뤄지는 사용자 소유 정보 | 닫아도 유지되며, 타인의 원문과 동일 소유권 정책을 적용하지 않음 |
| 저장 처리 상태와 receipt `S-72` | `D-ITEM`의 같은 `T-SAVE` 작업에 귀속 | 성공이 서버에서 확인되면 `D-SAVED`의 저장 관계를 뒷받침 | receipt 자체를 페이지·메뉴로 만들지 않음 |
| 검색어, 필터, 정렬, 목록 위치 | `D-LIB`의 발견 문맥 | `D-ITEM`에서 뒤로 갈 때 복원할 복귀 문맥 | 자료 콘텐츠나 독립 목적지가 아님 |
| 도움말 콘텐츠 | `D-HELP` | 이번 범위에서 다른 목적지와의 연결은 명시되지 않음 | 세부 분류를 새로 만들지 않음 |

## 5. 발견·진입·복귀 관계

### 검색과 필터

- 검색의 목적지는 `D-LIB`이며, 검색 결과의 자료 선택은 같은 ID의 `D-ITEM`으로 이어진다.
- 작성자와 태그는 `D-LIB`의 필터다. 정렬 역시 목록 문맥으로 유지한다.
- 확정된 복귀 문맥은 검색어 `q='작은 팀'`, 태그 `tag='운영'`, 정렬 `newest`, 목록 위치 `item R-72`다.
- 입력에는 작성자 필터의 URL 표현, 다중 필터 조합 규칙, 검색 대상 필드가 없다. 이 맵은 해당 규칙을 새로 정하지 않는다.

### 직접 진입과 문맥 진입

| 진입점 | 도착점 | 보존해야 할 식별·문맥 |
|---|---|---|
| `D-LIB`의 기본 목록 | `D-ITEM /items/R-72` | 자료 ID `R-72`; 기본 목록 복귀 문맥 |
| `D-LIB`의 검색·필터 결과 | `D-ITEM /items/R-72` | 자료 ID와 `q`, 태그, 정렬, 목록 위치 |
| 추천 | `D-ITEM /items/R-72` | 동일 자료 ID. 추천 출처의 별도 복귀 규칙은 입력에 없음 |
| `/items/R-72` 직접 URL | `D-ITEM /items/R-72` | 자료 ID. 선행 목록 문맥은 없음 |
| `D-ITEM`의 출처 링크 | 외부 원문 URL | 돌아왔을 때 현재 자료 `R-72`와 메모 입력 유지 |
| `D-ITEM`의 본문 건너뛰기 | 같은 `D-ITEM` 내부의 본문 | 현재 자료와 메모 입력 유지 |

### 복귀 규칙

1. 검색·필터 결과에서 `R-72` 상세로 들어왔다가 기존 뒤로가기를 사용하면 `D-LIB`로 돌아가 `q='작은 팀'`, `tag='운영'`, `newest`, `R-72`의 목록 위치를 복원한다.
2. 출처로 이동하거나 본문으로 건너뛰는 동작은 목록 복귀로 해석하지 않는다. 현재 자료와 입력을 변경하지 않는다.
3. 직접 URL 진입에는 복원할 선행 목록 문맥이 없다. 이 경우의 제품 내 기본 복귀 목적지는 입력에서 정하지 않았으므로 새 규칙을 가정하지 않는다.
4. `D-SAVED` 또는 추천에서 상세로 들어온 뒤 어느 문맥으로 복귀하는지는 입력에서 정하지 않았다. 해당 진입점의 문맥 보존이 필요하다면 후속 결정이 필요하다.

## 6. 저장 관계에 대한 구조적 제약

`T-SAVE`의 세부 화면 전이는 이 맵의 범위 밖이지만, 목적지와 데이터 관계를 잘못 만들지 않도록 다음 상태 제약은 유지한다.

```text
D-ITEM의 R-72 + 메모 초안
  → 동일 저장 요청(pending)
  → timeout-unknown
  → 상태 확인: pending
  → 상태 확인: succeeded + 유일 receipt S-72
  → D-SAVED에서 같은 R-72의 저장 관계 확인 가능
```

- `timeout-unknown`은 실패도 성공도 아니다.
- 승인된 복구는 같은 요청의 **상태 확인**이며 새 저장 요청의 재전송이 아니다.
- 같은 요청에 대한 중복 입력은 무시한다.
- 저장 작업을 닫아도 서버 작업을 취소하지 않고 메모 초안은 유지한다.
- 인증 복구 뒤 동일 키로 작업을 재조회하는 서버 API는 미정이다. 따라서 이 구간에서 성공·실패나 새 요청 생성을 추정하지 않는다.

## 7. 좁은 화면의 정보 우선순위

화면 배치나 메뉴 형태는 정하지 않고, 도달 가능성과 정보 우선순위만 정의한다.

1. **현재 과업 유지:** 검색 진입과 `D-SAVED` 진입은 숨겨져 도달 불가능해지면 안 된다.
2. **자료 식별:** 제목을 우선하고, 자료를 구별하거나 좁히는 작성자·태그 문맥을 유지한다.
3. **상세의 핵심 관계:** 현재 자료의 요약, 원문 URL, `T-SAVE`와 메모 초안에 계속 접근할 수 있어야 한다.
4. **목록 문맥 복원:** 상세에서 돌아올 때 검색어·태그·정렬·`R-72` 위치를 잃지 않는다.
5. **보조 목적지:** `D-HELP`는 기존 목적지로 유지하되, 좁은 화면에서 검색과 내 보관함보다 높은 우선순위를 갖는다는 근거는 없다.

위 우선순위는 메뉴를 탭, 드로어, 하단 탐색 등 특정 컴포넌트로 만들라는 뜻이 아니다.

## 8. 경로 점검

| 찾기 과업 | 경로 | 결과 |
|---|---|---|
| 검색과 태그로 자료 찾기 | `D-LIB` → `q='작은 팀'` + `tag='운영'` + `newest` → `R-72` → `D-ITEM` | 도달 가능. 동일 ID 유지 |
| 상세에서 기존 목록으로 돌아가기 | `D-ITEM R-72` → 기존 뒤로가기 → `D-LIB`의 이전 문맥과 `R-72` 위치 | 복귀 조건 확정 |
| URL로 자료 바로 열기 | `/items/R-72` → `D-ITEM R-72` | 도달 가능. 제품 내 기본 복귀점은 미정 |
| 원문 확인 뒤 작업 계속하기 | `D-ITEM R-72` → 원문 URL → 돌아오기 | 현재 자료와 메모 입력 유지 필요 |
| 불확실한 저장 결과 복구하기 | `D-ITEM`의 동일 `T-SAVE` → 상태 확인 → pending → 상태 확인 → succeeded + `S-72` | 경로 확정. 인증 복구 뒤 재조회 API만 미정 |
| 저장 자료 다시 찾기 | 좁은 화면을 포함한 `D-SAVED` 진입 → 저장된 `R-72` | 목적지와 접근 요구는 확정. 목록·상세 간 복귀 문맥은 입력에 없음 |

## 9. 변경 사항과 남은 결정

### 구조 변경

- 목적지 추가·삭제·이름 변경 없음.
- 기존 `D-LIB`, `D-ITEM`, `D-SAVED`, `D-HELP`를 유지한다.
- 태그·작성자는 필터로 유지하고 전역 메뉴로 만들지 않는다.
- 여러 발견 경로가 같은 자료 ID와 한 개의 상세 목적지로 수렴하도록 관계를 명시한다.

### 명시적으로 미결인 정책

| 미결 항목 | 구조에 미치는 영향 | 결정 전 처리 |
|---|---|---|
| 초대가 만료된 팀 자료를 읽을 수 있는가 | 검색·목록 노출, 직접 URL 접근, `D-ITEM`의 접근 조건이 달라짐 | 숨김과 접근 불가를 동일시하지 말고, 새 권한 규칙을 만들지 않음 |
| 인증 복구 뒤 동일 키로 저장 작업을 재조회하는 서버 API | `T-SAVE`의 불확실 상태를 인증 이후에도 이어갈 수 있는지가 달라짐 | 새 저장 요청을 보내거나 성공·실패로 단정하지 않음 |

### 입력에 없어서 가정하지 않은 세부 사항

- 직접 진입, 추천, `D-SAVED`에서 상세를 연 뒤의 기본 복귀 목적지와 문맥
- 검색 대상 필드, 작성자 필터의 URL 표현, 필터 조합 방식
- 각 목록에서 제목·요약·작성자·태그를 얼마나 노출할지
- `D-HELP`의 세부 콘텐츠 분류와 기존 전역·지역 탐색에서의 정확한 노출 위치

이 세부 사항은 현재 네 목적지와 확정된 검색 복귀 경로를 정의하는 데는 차단 요소가 아니지만, 관련 화면 또는 동작 명세를 작성하기 전에는 확인해야 한다.
