# `explain-interface` 역할 범위

## 역할

`explain-interface`는 웹사이트, 시각 효과 또는 애니메이션이 **어떤 구조와 기법으로 만들어졌는지 설명**하는 역할이다. 기존 결과물을 평가하거나 개선안을 설계하는 역할은 아니다.

## 입력

이 역할이 받는 입력은 다음과 같다.

- 설명할 대상: 전체 사이트 또는 특정 효과·애니메이션
- 대상에 접근할 근거: 라이브 URL 또는 스크린샷
- 사용자가 특히 알고 싶은 범위: 예를 들어 전체 프런트엔드 구성, 그라디언트, 전환 효과, 타이포그래피 등

전체 사이트가 대상이면 프레임워크와 렌더링 방식, 스타일링 체계, 컴포넌트와 토큰, 글꼴·간격·색상, 모션, 브레이크포인트, 이미지와 폰트 제공 방식을 살핀다. 특정 효과가 대상이면 그 효과를 만드는 레이어를 페인트 순서대로 좁혀 살핀다.

라이브 URL은 실제 DOM, 계산된 스타일, 의사 요소, 애니메이션과 전달된 HTML·CSS를 근거로 삼을 수 있다. 스크린샷만 있으면 원본 구현을 읽을 수 없으므로, 결과는 사실 확인이 아니라 **같은 인상을 만들 수 있는 재구성 가설**이다.

이번 작업의 실제 입력은 역할 경계 설명 요청뿐이다. 제공된 로컬 URL은 분석 대상으로 사용하지 않았고, 별도의 사이트 질문이나 스크린샷도 입력되지 않았다.

## 출력

일반적인 `explain-interface`의 출력은 다음 원칙을 따른다.

- 전체 사이트 질문: 관찰 근거와 함께 프런트엔드 시스템을 설명한다.
- 특정 효과 질문: 배경부터 전경까지 레이어 순서, 각 레이어의 구현 기법, 시각적으로 맡는 일을 설명한다.
- 수치는 나열로 끝내지 않고 어떤 패턴과 지각 효과를 만드는지 해석한다.
- 모든 주장은 **측정됨**, **계산됨**, **추론됨** 중 하나로 구분한다.
- 마지막에는 복사 가능한 원리와 그대로 옮길 수 없는 요소를 나누고, 읽지 못한 부분을 명시한다.
- 컴파일된 결과에서 원저자가 사용한 라이브러리나 작성 코드를 단정하지 않는다.

결과물은 재현 코드나 디자인 시안이 아니라, 관찰 가능한 근거에 기반한 메커니즘 설명이다.

## 인접 역할

- `design-browser`: 라이브 페이지의 렌더링, 상태, 모션, 계산된 스타일 등 브라우저 근거를 수집한다. `explain-interface`가 실제 URL을 조사할 때 사용하는 증거 수집 역할이지, 설명의 최종 소유자는 아니다.
- `interface-review` / `better-interface`: 인터페이스를 기준에 따라 검토하고 문제나 품질을 판단한다. `explain-interface`는 좋고 나쁨을 판정하지 않는다.
- `variant`: 사용자의 인터페이스에 대한 대안이나 변형을 탐색한다. `explain-interface`는 대안을 제안하지 않는다.
- `better-typography`, `better-colors` 같은 도메인 역할: 관찰한 기법을 정확한 분야 용어로 명명할 때 도움을 준다. 해당 분야를 전면 재설계하는 일은 이 역할의 범위를 벗어난다.

## 종료 지점

`explain-interface`는 질문한 대상의 작동 메커니즘을 근거 수준과 함께 설명하고, 전이 가능한 원리·복사할 수 없는 요소·관찰 한계를 밝힌 지점에서 끝난다.

다음 작업으로 넘어가지 않는다.

- 디자인 품질 평가 또는 표준 준수 판정
- 개선안, 변형안, 새 화면이나 사용자 흐름 설계
- 코드 작성, 구현, 수정 또는 배포
- 사용자가 지정하지 않은 링크 탐색, 로그인, 폼 제출
- 근거 없이 원본 소스·라이브러리·작성 의도를 단정하는 일

이번 역할 경계 확인에서는 여기서 더 일찍 멈춘다. 실제 사이트 조사, 브라우저 조작, 시각 효과 분석, 디자인 산출물 제작은 수행하지 않는다.

## 확인 한계

이번 산출물은 제공된 `TASK.md`와 로컬 `explain-interface` 스킬 문서만 바탕으로 작성했다. 라이브 페이지나 스크린샷을 열지 않았으므로 실제 인터페이스 구현에 관한 측정값, 계산값 또는 추론 결과는 포함하지 않는다.
