# EX-44 내보내기 사용자 흐름 계약

## 문서 정보

- 흐름 ID: `UF-EX-44`
- 근거: `TASK.md`의 단일 내보내기 작업 요청, `BRIEF.md`의 **Export job EX-44, approved decisions revision 2**
- 작성일: 2026-10-14
- 상태: 하위 화면 명세용 흐름 계약. 사용자 수용 검증 완료 상태는 아님.

## 작업 경계와 성공 기준

### 고정된 사실

- 행위자는 분석가이며, `q=주간`, `owner=나`, `sort=recent`가 적용된 `D-REPORT`에서 시작한다.
- 이 흐름의 목적지는 `D-REPORT`와 `D-EXPORT`뿐이다.
- 초안에는 파일명과 `CSV` 또는 `JSON` 형식이 있다.
- 최초 제출은 작업 키 `J-44`를 만들지만 클라이언트에서는 타임아웃으로 완료 여부를 알 수 없게 된다.
- 복구는 `J-44` 상태 확인으로만 한다. 완료 여부가 불명확하다는 이유로 새 제출을 해서는 안 된다.
- 첫 번째 상태 확인은 `pending`, 두 번째 상태 확인은 `ready`와 영수증 `E-44`, 다운로드 URL을 반환한다.
- 같은 다운로드를 다시 받아도 새 작업을 만들지 않는다.
- 닫기는 제출 전, 실행/불명확 상태, 준비 완료 후에 제공된다. 닫아도 작업은 취소되지 않고, 같은 로컬 방문 동안 초안과 이미 알려진 상태가 유지된다.
- 해당 요청이 진행 중일 때 들어오는 중복 제출 및 중복 상태 확인 이벤트는 무시한다.
- 확인된 실패는 완료 여부 불명확과 다른 상태다. 확인된 실패 뒤의 재시도 정책, 인증 복구, 브라우저 재시작 뒤의 보존 정책은 승인되지 않았다.

### 작업 결과와 관찰 가능한 성공

- 의도한 결과: 현재 필터의 보고서 내보내기가 준비되어 분석가가 그 결과를 내려받을 수 있다.
- **내보내기 작업의 실제 성공 조건:** `J-44`의 상태 확인 응답이 `ready`이고, 그 응답에 영수증 `E-44`와 다운로드 URL이 함께 존재한다. 제출 클릭, 타임아웃, `pending`, 다운로드 클릭만으로는 작업 성공으로 판정하지 않는다.
- 화면에서 식별할 수 있어야 하는 성공 증거: 준비 완료 상태, 영수증 `E-44`, 기존 결과를 받는 다운로드 행동.
- 파일이 실제로 로컬 저장소에 끝까지 기록되었는지를 제품이 별도로 확인하는 정책은 입력에 없다. 따라서 이 계약은 브라우저 다운로드 시작 이후의 전송 완료·실패를 성공 증거로 새로 정의하지 않는다.

### 명세 해석과 범위 밖

- `[해석 A-01]` “폼 초안”은 제출 전에 파일명과 형식을 바꿀 수 있는 것으로 해석한다. 빈 값, 잘못된 파일명, 형식 누락의 검증 규칙은 주어지지 않았으므로 이 흐름에 추가하지 않는다.
- 상태 이름과 사용자가 구별해야 할 의미는 이 계약의 제안이다. 실제 문구, 화면 배치, 컴포넌트와 구현 방식은 범위 밖이다.
- 구현 코드, 기존 화면 동작, 실제 서버 응답은 확인하지 않았다.

## 목적지별 노출 계약

### `D-REPORT`

- `q=주간`, `owner=나`, `sort=recent` 필터를 그대로 유지해야 한다.
- 첫 진입 또는 닫힌 내보내기를 여는 행동을 제공해야 한다.
- 내보내기 보기를 닫았다는 사실을 작업 취소로 표현해서는 안 된다.

### `D-EXPORT`

- 제출 전에는 초안의 파일명과 형식, 제출 행동, 닫기 행동을 제공해야 한다.
- 제출 요청 중에는 진행 중 상태를, 타임아웃 뒤에는 “확인된 실패”가 아닌 “완료 여부 불명확”을 구별해야 한다.
- 불명확 또는 `pending` 상태에서는 새 제출 대신 `J-44` 상태 확인 행동을 제공해야 한다. 작업 키를 화면에 문자열로 노출할지는 정하지 않지만 제품은 같은 키를 사용해야 한다.
- 상태 확인 중에는 확인 진행 중임을 구별하고 중복 확인 이벤트를 무시해야 한다.
- 준비 완료에는 영수증 `E-44`, 다운로드 가능 상태, 다운로드/재다운로드 행동을 제공해야 한다.
- 확인된 실패는 불명확 상태와 다르게 표현하되, 승인되지 않은 재시도 행동을 임의로 제공하지 않는다.

## 경로 점검

### `W-01` 승인된 성공 경로

`T-01` → `T-03` → `T-05` → `T-06` → `T-08` → `T-06` → `T-09` → `T-13`

- 결과: 한 번의 제출로 `J-44`만 생성되고, 첫 확인의 `pending`을 거쳐 두 번째 확인에서 `E-44`와 URL이 확보된다.
- 사용자는 타임아웃, 처리 중, 준비 완료를 서로 구별할 수 있고 준비 완료 뒤의 다음 행동을 찾을 수 있다.
- 판정: 내부 일관성 통과.

### `W-02` 중복 입력 경로

`T-03` → `T-04` → `T-05`, 이어서 `T-06` → `T-07` → `T-08`

- 결과: 중복 제출은 새 작업을 만들지 않고, 중복 상태 확인은 추가 확인 요청을 만들지 않는다. 원래 요청의 응답만 상태를 전진시킨다.
- 판정: 내부 일관성 통과.

### `W-03` 제출 전 닫기와 복귀

`T-01` → `T-02` → `T-11` → `T-12`

- 결과: `D-REPORT`의 필터와 수정한 초안은 유지된다. 상태는 `O-00`이므로 복귀할 때 작업 키나 영수증을 만들지 않는다.
- 판정: 내부 일관성 통과.

### `W-04` 진행 중 또는 불명확 상태에서 닫기와 복귀

- 제출 요청 중: `T-03` → `T-11` → 닫힌 상태에서 `T-05` → `T-12`.
- 상태 확인 중: `T-06` → `T-11` → 닫힌 상태에서 `T-08` 또는 `T-09` → `T-12`.
- 결과: 닫기는 작업을 취소하지 않는다. 다시 열면 닫기 전 상태를 무조건 복제하는 대신, 그동안 도착한 응답까지 반영한 **마지막으로 알려진 상태**를 복원한다.
- 판정: 내부 일관성 통과.

### `W-05` 준비 완료 뒤 닫기·복귀·재다운로드

`T-09` → `T-11` → `T-12` → `T-13` → `T-13`

- 결과: 복귀 뒤에도 `J-44`, `E-44`, URL이 유지된다. 두 번의 다운로드 모두 같은 준비 완료 결과를 사용하고 새 작업은 생기지 않는다.
- 판정: 내부 일관성 통과.

### `W-06` 확인된 실패 경로

`T-06` → `T-10` → `O-06`

- 결과: 실패는 타임아웃 불명확 상태로 되돌아가지 않는다. 그러나 승인된 재시도와 실패 상태에서의 종료 행동이 없어 다음 전이는 `P-01`에 막힌다.
- 판정: 상태 구분은 일관되나 제품 정책 결정 전에는 완결할 수 없음. EX-44에 승인된 정상 응답 순서에서는 실행되지 않는 경계 경로다.

### 행동-전이 대조 결과

| 상태에서 제공하거나 방어해야 하는 행동 | 대응 전이 | 결과 |
|---|---|---|
| 최초 열기 / 다시 열기 | `T-01`, `T-12` | 일치 |
| 초안 수정 | `T-02` | 일치 (`A-01`) |
| 제출 / 진행 중 중복 제출 | `T-03`, `T-04` | 일치 |
| 상태 확인 / 진행 중 중복 확인 | `T-06`, `T-07` | 일치 |
| 제출 전·진행/불명확·준비 완료 상태에서 닫기 | `T-11` | 일치 |
| 다운로드 / 재다운로드 | `T-13` | 일치 |
| 확인된 실패 뒤 재시도 또는 종료 | 없음 | `P-01` 때문에 의도적으로 미결 |

도달 가능한 승인 경로에 고아 상태나 상충하는 전제는 발견되지 않았다. `O-06`의 후속만 승인되지 않은 정책 의존 상태다.

## 미결 정책과 검증 한계

| ID | 미결 사항 | 현재 계약의 처리 | 필요한 결정 |
|---|---|---|---|
| `P-01` | 확인된 실패 뒤 재시도 및 실패 상태에서 벗어나는 행동 | `O-06`에서 새 제출, 같은 키 재확인, 닫기를 임의로 허용하지 않음 | 허용 행동, 새 작업 생성 여부, 초안 재사용 여부, 실패 상태의 종료 경로 |
| `P-02` | 인증이 만료되거나 인증이 요구될 때의 복구 | 인증 관련 전이를 만들지 않음 | 인증 목적지, 복귀 위치, 진행 중 요청·초안·키의 보존 규칙 |
| `P-03` | 브라우저 재시작 뒤의 보존 | 같은 로컬 방문 동안만 복원 보장 | 초안, `J-44`, `E-44`, URL 각각의 저장 기간과 저장 위치 |
| `P-04` | 다운로드 전송 완료·실패 피드백 | `T-13`은 기존 URL로 다운로드를 시작하고 `O-05`를 유지 | 완료 확인 방식, 전송 실패 시 재시도/오류 처리, 만료 URL 처리 |

이 점검은 문서에 적힌 전이를 저자가 따라가며 확인한 내부 일관성 검사다. 실제 사용자 과업 성공, 접근성, 브라우저 동작, 서버 동시성은 검증하지 않았다. 계정과 라이브 API를 사용하지 않았고, 구현 관찰도 수행하지 않았다.
