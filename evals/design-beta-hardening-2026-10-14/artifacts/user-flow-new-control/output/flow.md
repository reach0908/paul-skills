# EX-44 내보내기 상태·전이 명세

## 범위와 기준

- 대상은 현재 필터가 적용된 `D-REPORT`에서 내보내기 영역 `D-EXPORT`로 이어지는 작업 하나다.
- 범위 안의 목적지는 `D-REPORT`, `D-EXPORT`뿐이다.
- 보고서로 돌아왔을 때 `q=주간`, `owner=나`, `sort=recent`를 그대로 유지한다.
- 초안은 파일명과 `CSV` 또는 `JSON` 형식을 가진다. 필수값 검증이나 형식별 세부 규칙은 입력에 없으므로 정하지 않는다.
- 작업 상태와 화면의 열림/닫힘은 별개다. 닫기는 작업을 취소하거나 작업 상태를 바꾸지 않고, 현재 로컬 방문 동안 초안을 보존한다.

## 사용자가 볼 수 있는 행동

| 행동 | 사용자에게 보이는 결과 | 실제 처리 규칙 |
|---|---|---|
| 내보내기 열기 | `D-EXPORT`에서 초안과 현재 알려진 작업 상태를 본다. | 처음 열면 아직 작업 키와 영수증이 없다. 같은 로컬 방문에서 다시 열면 보존된 초안과 알려진 상태를 복원한다. |
| 초안 편집 | 파일명과 `CSV`/`JSON` 선택이 초안에 반영된다. | 제출 전 작업 상태는 바뀌지 않는다. |
| 제출 | 제출 진행 상태를 본다. | 최초 요청은 작업 `J-44`를 만든다. 제출 요청이 진행 중일 때 추가 제출은 새 요청을 만들지 않는다. |
| 상태 확인 | 확인 진행 상태를 거쳐 `대기 중`, `준비됨`, 또는 확인된 `실패`를 본다. | `timeout-unknown` 또는 `pending`인 동일한 `J-44`만 조회한다. 확인 요청 진행 중의 추가 확인은 새 요청을 만들지 않는다. |
| 닫기 | `D-REPORT`로 돌아간다. | 작업을 취소하지 않는다. 보고서 필터와 이 로컬 방문의 초안을 보존한다. |
| 다시 열기 | `D-EXPORT`에서 마지막으로 알려진 상태를 본다. | 제출 전에는 키를 만들어 내지 않으며, 준비된 뒤에는 `E-44`와 다운로드 URL을 잃지 않는다. 닫혀 있는 동안 끝난 요청이 있다면 그 결과를 포함한 최신 알려진 상태를 복원한다. |
| 다운로드 | 준비된 결과의 다운로드를 시도한다. | `E-44`에 연결된 기존 URL을 사용하며 새 작업을 만들지 않는다. |
| 다시 다운로드 | 같은 준비된 결과를 다시 받을 수 있다. | 작업 키는 `J-44`, 영수증은 `E-44`로 유지되며 제출 요청을 새로 보내지 않는다. |

## 작업 상태 표

| ID | 작업 상태 | 보존되는 사실 | `D-EXPORT`에서 보여야 하는 의미 | 성공 여부 |
|---|---|---|---|---|
| `S0` | 미제출 | 초안, 키 없음, 영수증 없음 | 아직 작업을 만들지 않음 | 성공 아님 |
| `S1` | 제출 요청 중 | 초안, 생성 대상 작업은 `J-44`, 영수증 없음 | 요청 처리 중 | 성공 아님; 추가 제출은 무시 |
| `S2` | 시간 초과·결과 불명 (`timeout-unknown`) | 초안, `J-44`, 영수증 없음 | 서버에서 계속 처리 중일 수 있어 상태 확인이 필요함 | 실패로 판정하지 않음; 재제출 금지 |
| `S3(U)` | 상태 확인 중—직전 상태 불명 | 초안, `J-44`, 영수증 없음 | `J-44` 확인 중 | 성공 아님; 추가 확인은 무시 |
| `S3(P)` | 상태 확인 중—직전 상태 대기 | 초안, `J-44`, 영수증 없음 | `J-44` 다시 확인 중 | 성공 아님; 추가 확인은 무시 |
| `S4` | 대기 중 (`pending`) | 초안, `J-44`, 영수증 없음 | 작업이 존재하며 아직 준비되지 않음 | 성공 아님; 같은 키를 다시 확인 |
| `S5` | 준비됨 (`ready`) | 초안, `J-44`, 영수증 `E-44`, 다운로드 URL | 기존 결과를 다운로드하거나 다시 다운로드할 수 있음 | 내보내기 생성 성공 |
| `S6` | 확인된 실패 (`failed`) | 초안, `J-44`, 영수증 없음 | 결과 불명과 구별되는 확정 실패 | 실패 확정; 이후 재시도 정책은 미결 |

`S1`의 서버 측 생성과 클라이언트가 키를 확실히 보존하는 시점 사이의 세부 통신 순서는 입력에 없다. 다만 `S2`부터는 승인된 복구가 `J-44` 조회이므로 그 키가 알려져 있어야 한다.

## 보기 상태

| 보기 상태 | 목적지 | 규칙 |
|---|---|---|
| `OPEN(Sx)` | `D-EXPORT` | 작업 상태 `Sx`의 행동을 제공한다. |
| `CLOSED(Sx)` | `D-REPORT` | 작업 상태 `Sx`를 유지한 채 내보내기 영역만 닫혀 있다. `q=주간`, `owner=나`, `sort=recent`를 유지한다. |

닫기가 승인된 작업 상태는 미제출, 제출 중, 결과 불명, 상태 확인 중, 대기 중, 준비됨이다. 확인된 실패 뒤의 닫기 제공 여부는 입력에 없으므로 결정하지 않는다.

## 전이 표

| 전이 | 현재 상태·목적지 | 행동 또는 결과 | 다음 상태·목적지 | 사용자에게 보이는 변화와 불변 조건 |
|---|---|---|---|---|
| `T01` | `D-REPORT` | 내보내기 열기 | `OPEN(S0)` 또는 보존된 `OPEN(Sx)` | 처음이면 키·영수증이 없는 초안을, 재진입이면 최신 알려진 상태를 본다. |
| `T02` | `OPEN(S0)` | 파일명/형식 편집 | `OPEN(S0)` | 초안만 바뀌며 키·영수증은 생기지 않는다. |
| `T03` | `OPEN(S0)` | 제출 | `OPEN(S1)` | 최초 요청 한 건이 시작되고 서버 작업 `J-44`가 생성된다. |
| `T04` | `OPEN(S1)` | 제출 반복 | `OPEN(S1)` | 입력을 무시하며 추가 제출 요청이나 추가 작업을 만들지 않는다. |
| `T05` | `OPEN/CLOSED(S1)` | 최초 요청이 시간 초과로 결과 불명 | 같은 보기의 `S2` | `J-44`를 보존한다. 실패로 바꾸거나 재제출하지 않는다. |
| `T06` | `OPEN(S2)` | 제출 이벤트 | `OPEN(S2)` | 승인된 복구 경로가 아니므로 재제출하지 않고 새 작업도 만들지 않는다. |
| `T07` | `OPEN(S2)` | 첫 상태 확인 | `OPEN(S3(U))` | `J-44`에 대한 확인 요청 한 건을 시작한다. |
| `T08` | `OPEN(S3(U))` 또는 `OPEN(S3(P))` | 상태 확인 반복 | 현재 상태 유지 | 입력을 무시하며 확인 요청을 추가하지 않는다. |
| `T09` | `OPEN/CLOSED(S3(U))` | 첫 확인 결과 `pending` | 같은 보기의 `S4` | `J-44`는 유지되고 영수증은 아직 없다. |
| `T10` | `OPEN(S4)` | 두 번째 상태 확인 | `OPEN(S3(P))` | 동일한 `J-44`에 대한 확인 요청 한 건을 시작한다. |
| `T11` | `OPEN/CLOSED(S3(P))` | 두 번째 확인 결과 `ready` | 같은 보기의 `S5` | 영수증 `E-44`와 다운로드 URL을 저장한다. |
| `T12` | `OPEN(S5)` | 다운로드 | `OPEN(S5)` | 기존 URL을 사용하며 `J-44`와 `E-44`는 바뀌지 않는다. |
| `T13` | `OPEN(S5)` | 다시 다운로드 | `OPEN(S5)` | 같은 결과를 다시 사용하고 새 작업을 만들지 않는다. |
| `T14` | `OPEN/CLOSED(S3(U/P))` | 상태 확인 결과가 확정 실패 | 같은 보기의 `S6` | 결과 불명이나 대기와 구별해 실패로 표시한다. 후속 재시도는 수행하지 않는다. |
| `T15` | 승인된 `OPEN(Sx)` | 닫기 | `CLOSED(Sx)` | `D-REPORT`로 돌아가며 작업은 취소되지 않고 초안과 필터가 유지된다. |
| `T16` | `CLOSED(Sx)` | 다시 열기 | 최신 알려진 `OPEN(Sx)` | 제출 전에는 키가 없고, 준비 후에는 `E-44`와 URL이 유지된다. |

`T14`는 확정 실패를 결과 불명과 분리하기 위한 대체 경로다. 승인된 EX-44의 기준 경로는 첫 확인 `pending`, 두 번째 확인 `ready`인 `T07`~`T11`이다.

## 실제 성공 기준

| 단계 | 성공으로 인정하는 증거 | 성공으로 인정하지 않는 것 |
|---|---|---|
| 작업 생성 | 동일 요청에 작업 키 `J-44`가 하나만 존재함 | 제출 버튼 클릭, 진행 표시, 시간 초과 자체 |
| 내보내기 생성 | 상태가 `ready`이고 `J-44`에 영수증 `E-44`와 다운로드 URL이 연결됨 | `timeout-unknown`, 첫 확인의 `pending` |
| 파일 획득 | 준비된 URL을 사용한 다운로드가 실제로 완료됨 | URL 노출이나 다운로드 동작 시작만으로는 완료를 단정하지 않음 |
| 복귀 | `D-REPORT`에서 `q=주간`, `owner=나`, `sort=recent`가 모두 유지됨 | 목적지만 돌아오고 필터가 달라진 상태 |
| 중복 방지 | 진행 중 반복 제출·확인에 추가 요청이 없고, 재다운로드에 새 작업이 없음 | 같은 화면 문구를 보여 주는 것만으로는 중복 방지 증거가 아님 |

입력은 `ready`, 영수증, URL까지 명시하지만 실제 파일 전송 완료나 파일 내용의 정확성은 제공하지 않는다. 따라서 이 문서만으로 확정할 수 있는 생성 성공은 `S5`이며, 파일 획득 성공은 실행 환경의 다운로드 완료 증거가 있어야 한다.

## 경로 일치 확인

정적 명세를 전이 표 순서대로 추적했다. 계정이나 라이브 API는 사용하지 않았다.

| 확인 경로 | 추적한 상태·전이 | 결과 |
|---|---|---|
| 기준 경로 | `D-REPORT → T01:S0 → T03:S1 → T05:S2 → T07:S3(U) → T09:S4 → T10:S3(P) → T11:S5 → T12:S5` | 입력의 `J-44` 생성, 시간 초과·결과 불명, 첫 확인 `pending`, 두 번째 확인 `ready`, `E-44`와 URL 보존 순서와 일치한다. |
| 제출 중복 | `S0 → T03:S1 → T04:S1` | 작업은 `J-44` 하나뿐이며 행동 표의 “진행 중 반복 제출 무시”와 일치한다. |
| 확인 중복 | `S2 → T07:S3(U) → T08:S3(U)` 및 `S4 → T10:S3(P) → T08:S3(P)` | 각 진행 구간에 확인 요청은 한 건만 남아 행동 표와 일치한다. |
| 결과 불명 복구 | `S2 → T06:S2`, 이어서 `T07` | 재제출 없이 `J-44`를 확인하는 승인된 복구와 일치한다. |
| 제출 전 닫기·복귀 | `OPEN(S0) → T15:CLOSED(S0) → T16:OPEN(S0)` | 초안은 유지되고 키·영수증은 새로 생기지 않는다. |
| 실행 중 닫기·복귀 | `OPEN(S1/S3) → T15:CLOSED → T05/T09/T11/T14:CLOSED(결과 상태) → T16:OPEN(결과 상태)` | 닫기가 작업을 취소하지 않고 최신 알려진 상태를 복원한다. |
| 준비 후 닫기·복귀 | `OPEN(S5) → T15:CLOSED(S5) → T16:OPEN(S5)` | `J-44`, `E-44`, URL을 잃지 않는다. |
| 재다운로드 | `S5 → T12:S5 → T13:S5` | 영수증과 작업 키가 그대로이고 새 작업이 생기지 않는다. |
| 확정 실패 | `S2/S4 → 상태 확인 중 S3 → T14:S6` | 결과 불명과 실패가 분리된다. 다만 `S6` 이후 행동은 승인되지 않아 여기서 추적을 멈춘다. |

표에 정의한 모든 사용자 행동은 대응 전이가 있으며, 기준 경로와 중복·닫기·재다운로드 경로에서 다음 상태가 모순되지 않는다. 실제 다운로드 완료는 입력 자료만으로 검증할 수 없어 판정을 보류한다.

## 미결 정책과 명세 한계

- `S6` 확인 후 재시도, 새 제출, 사용자 선택지는 승인되지 않았다. 따라서 자동 재시도나 새 작업 생성을 정하지 않는다.
- 인증 만료와 인증 복구는 미정이다.
- 브라우저 재시작 뒤의 초안·키·영수증 보존은 미정이다. 보존 보장은 현재 로컬 방문 안에서만 적용한다.
- 상태 확인을 자동으로 할지 사용자가 시작할지, 확인 간격과 추가 시간 초과 처리는 입력에 없다. 이 문서는 “첫 확인”과 “두 번째 확인”의 결과 순서만 고정한다.
- 다운로드 URL의 만료, 파일 보관 기간, 실제 파일 내용·무결성 검증은 입력에 없다.
- 확인된 실패 뒤 닫기 제공 여부와 일반적인 작업 취소 기능은 정하지 않는다.
