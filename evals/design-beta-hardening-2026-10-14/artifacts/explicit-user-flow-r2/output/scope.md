# `user-flow` 역할 범위

## 이번 확인의 경계

이 문서는 `user-flow` 스킬의 역할 경계만 설명한다. 실제 제품 과제를 해석해 흐름, 상태 ID, 전이 표, 경로 점검 결과를 만드는 작업은 수행하지 않았다. 화면 설계, 구현, 브라우저 조작도 범위 밖이다.

확인한 로컬 자료는 다음 세 파일뿐이다.

- `TASK.md`: 스킬의 현재 역할과 종료 경계만 설명하라는 작업 지시
- `PROMPT.md`: 로컬 작업 범위, 금지 사항, 한국어 출력 조건
- `.agents/skills/user-flow/SKILL.md`: 역할 정의와 작업 절차

별도의 PM 결정문, 정보 구조(IA), 기존 동작 자료 또는 실제로 설계할 제품 과제는 제공되지 않았다.

## 역할

`user-flow`는 범위가 정해진 제품 과제를 **검사 가능한 전이 계약**으로 바꾸는 역할이다. 사용자가 무엇을 하고, 제품이 어떻게 반응하며, 다음에 어느 상태나 목적지로 가는지를 명시한다. 성공뿐 아니라 과제에서 실제로 발생할 수 있는 비동기 처리, 반복 입력, 실패, 수정, 재시도, 취소, 이탈, 중단 후 복귀도 다룬다.

이 역할은 상태를 화면과 동일시하지 않는다. 여러 상태가 한 화면에 있을 수 있고, 상태 전이가 항상 경로 변경을 뜻하지도 않는다. 또한 제안된 동작, 이미 합의된 정책, 관찰된 구현을 구분한다.

## 입력

실제 흐름 작업을 시작하려면 다음 입력을 받는다.

- 범위가 정해진 제품 과제
- 행위자, 진입 맥락, 의도한 결과, 관찰 가능한 성공 조건
- 확정된 제품 결정과 정책(특히 권한, 저장·복원, 확정 시점처럼 전이를 바꾸는 규칙)
- 관련 정보 구조와 기존 목적지 ID
- 보존해야 할 기존 동작 또는 관찰 자료
- 확인할 요구사항과, 요구사항이 아닌 명시적 가정

IA가 없다고 전체 사이트맵을 새로 만들지는 않는다. 해당 과제에 필요한 최소 목적지만 식별하고, 구조 결정이 열려 있으면 미결정으로 남긴다. 권한·지속성·확정 규칙이 누락되어 중요한 전이를 바꾸는 경우에는 그 전이를 임의로 확정하지 않는다.

## 출력

정상적인 `user-flow` 작업의 출력은 다음을 포함하는 Markdown 전이 계약이다.

- 출처 리비전 또는 동등한 입력 위치
- 과제 경계와 사실: 행위자, 진입점, 목표, 성공 조건
- 안정적인 흐름 ID와 상태 ID
- 권위 있는 전이 표: 출발 상태, 사용자 행동 또는 시스템 이벤트, 전제조건, 피드백, 도착 상태, 유지·변경되는 데이터
- 성공 경로와 의미 있게 다른 복구·이탈·복귀 경로의 점검 결과
- 미해결 정책, 가정, 확인하지 못한 분기와 관찰 한계
- 각 화면이 노출해야 할 정보와 행동(시각적 배치 지시 제외)

저자의 경로 점검은 계약의 내부 일관성을 확인할 뿐 실제 사용자 성공이나 사용자 수용을 입증하지 않는다.

## 인접 역할과 책임 구분

| 인접 역할 | `user-flow`와의 관계 | 이 역할이 넘지 않는 경계 |
|---|---|---|
| 제품 결정 / PM | 과제 범위와 제품 정책을 제공한다. | 중요한 권한·저장·확정 정책을 흐름 작성자가 대신 결정하지 않는다. |
| 정보 구조(IA) | 합의된 목적지와 목적지 ID를 제공한다. | 전체 사이트맵이나 탐색 구조를 새로 설계하지 않는다. |
| 와이어프레임 | 전이와 화면별 필수 정보·행동을 받아 화면 계층과 컨트롤을 구체화한다. | 화면 구성, 배치, 반응형 순서, 시각적 선택을 하지 않는다. |
| 구현 | 계약을 제품 로직과 UI로 구현한다. | 생산 코드, API 동작, 데이터 저장 로직을 작성하지 않는다. |
| 브라우저 관찰 | 기존 흐름 검증이 필요할 때 예상 전이를 기준으로 실제 동작 증거를 수집한다. | 이번 작업처럼 검증 요청이 없으면 브라우저를 조작하지 않으며, 관찰과 제안을 섞지 않는다. |
| `state-machine` 작업대 | 구현된 컴포넌트 상태를 표시하는 별도 작업이다. | 흐름 계획의 선행 조건이 아니며, 사람이 명시적으로 요청하지 않으면 로드하지 않는다. |
| 사용자 수용·사용성 검증 | 실제 사용자가 과제를 성공적으로 수행하는지 검증한다. | 작성자의 워크스루를 사용자 검증으로 간주하지 않는다. |

## 종료 지점

`user-flow`는 선택된 과제 경로가 다음 조건을 만족하면 멈춘다.

1. 구체적인 시작점과 관찰 가능한 성공이 정의되어 있다.
2. 범위 안의 모든 행동에 제품 반응이 연결되어 있다.
3. 도달 가능한 모든 분기가 과제 결과, 의도적 이탈 또는 이름 붙은 의존성으로 끝난다.
4. 성공·복구·이탈·복귀 경로가 전이 표와 일치하는지 점검되었거나, 점검할 수 없는 이유가 기록되어 있다.
5. 와이어프레임과 구현이 추적할 수 있도록 ID, 가정, 미결정 사항, 화면별 필수 정보·행동이 전달되어 있다.

여기서 다음 역할로 인계한다. 화면 설계 요청이 별도로 없다면 와이어프레임을 만들지 않고, 구현하지 않으며, 사용자 수용 상태를 선언하지 않는다.

## 이번 산출물의 한계

이번 요청은 역할 경계 확인만 허용했다. 따라서 실제 제품 과제에 대한 상태·전이·경로는 작성하거나 점검하지 않았다. 브라우저, 제공된 URL, 계정, 라이브 API도 사용하지 않았다. 별도의 설계 입력이 없으므로 이 문서는 특정 제품 흐름의 준비 완료 여부를 판단하지 않는다.
