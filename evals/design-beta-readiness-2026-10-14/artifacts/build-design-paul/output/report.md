## 실제 상태 및 입력 관찰

- 초기: 상태 문구 `저장 전`, 메모 `다음 회의에서 공유`.
- pending/disabled: 저장을 누르면 즉시 `저장 요청 중`, 저장 버튼 `disabled=true`; 메모는 유지됐다.
- 중복 입력: pending 중 같은 버튼의 클릭을 다시 전달해도 상태와 메모가 바뀌지 않았다.
- success: 약 1초 뒤 `저장 완료 S-72`, 상위 피드백 `저장됨`, 저장 버튼이 다시 활성화됐다.
- error: `오류 예시`를 누르면 `저장하지 못했습니다. 다시 시도해 주세요.`가 표시되고 메모는 유지됐다.
- empty: `빈 결과 예시`를 누르면 `검색 결과가 없습니다. 검색어를 바꿔 주세요.`가 표시되고 메모는 유지됐다.
- 키보드: Tab 순서는 `자료함 → 내 보관함 → 검색 → 내 메모 → 저장 → 메모 비우기 → 오류 예시 → 빈 결과 예시`였다. 각 요소에서 3px 포커스 윤곽선과 3px 오프셋이 관찰됐고, 오류 버튼은 Enter로 실행됐다.
- 콘솔: 관찰 종료 시 오류와 경고가 없었다.

## 미결 및 검증 한계

- **빠진 시각 명세.** DS-72에는 pending, error, empty, disabled 전용 화면이 없다. 기존 상태 문구, `role=status`, 버튼의 `opacity:.6`과 포커스 처리를 유지했으며 새 시각 처리는 추가하지 않았다.
- **동작 차이.** PB-72는 첫 저장을 `timeout-unknown`으로 두고 재전송이 아닌 상태 확인을 두 번 거쳐 성공시키도록 정하지만, 현재 `app.js`는 pending 뒤 약 1초 만에 바로 성공한다. `app.js`는 이번 수정 금지 범위여서 이 복구 흐름은 구현·검증하지 않았다.
- **미연결.** 제목, 요약, 메모, receipt는 정적 HTML과 클라이언트 타이머로 제공된다. 서버 저장, 동일 키 재조회, 인증 복구 API는 연결되어 있지 않다.
- **범위 밖.** 뒤로가기 검색 문맥, 원문 URL, 본문 건너뛰기, 만료 초대 권한 정책은 대상 카드 시각 구현에 포함되지 않아 검증하지 않았다.
- 상태별 별도 이미지는 저장하지 않았고, 각 상태는 Playwright의 실제 클릭·키보드 입력과 DOM 상태 반환으로 관찰했다.

브라우저 비교는 1280×900과 320×700에서 수행했다. 정적 서버가 유지되는 동안 위 실행 URL에서 결과를 다시 열 수 있다.
