# `renderQueueCard` 스트레스 리포트

- 실행 URL: <http://127.0.0.1:48914/runs/break-original/app/stress/>
- 대상: 항목 제목과 목록, 권한·로드·오류·새로고침·잠김 프로퍼티를 받아 검토 대기 자료 카드를 렌더링하는 `app/queue.js`의 실제 `renderQueueCard`
- 관찰: 기존 `beta-break-original` 세션에서 위 URL을 한 번 로드해 전체 페이지를 위에서 아래까지 확인함

## 실제로 보인 깨짐

| 시나리오 | 관찰 | 담당 |
| --- | --- | --- |
| 제목 길이 · 빈 문자열 | 제목 없는 항목이 보이는 라벨 없이 매우 좁은 빈 버튼으로 축소됨 | `better-accessibility` |
| 제목 길이 · 공백 없는 긴 문자열 | 제목 버튼이 카드의 오른쪽 경계를 넘어 페이지 밖으로 이어짐 | `better-typography` |
| 좁은 컨테이너 · 320px | 제목 버튼이 320px 카드의 오른쪽 경계 밖으로 빠져나감 | `better-layout` |

위 세 관찰은 결과 페이지에서 각 시나리오 라벨 바로 아래에도 표시했다.

## 깨짐이 보이지 않은 시나리오

- 제목 길이: 한 단어, 일반적인 제목, 여러 문장
- 목록 수량: 0개, 1개, 현실적인 4개, 40개
- 코드상 상태: 검토 권한 없음, 로딩, 오류, 기존 목록을 보여주며 새로고침 중, 잠김

## 적용 및 제외 범위

- 적용: 제목 길이, 공백 없는 문자열, 목록 수량, 고정 320px 컨테이너, 코드에 프로퍼티로 존재하는 상태
- 제외: 이모지·RTL 등 콘텐츠 모양, 넓은 컨테이너, 테마·줌·모션 환경, hover·focus 상호작용. 모두 현재 작업의 명시 범위 밖이다.
- 라이브 데이터는 연결하지 않았고 모든 항목은 하네스 fixture로 전달했다.

## 산출물

- `app/stress/index.html`: 실제 컴포넌트를 import하는 유지 대상 스트레스 페이지
- `output/break-report.png`: 관찰 시점의 전체 페이지 캡처, 1313×5861 PNG
- `output/report.md`: 이 보고서

`app/queue.js`, `app/style.css`, `app/stress.css`는 변경하지 않았다. 스트레스 페이지는 기존 `style.css`와 `stress.css`를 그대로 불러온다.

## 남은 미확인 사항

- 캡처는 깨짐 표기를 페이지에 넣기 전의 단일 관찰 화면이다. 표기를 넣은 뒤에는 한 번만 보라는 절차를 지키기 위해 브라우저를 다시 로드하지 않았으므로, 표기된 최종 페이지의 브라우저 렌더는 재확인하지 않았다.
- 제외한 환경 및 상호작용 상태는 관찰하지 않았다.
- 작업 디렉터리가 Git 저장소로 인식되지 않아 `git diff` 기반 확인은 할 수 없었다. 제품 파일은 편집 명령의 대상에 포함하지 않았다.
