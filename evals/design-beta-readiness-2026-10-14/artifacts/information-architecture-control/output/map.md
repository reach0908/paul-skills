# 공유 자료함 정보 구조 지도

기준: `PB-72 revision 3`  
범위: 기존 목적지와 탐색 문맥의 정리. 화면 배치, 실제 구현, 새 메뉴 및 새 제품 정책은 포함하지 않는다.

## 1. 유지하는 구조

- 전역 목적지는 네 개만 유지한다: **자료함** `D-LIB /library`, **자료 상세** `D-ITEM /items/:id`, **내 보관함** `D-SAVED /saved`, **도움말** `D-HELP /help`.
- 태그와 작성자는 자료함 안에서 결과를 좁히는 **필터**다. 별도 전역 목적지나 메뉴로 승격하지 않는다.
- 같은 자료는 목록, 검색 결과, 추천, 상세, 보관함에서 같은 ID를 사용한다. 예시 자료는 `R-72`이며 상세 주소는 `/items/R-72`다.
- 상세의 본문 내 **출처로 이동**은 원문 URL로 가는 외부 경로다. 자료함으로 돌아가는 경로로 사용하지 않는다.
- **본문으로 건너뛰기**는 같은 상세 안의 위치 이동이다. 현재 자료, 메모 초안, 검색·필터 문맥을 바꾸지 않는다.
- 자료 상세에서 시작하는 `T-SAVE`를 유지한다. 별도 저장 전용 목적지는 만들지 않는다.

## 2. 콘텐츠–목적지 표

| 콘텐츠 / 상태 | D-LIB 자료함 `/library` | D-ITEM 자료 상세 `/items/:id` | D-SAVED 내 보관함 `/saved` | D-HELP 도움말 `/help` | 구조상 역할과 경계 |
|---|---|---|---|---|---|
| 자료 ID | 목록·검색·추천 항목을 같은 ID로 식별 | 주소의 `:id`와 현재 자료를 식별 | 저장된 자료도 원본과 같은 ID 사용 | 해당 없음 | 채널마다 새 ID를 만들지 않는다. |
| 제목 | 결과를 식별하고 상세로 진입하는 핵심 단서 | 현재 자료의 정체성을 확인 | 저장된 자료를 다시 찾는 핵심 단서 | 해당 없음 | `R-72`: **작은 팀에서 실패 후 다시 시도하기** |
| 요약 | 상세 진입 전 자료의 적합성 판단 | 현재 자료 이해 | 저장된 자료 재식별에 사용 가능한 원자료 정보 | 해당 없음 | 요약은 자료 콘텐츠이며 내 메모와 구분한다. 구체 노출량은 화면 설계 범위다. |
| 작성자 | 결과 메타데이터이며 작성자 필터의 기준 | 자료 메타데이터 | 원자료 메타데이터 | 해당 없음 | 작성자는 필터이지 전역 메뉴가 아니다. 필터의 URL 직렬화 방식은 입력에 없다. |
| 태그 | 결과 메타데이터이며 태그 필터의 기준 | 자료 메타데이터 | 원자료 메타데이터 | 해당 없음 | 태그는 필터이지 전역 메뉴가 아니다. 현재 복귀 문맥의 태그는 `운영`이다. |
| 원문 URL | 목록 복귀 링크로 사용하지 않음 | 본문 내 **출처로 이동**의 대상 | 원자료의 출처 정보 | 해당 없음 | 외부 원문으로 나가며 현재 자료의 ID나 입력을 바꾸지 않는다. |
| 검색어·필터·정렬·목록 위치 | `q`, 태그·작성자 필터, 정렬, 현재 목록 위치를 소유 | 상세 진입의 복귀 문맥으로만 보존 | 해당 없음 | 해당 없음 | 알려진 문맥: `q='작은 팀'`, `tag='운영'`, `sort='newest'`, 위치 `R-72`. |
| 내 메모 초안 | 해당 없음 | `T-SAVE` 입력으로 편집하며 닫아도 유지 | 저장 성공 후 해당 자료에 연결된 **내 메모** | 해당 없음 | 타인의 원문과 동일한 소유권으로 취급하지 않는다. 세부 권한은 미결이다. |
| 저장 요청 상태 | 해당 없음 | `pending`, `timeout-unknown`, 상태 확인 결과를 현재 작업과 연결 | 서버가 성공을 확인한 저장만 보관함 결과로 취급 | 해당 없음 | 클라이언트 추정이 아니라 서버 확인과 유일 receipt `S-72`가 성공의 근거다. |
| 사용 안내 | 해당 없음 | 해당 없음 | 해당 없음 | 도움말 콘텐츠의 독립 목적지 | 자료, 필터, 작성자용 새 전역 메뉴를 만들 이유가 아니다. |

## 3. 진입·검색·필터·복귀 경로

### 3.1 직접 진입

| 시작 | 도착 | 사용자가 확인해야 할 것 | 보존 / 미결 |
|---|---|---|---|
| 주소 또는 공유 링크 | `/library` | 자료함과 검색·필터 진입점 | 검색 문맥 없이 시작할 수 있다. |
| 자료 링크 | `/items/R-72` | 제목과 ID가 `R-72`에 일치하는 상세 | 초대가 만료된 팀 자료의 읽기 가능 여부는 미결이다. |
| 주소 또는 기존 전역 진입점 | `/saved` | 내가 저장한 자료와 내 메모 | 원자료와 내 메모의 권한을 하나로 합치지 않는다. |
| 주소 또는 기존 전역 진입점 | `/help` | 도움말 | 네 기존 목적지 중 하나로만 유지한다. |

직접 상세 진입에는 선행 목록 문맥이 없을 수 있다. 이때 임의의 검색어·필터·목록 위치를 만들어 복귀시키지 않는다.

### 3.2 검색 경로

`/library` → 검색어 `q='작은 팀'` 적용 → 결과의 `R-72` 선택 → `/items/R-72`

- 검색 결과와 추천에서 `R-72`는 동일 자료다.
- 상세 진입 시 검색어만이 아니라 함께 적용된 태그 `운영`, 정렬 `newest`, 목록 위치 `R-72`까지 복귀 문맥으로 보존한다.
- 검색 결과 안의 작성자와 태그는 결과를 좁히는 수단이며 별도 목적지로 이동시키지 않는다.

### 3.3 필터 경로

`/library` → 태그 또는 작성자 필터 적용 → 좁혀진 결과 → 자료 선택 → `/items/:id`

- 필터는 자료함의 결과 집합을 바꾸지만 정보 구조의 목적지 수는 바꾸지 않는다.
- 알려진 예에서는 태그 `운영`을 유지한다.
- 작성자 필터의 값, 다중 선택 규칙, URL 매개변수 이름은 결정본에 없으므로 새 규칙을 만들지 않는다.
- 정렬 `newest`는 필터와 함께 복귀 문맥에 포함되지만 전역 목적지는 아니다.

### 3.4 상세에서의 복귀와 비복귀 이동

| 상세 안의 이동 | 목적지 / 효과 | 검색·필터 문맥 | 메모 초안 |
|---|---|---|---|
| 뒤로가기 | 직전 자료함 결과 | `q='작은 팀'`, `tag='운영'`, `sort='newest'`, 목록 위치 `R-72` 복원 | 유지 |
| 출처로 이동 | 현재 자료의 원문 URL | 변경하지 않음 | 변경하지 않음 |
| 본문으로 건너뛰기 | 같은 상세의 본문 위치 | 변경하지 않음 | 변경하지 않음 |
| 저장 작업 닫기 | 현재 저장 UI를 닫음 | 변경하지 않음 | 유지; 서버 작업은 취소하지 않음 |

브라우저의 일반 뒤로가기와 제품 내 복귀 동작 중 무엇을 쓰더라도, 위 문맥 복원이 결과여야 한다. 단, 직접 진입처럼 이전 목록 문맥이 없을 때의 대체 목적지는 결정본에 없으므로 여기서 정하지 않는다.

## 4. 저장 작업과 상태 확인

저장은 탐색 목적지가 아니라 `/items/:id`에 연결된 작업이다.

```text
R-72 상세 + 메모 초안
        │ T-SAVE (동일 요청의 중복 입력은 무시)
        ▼
      pending
        │ 첫 요청의 응답이 불명
        ▼
 timeout-unknown ── 상태 확인(재전송 아님) ──▶ pending
        │                                      │
        └──────────── 두 번째 상태 확인 ───────┘
                                               ▼
                              succeeded + receipt S-72
                                               │
                                               ▼
                               /saved에서 저장 완료로 취급
```

- `timeout-unknown`은 실패도 성공도 아니다. 서버 처리 여부를 모르는 상태 그대로 표현한다.
- 승인된 복구는 같은 작업의 **상태 확인**이다. 새 저장 요청을 보내지 않는다.
- 성공은 서버가 확인하고 유일 receipt `S-72`를 반환했을 때만 확정한다.
- 닫기는 진행 중 서버 작업을 취소하지 않고 메모 초안을 유지한다.
- 인증 복구 뒤 동일 키로 작업을 재조회할 서버 API는 미정이다. 정보 구조가 이 빈칸을 새 요청이나 새 목적지로 메우지 않는다.

## 5. 좁은 화면 우선순위

아래는 노출 순서가 아니라 **접근성·보존 우선순위**다. 구체 배치, 접힘, 고정 방식은 이번 범위가 아니다.

1. **현재 위치와 자료 식별** — 네 목적지 중 현재 위치, 상세에서는 제목과 `R-72`의 일관성을 잃지 않는다.
2. **검색 접근** — 좁은 화면에서도 `/library`의 검색을 시작·수정할 수 있어야 한다.
3. **내 보관함 접근** — 좁은 화면에서도 `/saved`로 이동할 수 있어야 한다.
4. **현재 작업과 상태** — 상세의 메모 초안, `T-SAVE`, `pending`·`timeout-unknown`·성공 확인을 다른 탐색 요소 때문에 잃지 않는다.
5. **필터 및 복귀 문맥** — 태그·작성자 필터는 전역 메뉴가 되지 않으며, 적용 상태와 `q`·정렬·목록 위치가 상세 왕복 뒤 복원돼야 한다.
6. **본문 내 이동** — 출처 링크와 본문 건너뛰기는 현재 자료와 입력을 바꾸지 않는 보조 이동으로 유지한다.
7. **도움말** — 기존 목적지로 접근 가능하게 유지하되 검색과 내 보관함보다 높은 좁은 화면 우선순위를 새로 부여하지 않는다.

## 6. 미결 권한·소유권·복구 결정

| 미결 항목 | 지금 확정된 경계 | 이번 문서에서 결정하지 않는 것 |
|---|---|---|
| 만료된 초대의 팀 자료 | 팀 자료 `R-72`의 정체성과 경로는 유지 | 초대 만료 뒤 읽기 허용 여부, 차단 시 처리 |
| 내 메모와 타인의 원문 | 둘은 같은 소유권 정책이 아님 | 열람·수정·삭제·공유·보존 권한의 구체 규칙 |
| 인증 복구 후 저장 작업 재조회 | 새 저장 요청이 아니라 동일 작업의 상태 확인이어야 함 | 동일 키 재조회 서버 API와 인증 경계 |

이 항목들은 구현에서 임의 기본값으로 닫지 않고, 권한 또는 API 결정이 내려질 때까지 미결 상태로 전달한다.

## 7. 구현 인계용 불변 조건

- 목적지는 `/library`, `/items/:id`, `/saved`, `/help` 네 개다.
- 태그와 작성자는 필터다. 전역 메뉴가 아니다.
- 자료 ID는 목록·검색·추천·상세·보관함에서 동일하다.
- `R-72`의 제목은 **작은 팀에서 실패 후 다시 시도하기**다.
- 뒤로가기는 `q='작은 팀'`, `tag='운영'`, `sort='newest'`, 위치 `R-72`를 복원한다.
- 출처 링크와 본문 건너뛰기는 현재 자료와 입력을 바꾸지 않는다.
- 저장 성공은 서버 확인과 receipt `S-72`로만 확정한다.
- 첫 timeout은 unknown이며, 복구는 재전송이 아닌 상태 확인이다.
- 닫기 뒤에도 초안과 서버 작업이 유지되고, 동일 요청의 중복 입력은 무시된다.
- 좁은 화면에서 검색과 내 보관함에 접근할 수 있어야 한다.
