# 공유 자료함 정보 구조 맵

## 문서 상태와 경계

- **근거:** [`BRIEF.md`](../BRIEF.md) — `공유 자료함, 결정본 PB-72 revision 3`
- **요청:** [`TASK.md`](../TASK.md) — 기존 정보 구조 검토와 콘텐츠-목적지 추적
- **상태:** 기존 네 목적지와 분류 체계는 그대로 사용할 수 있어 **후속 초안 작성 준비됨**. 이 맵 자체의 별도 승인은 요청하지 않았다. 초대 만료 자료의 읽기 권한과 인증 복구 후 재조회 API는 미결이다.
- **대상:** 팀의 읽기 목록에서 자료를 찾고 자기 보관함에 저장하는 사용자
- **범위:** 목적지, 콘텐츠의 소속, 진입·검색·필터·복귀 관계, 좁은 화면의 정보 우선순위, 권한 의존성
- **제외:** 화면 배치, 메뉴 컴포넌트, 상세 작업 전이 설계, 서버 API 설계, 새 권한·소유권 정책

### 고정 결정

1. `D-LIB`, `D-ITEM`, `D-SAVED`, `D-HELP` 네 목적지와 현재 경로를 유지한다.
2. 태그와 작성자는 `D-LIB`의 필터이며 전역 메뉴나 독립 목적지가 아니다.
3. 목록·검색·추천에서 같은 자료 ID는 항상 같은 `D-ITEM`으로 간다.
4. 좁은 화면에서도 검색과 `D-SAVED` 진입은 접근 가능해야 한다.
5. 본문 안의 **출처로 이동**은 원문 URL로 나가는 링크이며 자료 목록 링크가 아니다.
6. 저장 작업 `T-SAVE`의 상태와 복구는 `D-ITEM`에 속한다. 별도 상태 페이지를 만들지 않는다.

### 가정

- `D-SAVED`의 자료도 별도 상세 유형을 만들지 않고 동일한 `D-ITEM`으로 연결한다고 본다. 이는 기존 목적지 네 개를 유지한다는 결정에서 도출한 구조적 가정이며, 새 소유권 정책을 뜻하지 않는다.
- 직접 진입으로 이전 목록 문맥이 없는 경우에는 보존할 검색 상태도 없다. 별도 복귀 제어는 제안하지 않고 현재 전역 탐색 또는 브라우저 이력 범위로 남긴다.
- 전역 내비게이션의 실제 항목 구성과 표시 방식은 입력에 없으므로 확정하지 않는다.

## 목적지

| ID | 사용자 표시명 | 경로 | 포함 콘텐츠 | 지원하는 찾기/작업 | 접근 조건 |
|---|---|---|---|---|---|
| `D-LIB` | 자료함 | `/library` | 팀 자료 목록, 검색어, 작성자·태그 필터, 정렬, 목록 위치 | 자료 검색·필터링·비교, 자료 상세 진입 | 팀 자료 읽기 권한 적용. 초대가 만료된 경우는 미결 |
| `D-ITEM` | 자료 상세 | `/items/:id` | 제목, 요약, 작성자, 태그, 원문 URL, 현재 자료 ID, 메모 초안, `T-SAVE` 상태와 유일 receipt | 자료 확인, 원문 열기, 메모와 함께 저장, 불확실한 저장 상태 확인 | 해당 팀 자료 읽기 권한 적용. 초대 만료 시 규칙 미결 |
| `D-SAVED` | 내 보관함 | `/saved` | 사용자가 저장한 자료와 내 메모 | 저장한 자료 재찾기, 동일 자료 상세로 진입 | 사용자 본인의 보관함 접근. 내 메모와 타인의 원문은 같은 소유권 규칙으로 취급하지 않음 |
| `D-HELP` | 도움말 | `/help` | 제품 사용 도움말 | 사용 방법 찾기 | 입력에 별도 조건 없음 |

`R-72`의 고정 표시는 **작은 팀에서 실패 후 다시 시도하기**이며 상세 목적지는 `/items/R-72`이다.

## 콘텐츠-목적지 추적

| 콘텐츠/상태 | 주 목적지 | 다른 곳에서의 표현 | 분류 판단 |
|---|---|---|---|
| 자료 객체와 안정 ID | `D-ITEM` | `D-LIB`, 검색·추천 결과, `D-SAVED`에서 요약·링크 | 경로마다 복제된 객체가 아니라 같은 자료 상세로 수렴 |
| 제목·요약·작성자·태그 | `D-ITEM` | `D-LIB`의 목록·검색 결과에서 인지 단서로 사용 가능 | 작성자와 태그는 속성이자 필터이며 독립 페이지가 아님 |
| 검색 결과 목록 | `D-LIB` | 없음 | 검색을 별도 목적지로 분리하지 않음 |
| 검색어 `q`, 작성자·태그 필터, 정렬, 목록 위치 | `D-LIB` | `D-ITEM`에서 돌아갈 때 복귀 문맥으로 유지 | 탐색 상태이며 콘텐츠 목적지가 아님 |
| 원문 URL | 외부 출처 | `D-ITEM` 본문의 **출처로 이동** | `D-LIB`로 가는 내부 링크가 아님 |
| 메모 초안 | `D-ITEM` | 저장 성공 전에는 `D-SAVED`의 확정 메모로 간주하지 않음 | 닫아도 유지되는 현재 입력. 서버 취소와 무관 |
| 저장 작업 `T-SAVE` 상태 | `D-ITEM` | 성공 후 `D-SAVED`에서 저장 결과를 찾을 수 있음 | `pending`, `timeout-unknown`, 상태 확인 결과와 receipt를 같은 작업 문맥에 표시 |
| 유일 receipt `S-72` | `D-ITEM`의 `T-SAVE` 결과 | 필요하면 `D-SAVED`의 저장 기록과 연결 | 서버 확인을 받은 성공의 식별자. 별도 영수증 목적지를 만들지 않음 |
| 저장된 자료와 내 메모 | `D-SAVED` | 자료 자체는 동일한 `D-ITEM`으로 연결 | 내 메모 소유권과 타인의 원문 소유권을 합치지 않음 |
| 도움말 콘텐츠 | `D-HELP` | 다른 목적지의 구체적 도움말 링크는 입력에 없음 | 현재 독립 목적지 유지 |
| **본문으로 건너뛰기** | `D-ITEM` 내부 현재 위치 | 없음 | 같은 자료·입력을 유지하는 페이지 내부 이동이며 새 목적지가 아님 |

### 명시적 제외

- 작성자 페이지, 태그 페이지, 검색 결과 전용 페이지, 저장 상태 페이지, receipt 페이지를 새로 만들지 않는다.
- `timeout-unknown`을 실패 또는 성공으로 분류하지 않는다.
- 상태 확인을 새 저장 요청의 재전송으로 해석하지 않는다.
- 화면 크기에 맞춰 새 전역 메뉴나 숨겨진 대체 목적지를 만들지 않는다.

## 발견·진입·복귀 관계

|---|---|---|---|---|
| `/library` 직접 진입 | 자료함 경로 | `D-LIB` | 초기 또는 URL에 표현된 탐색 상태 | 결과에서 자료 선택 → 같은 ID의 `D-ITEM` |
| `D-LIB` | 검색 | `D-LIB` 결과 | 검색어 `q`와 함께 필터·정렬·목록 위치 | 결과 선택 → `D-ITEM`; 뒤로가기 → 같은 `D-LIB` 문맥 |
| `D-LIB` | 작성자 또는 태그 필터, 정렬 | `D-LIB` 결과 | 선택한 작성자/태그와 정렬 | 결과 선택 → `D-ITEM`; 뒤로가기 → 같은 `D-LIB` 문맥 |
| 검색·목록·추천 | 자료 ID 선택 | `D-ITEM` | 진입 출처가 가진 목록 문맥 | 뒤로가기 시 진입 문맥으로 복귀 |
| `/items/:id` 직접 진입 | 안정 URL | `D-ITEM` | 이전 목록 문맥 없음 | 현행 전역 탐색 또는 브라우저 이력만 사용; 새 복귀 제어는 이번 범위에서 만들지 않음 |
| `D-ITEM` | **출처로 이동** | 외부 원문 URL | 현재 자료와 메모 입력은 바꾸지 않음 | 외부 페이지에서 브라우저 복귀 시 같은 `D-ITEM` 문맥 |
| `D-ITEM` | **본문으로 건너뛰기** | `D-ITEM` 내부 본문 | 현재 자료와 입력 모두 유지 | 같은 상세 안에서 계속 탐색 |
| `D-ITEM` | `T-SAVE` 상태 확인 | 같은 `D-ITEM`의 같은 작업 | 메모 초안, 동일 요청 키, 불확실 상태 | 첫 확인 `pending`, 두 번째 확인 `succeeded`와 `S-72`; 성공 후 저장 결과는 `D-SAVED`에서 재발견 가능 |
| `/saved` 또는 기존 내 보관함 진입점 | 직접/기존 탐색 | `D-SAVED` | 사용자의 보관함 문맥 | 저장 자료 선택 → 동일 자료의 `D-ITEM`; 복귀 시 보관함 문맥 |
| `/help` | 직접/기존 탐색 | `D-HELP` | 입력에 정의된 별도 상태 없음 | 현행 전역 탐색 또는 브라우저 이력 |

### 기준 문맥 복귀

검증 기준이 되는 목록 문맥은 다음 한 묶음으로 취급한다.

- 검색어: `q='작은 팀'`
- 태그: `운영`
- 정렬: `newest`
- 목록 위치: `R-72`

이 상태에서 `R-72`를 열어 `D-ITEM`에 들어간 뒤 뒤로가면 네 값이 모두 유지되어야 한다. **출처로 이동**과 **본문으로 건너뛰기**는 이 문맥이나 메모 입력을 변경하지 않는다.

## 좁은 화면의 정보 우선순위

아래는 배치나 메뉴 패턴이 아니라, 좁은 폭에서도 사라지면 안 되는 접근 순서와 관계다.

1. `D-LIB`에서 검색 진입과 현재 검색 결과를 먼저 찾을 수 있어야 한다.
2. `D-SAVED`로 가는 기존 진입점은 계속 접근 가능해야 한다.
3. 검색 결과의 자료 ID는 넓은 화면과 같은 `D-ITEM`으로 연결되어야 한다.
4. 작성자와 태그는 계속 `D-LIB`의 필터로 남고 전역 탐색으로 승격하지 않는다.
5. 상세에서 자료 식별 정보, 원문 URL, 현재 메모 초안과 `T-SAVE` 상태는 같은 자료 문맥을 유지해야 한다.
6. 뒤로가기 시 검색어·필터·정렬·목록 위치 보존은 화면 폭과 무관하게 동일하다.

`D-HELP`의 좁은 화면 노출 우선순위와 실제 메뉴 축약 방식은 입력에 없고 화면 설계 범위이므로 정하지 않는다.

| 검색 과업 | 경로 | 결과 |
|---|---|---|
| 조건으로 `R-72` 찾기 | `D-LIB` → 검색 `작은 팀` → 태그 `운영` → 정렬 `newest` → `R-72` | 도달 가능. 검색·필터·정렬은 한 목적지 안의 탐색 상태로 유지 |
| 상세 확인 후 목록으로 복귀 | 위 결과의 `R-72` → `D-ITEM` → 뒤로가기 | `q`, 태그, 정렬, `R-72` 위치를 보존해야 함. 구조적으로 명확 |
| 원문 확인 | `D-ITEM(R-72)` → **출처로 이동** → 외부 원문 → 브라우저 복귀 | 내부 목록으로 잘못 연결하지 않음. 현재 자료와 입력 유지 |
| 메모와 함께 저장 | `D-ITEM(R-72)`에서 초안 입력 → `T-SAVE` | 서버 확인 전에는 성공으로 분류하지 않음. 성공 결과의 receipt는 `S-72` 하나 |
| timeout 뒤 상태 복구 | 같은 `D-ITEM` → 같은 작업 상태 확인 → `pending` → 다시 상태 확인 → `succeeded` | 새 저장 요청이 아닌 동일 작업 조회. 중복 입력은 무시. 인증 복구 뒤 재조회 API는 미결 |
| 저장 자료 다시 찾기 | `D-SAVED` → 저장 자료 → 동일 `D-ITEM` | 기존 목적지로 수렴. 내 메모와 타인의 원문 권한은 각각 적용되어야 하나 세부 정책은 미결 |
| 상세 URL로 직접 진입 | `/items/R-72` | 자료는 찾을 수 있음. 이전 목록 문맥은 없으며 별도 복귀 목적지는 추가하지 않음 |

## 검토 결과와 제안 변경

- **유지:** 네 목적지의 경계가 자료 탐색, 상세 확인·저장, 개인 재발견, 도움말을 겹치지 않게 나눈다.
- **유지:** 태그·작성자를 필터로 두는 구조는 현재 찾기 과업에 맞고 목적지 증가가 필요 없다.
- **유지:** 안정 자료 ID와 목록 문맥 보존이 여러 진입 경로를 하나의 상세로 수렴시키면서 복귀 가능성을 지킨다.
- **정정이 필요한 분류:** `timeout-unknown`을 오류 완료 상태로 표시하거나 상태 확인을 재저장으로 취급해서는 안 된다. 이는 새 화면 제안이 아니라 기존 `D-ITEM` 콘텐츠의 의미를 명확히 하는 것이다.
- **새 목적지·분류·메뉴 제안:** 없음.

## 남은 결정과 의존성

| ID | 미결 사항 | 영향 범위 | 결정 전 취급 |
|---|---|---|---|
| `U-PERM-INVITE` | 초대가 만료된 팀 자료를 계속 읽을 수 있는가 | `D-LIB`, `D-ITEM`, 직접 URL, 검색 결과 가시성 | 숨김과 접근 불가를 임의로 선택하지 않는다. 권한 상태를 확정할 때까지 IA의 접근 조건으로만 표시 |
| `U-AUTH-REQUERY` | 인증 복구 뒤 동일 요청 키로 `T-SAVE`를 재조회하는 서버 API | `D-ITEM`의 불확실 저장 복구 | 재전송으로 대체하지 않는다. 동일 작업 조회 경로는 API 결정에 의존 |
| `U-OWNERSHIP` | 내 메모와 타인의 원문에 적용되는 구체적 소유권·접근 규칙 | `D-SAVED`, `D-ITEM`, 외부 원문 링크 | 두 콘텐츠를 하나의 소유권 정책으로 합치지 않는다. 새 정책은 만들지 않음 |

미결 사항은 권한과 서버 계약의 정확한 동작을 막지만, 목적지 ID와 콘텐츠 소속을 사용하는 후속 초안은 이 맵으로 진행할 수 있다.
