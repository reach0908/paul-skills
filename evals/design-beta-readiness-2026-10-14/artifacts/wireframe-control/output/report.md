# 로컬 와이어프레임 실행 보고서

## 실행 결과

- 실행 URL: `http://127.0.0.1:48914/runs/wireframe-control/app/index.html`
- 구현 파일: `app/index.html`, `app/style.css`
- 상태/전이 문서: `output/screens.md`
- 브라우저 관찰에는 지정된 Playwright CLI 세션 `beta-wireframe-control`만 사용했으며, 관찰을 마친 뒤 해당 세션을 닫았다.

## 실제 관찰 상태

1. 1280×900 상세 화면에서 메모 칸을 클릭하고 실제 키보드 입력으로 `다음 회고에서 절반 크기 원칙을 적용해 보기`를 작성했다.
2. 첫 `저장`에서 `응답을 받지 못했습니다`와 서버 처리 여부 불명 안내가 나타났다. 요청 키는 `T-SAVE:R-72:LOCAL-01`이었고 저장 버튼은 `저장 요청 전송됨`으로 비활성화돼 중복 요청을 막았다.
3. 첫 `상태 확인`에서는 `저장 처리 중`, 두 번째에서는 `저장되었습니다`와 유일 영수증 `S-72`가 나타났다.
4. 패널을 닫은 뒤 새로고침했을 때 `저장 결과 S-72와 메모가 유지됩니다`가 나타났다. 패널을 다시 열었을 때 입력 메모와 완료 영수증도 복원됐다.
5. `자료 목록으로` 이동했을 때 검색어 `작은 팀`, 태그 `운영`, 정렬 `최신순`, 마지막 위치 `R-72`를 확인했다. R-72 상세로 돌아온 뒤 메모와 `S-72`가 유지됐다.
6. `출처 구역으로 이동`은 `#source-section`으로, 키보드로 실행한 `본문으로 건너뛰기`는 `#article-body`로 이동했다. 두 이동 모두 메모를 바꾸지 않았다.
7. `내 보관함`에는 완료가 확인된 R-72와 입력한 내 메모가 표시됐다.
8. 1280×900에서 문서 폭 1280px/뷰포트 폭 1280px, 320×700에서 문서 폭 320px/뷰포트 폭 320px로 측정되어 가로 넘침은 없었다. 320px에서도 검색창과 내 보관함 메뉴가 노출됐다.
9. 최종 콘솔 확인 결과 오류 0건, 경고 0건이었다.

## 모의 범위와 확인 한계

- 네트워크, 저장 처리, 요청 키, 영수증, 내 보관함은 모두 브라우저 `localStorage` 기반 모의다. 실제 계정이나 서버에는 접근하지 않았다.
- 원문 URL이 자료 목록이 아닌 외부 URL인 것은 DOM과 브라우저 스냅샷에서 확인했지만, 외부 사이트는 열지 않았다.
- 실제 서버 재시도, 계정 인증 복구, 다중 기기 동기화는 확인하지 않았다. 인증 복구 뒤 동일 키 재조회 API는 결정본대로 미정이다.
- 초대 만료 팀 자료의 열람 권한과 내 메모/타인 원문의 세부 소유권 정책은 결정본대로 미정이며 새 정책을 추가하지 않았다.
- 1280×900과 320×700 두 지정 크기만 브라우저로 확인했으며, 그 사이의 모든 폭과 다른 브라우저 엔진은 확인하지 않았다.
