# T-SAVE 화면과 전이

## 화면 ID

| ID | 화면 | 핵심 상태와 조작 |
| --- | --- | --- |
| D-ITEM / S-DETAIL | 자료 상세 | R-72의 제목·요약·작성자·태그·본문·원문 URL, 메모 입력, T-SAVE 시작 |
| S-TIMEOUT | 저장 응답 불명 | 첫 저장 뒤 성공/실패를 단정하지 않고 `timeout-unknown` 안내, 동일 요청 재전송 비활성화 |
| S-PENDING | 저장 처리 중 | 첫 `상태 확인` 결과. 기존 요청이 pending임을 표시 |
| S-SAVED | 저장 완료 | 둘째 `상태 확인` 결과. 유일 영수증 `S-72` 표시 |
| S-CLOSED | 저장 패널 닫힘 | 서버 작업을 취소하지 않고 초안과 현재 결과를 유지, 다시 열기 제공 |
| D-LIB / S-LIST | 자료함 | `q=작은 팀`, `tag=운영`, `sort=newest`, 마지막 위치 `R-72` 보존 |
| D-SAVED / S-MY-SAVED | 내 보관함 | 성공 확인 뒤에만 R-72와 내 메모를 표시 |
| D-HELP / S-HELP | 도움말 | 불확실 상태 복구 원칙과 정책/API 미결 사항 표시 |

## T-SAVE 전이

1. `S-DETAIL`에서 메모를 입력한다. 입력할 때마다 브라우저 로컬 저장소에 초안을 기록한다.
2. `저장`을 한 번 누르면 요청 키 `T-SAVE:R-72:LOCAL-01`의 `S-TIMEOUT`으로 이동한다. 서버 처리 여부는 모른다고 명시한다.
3. 저장 버튼은 `저장 요청 전송됨`으로 비활성화된다. 따라서 같은 키의 중복 입력은 무시되고 새 저장 요청을 만들지 않는다.
4. 첫 `상태 확인`은 `S-PENDING`, 두 번째는 `S-SAVED`로 전이한다. 성공은 영수증 `S-72`가 있을 때만 확정한다.
5. 어느 단계에서든 패널을 닫으면 `S-CLOSED`가 된다. 다시 열거나 페이지를 새로 열어도 메모, 상태, 영수증을 복원한다.
6. 상태를 처음으로 되돌리는 경로는 별도 `저장 시나리오 재설정` 버튼과 확인 대화상자뿐이다.

## 내부 이동과 목록 문맥

- `본문으로 건너뛰기`는 `#article-body`, `출처 구역으로 이동`은 `#source-section`으로만 이동하여 현재 자료와 메모를 바꾸지 않는다.
- 본문의 `원문 자료`와 출처 URL은 원문 URL이며 자료 목록으로 연결하지 않는다.
- `자료 목록으로` 이동하면 검색어 `작은 팀`, 태그 `운영`, 정렬 `최신순`, R-72 위치가 나타난다. R-72를 다시 선택하면 상세의 초안과 저장 결과가 유지된다.
- 좁은 화면에서도 헤더의 자료 검색과 `내 보관함`을 노출한다.

## 모의 경계와 미결 사항

- 네트워크 요청, 저장 처리, 영수증, 내 보관함은 모두 이 브라우저의 로컬 상태로 모의한다. 실제 계정·서버·권한에는 접근하지 않는다.
- 인증 복구 뒤 동일 키로 서버 작업을 재조회하는 API는 미정이다.
- 초대가 만료된 팀 자료를 계속 읽을 수 있는지에 대한 권한 정책은 미정이다.
- 내 메모와 타인의 원문은 서로 다른 소유권 정책 대상이라는 결정만 유지하며 새 정책을 추가하지 않는다.

## Playwright CLI 확인 기록

- 지정 세션 `beta-wireframe-control`에서 실제 키보드 입력으로 메모 `다음 회고에서 절반 크기 원칙을 적용해 보기`를 작성했다.
- 첫 저장 직후 `응답을 받지 못했습니다`, 중복 저장 버튼 비활성화, 요청 키 `T-SAVE:R-72:LOCAL-01`을 관찰했다.
- 첫 상태 확인에서 `저장 처리 중`, 두 번째 상태 확인에서 `저장되었습니다`와 `S-72`를 순서대로 관찰했다.
- 저장 패널을 닫고 페이지를 새로고침한 뒤 `저장 결과 S-72와 메모가 유지됩니다`를 관찰했고, 다시 열어 원래 메모와 영수증을 확인했다.
- 자료 목록 왕복에서 `작은 팀`/`운영`/`최신순`/`R-72`가 보존되고 상세 복귀 뒤 메모와 `S-72`가 유지됐다.
- 출처 이동 뒤 URL 해시는 `#source-section`, 메모와 결과는 그대로였다. 키보드 `Tab`, `Enter`로 본문 건너뛰기를 실행한 뒤 해시는 `#article-body`, 초점은 `article-body`였다.
- 1280×900에서 `innerWidth=1280`, `scrollWidth=1280`; 320×700에서 `innerWidth=320`, `scrollWidth=320`으로 두 폭 모두 가로 넘침이 없었다.
- 320×700에서 자료 검색과 내 보관함 메뉴가 화면에 노출된 상태를 확인했다. 브라우저 콘솔 오류와 경고는 0건이었다.
