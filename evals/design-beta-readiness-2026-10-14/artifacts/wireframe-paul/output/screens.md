# PB-72 자료 상세 저장 와이어프레임 명세

## 입력과 범위

- 입력 결정본: `BRIEF.md` — **공유 자료함, 결정본 PB-72 revision 3**
- 실행 과업: `TASK.md` — D-ITEM의 T-SAVE 로컬 브라우저 와이어프레임
- 대상 자료: `R-72`, **작은 팀에서 실패 후 다시 시도하기**
- 유지 목적지: `D-LIB /library`, `D-ITEM /items/:id`, `D-SAVED /saved`, `D-HELP /help`
- 이번 산출물은 D-ITEM과 문맥 확인용 D-LIB만 렌더링한다. D-SAVED와 D-HELP의 전체 화면, 권한·인증 복구 정책은 새로 결정하지 않는다.

브라우저용 정적 프로토타입 경로는 `app/index.html`이다. 정적 서버 제약 때문에 실제 제품 경로 대신 쿼리 기반 로컬 화면 전환을 사용한다.

## 화면과 상태 ID

| ID | 화면/상태 | 필요한 정보 | 주 동작 | 피드백 |
| --- | --- | --- | --- | --- |
| `D-ITEM.READY` | 자료 상세, 저장 전 | R-72 제목·요약·작성자·태그·본문·원문, 내 메모 | `메모와 함께 저장` | 초안이 이 브라우저에 유지됨 |
| `T-SAVE.PENDING` | 첫 저장 요청 전송 중 | 요청 `SAVE-R72-1`, R-72 | 기다리기, 상태 패널 닫기 | `전송 중`; 저장 버튼 잠금; 닫아도 서버 작업은 취소되지 않음 |
| `T-SAVE.TIMEOUT-UNKNOWN` | 첫 요청 응답 시간 초과 | 같은 요청 ID, 초안 | `상태 확인` | 성공·실패로 단정하지 않음; 새 저장 금지 |
| `T-SAVE.CHECK-1-PENDING` | 첫 상태 확인 | 같은 요청 ID | `다시 상태 확인` | `첫 확인 결과: 아직 처리 중` |
| `T-SAVE.SUCCEEDED` | 두 번째 상태 확인 성공 | 요청 `SAVE-R72-1`, 영수증 `S-72`, 초안 | 상태 패널 닫기 | `저장됨`; 저장 버튼 잠금; 유일 영수증 S-72 |
| `T-SAVE.PANEL-CLOSED` | 상태 패널을 닫은 상세 | 현재 저장 배지, 초안 | `진행 상태 보기` | 요청은 취소·초기화되지 않음 |
| `D-LIB.CONTEXT` | 자료 목록 복귀 | `q=작은 팀`, `tag=운영`, `sort=newest`, 보던 자료 R-72 | R-72 상세 재진입 | 검색 조건과 목록 위치를 명시 |

## 전이 계약

1. `D-ITEM.READY`에서 메모를 입력하면 입력마다 로컬 초안을 갱신한다.
2. 첫 저장은 `T-SAVE.PENDING`을 거쳐 1.2초 뒤 `T-SAVE.TIMEOUT-UNKNOWN`이 된다. 이 시간은 모의 지연이다.
3. 요청이 만들어진 뒤 저장 버튼은 비활성화된다. 같은 화면에서 빠르게 다시 누르거나 돌아온 뒤 눌러도 새 요청은 만들어지지 않는다.
4. 첫 `상태 확인`은 `T-SAVE.CHECK-1-PENDING`, 두 번째 확인은 `T-SAVE.SUCCEEDED`로 이동한다. 두 확인 모두 새 저장이 아니라 `SAVE-R72-1` 조회다.
5. `닫기`는 상태 패널만 닫고 `T-SAVE.PANEL-CLOSED`로 보인다. 진행 중 타이머, 요청, 초안, 확인 횟수와 영수증은 유지된다.
6. `진행 상태 보기`는 닫기 전의 동일 상태를 다시 연다.
7. `시나리오 재설정`만 초안과 모의 저장 결과를 지운다. 로드·새로고침·목록 이동은 초기화하지 않는다.
8. `자료 목록으로`는 `D-LIB.CONTEXT`를 열고 R-72 위치로 복귀한다. R-72 링크 또는 브라우저 앞으로 가기는 동일 상세와 저장 상태를 복원한다.
9. 상세의 `본문으로 건너뛰기`와 `출처 구역으로 이동`은 URL이나 자료 입력을 바꾸지 않고 같은 화면의 대상에 포커스와 스크롤을 옮긴다.

## 정보 위계와 동작

상세의 읽기 순서는 목록 문맥 → 자료 식별 정보 → 본문/출처 내부 이동 → 본문 → T-SAVE → 출처 → 내 보관함 안내 → 미결 정책이다. T-SAVE는 메모, 현재 상태, 주 동작, 중복 방지 안내, 요청 상세, 모의 경계, 시나리오 재설정 순으로 구성했다.

헤더에는 좁은 폭에서도 검색과 내 보관함 링크를 유지했다. 태그와 작성자는 상세 메타데이터 및 목록 필터이며 새 전역 메뉴가 아니다. 원문 링크는 자료 목록이 아닌 원문 URL을 새 탭으로 연다.

## 반응형 순서

- `1280×900`: 본문 폭은 최대 960px이고 목록 문맥, 상태 제목/배지, 필터가 가능한 범위에서 한 줄을 사용한다.
- `320×700`: 헤더·검색·필터·상태 제목·행동을 세로로 바꾸고 버튼은 전체 폭을 쓴다. 콘텐츠 우선순위와 DOM 읽기 순서는 데스크톱과 같다.
- 두 폭 모두 검색, 내 보관함, 목록 복귀, 내부 이동, 메모, 저장 상태 및 재설정에 키보드로 접근할 수 있다.

## 모의 경계

- 네트워크 요청, 서버 처리 상태, 영수증 `S-72`는 `app/app.js`의 로컬 상태 기계가 재현한다.
- 초안과 결과 지속성은 브라우저 `localStorage` 키 `pb72-r72-save-v1`로 재현한다. 실제 제품 저장소가 아니다.
- 실제 계정, 인증, 팀 데이터, 서버 API, 권한 검사, D-SAVED 반영은 호출하지 않는다.
- 원문 URL은 구조 확인용 `example.org` 자리표시자다.

## 관찰된 구현 상태

- 렌더됨: `D-ITEM.READY`, 모든 T-SAVE 상태, `D-LIB.CONTEXT`, 1280×900 및 320×700.
- 동작 확인: 실제 키보드 메모 입력, pending → timeout-unknown → 첫 pending → S-72, 진행 중 닫기/재열기, 중복 방지, 새로고침 지속, 목록 왕복과 브라우저 뒤로/앞으로, 내부 이동, 두 폭의 가로 넘침 및 Tab 순서.
- 사용자 수용: 확인하지 않음. 이 문서는 동작하는 와이어프레임이며 사용자 승인이나 운영 준비 완료를 뜻하지 않는다.

## 미결 결정

- 인증 복구 뒤 동일 키로 작업을 다시 조회하는 서버 API.
- 초대가 만료된 팀 자료의 읽기 권한.
- 보관함의 내 메모와 타인의 원문에 적용할 서로 다른 소유권 정책의 구체 규칙.
