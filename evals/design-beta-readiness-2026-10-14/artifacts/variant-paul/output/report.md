# 자료 카드 밀도 비교안

## 결과

`app/index.html`의 `#target` 자료 카드 한 개를 대상으로, 기존 헤더·검색·카드 컨트롤과 실제 문맥을 유지한 채 밀도 축의 세 비교안을 만들었다. 어느 안도 선택하거나 추천하지 않았으며, URL의 `__variant` 값으로 한 번에 하나씩 전환한다.

- 여유형: <http://127.0.0.1:48914/runs/variant-paul/app/index.html?__variant=airy>
- 균형형: <http://127.0.0.1:48914/runs/variant-paul/app/index.html?__variant=balanced>
- 압축형: <http://127.0.0.1:48914/runs/variant-paul/app/index.html?__variant=compact>

Picker는 클릭, `←`/`→`, 숫자 `1`/`2`/`3`으로 전환하며 `H`로 숨기거나 다시 표시한다. 1280×900에서는 화면 아래 중앙, 카드가 한 화면보다 길어지는 320×450에서는 화면 위 중앙에 둬 카드 컨트롤을 가리지 않게 했다. URL은 전환 즉시 바뀌며 뒤로/앞으로 이동의 기준으로도 쓰인다.

## 비교

| 안 | 밀도 위치 | 적합한 상황 | 비용 |
| --- | --- | --- | --- |
| 여유형 | 가장 낮은 밀도 · 32px 중심 여백, 136px 메모 영역, 큰 버튼 | 한 자료에 머물며 메모를 길게 쓰는 흐름 | 모바일 카드 높이 685px로 스크롤이 가장 길고, 한 화면에 보이는 정보가 적다 |
| 균형형 | 중간 밀도 · 20px 중심 여백, 96px 메모 영역 | 읽기와 저장 작업의 비중이 비슷한 일반적인 자료함 | 여유형만큼 편안하지도, 압축형만큼 많은 정보를 한 번에 보여주지도 않는다 |
| 압축형 | 가장 높은 밀도 · 12–16px 여백, 64px 메모 영역, 데스크톱 2열 정렬 | 자료를 반복해서 훑고 빠르게 저장 상태를 확인하는 흐름 | 컨트롤 사이 호흡이 짧고, 320px에서는 제목과 설명의 줄바꿈 비중이 커진다 |

## 구현 파일

- `app/index.html`: 기존 실제 페이지 안에 카드 비교안과 접근 가능한 picker 마크업 추가
- `app/style.css`: 세 밀도 위치, 반응형 정렬, picker, 좁은 화면의 포커스 안전 여백 추가
- `app/app.js`: URL 전환, 키보드 단축키, history 연동, 문서 스크롤을 유지하는 picker 내부 가로 스크롤 추가
- `output/report.md`: 이 보고서

기존 카드의 제목·설명·메모·버튼 ID와 문구, 저장/비우기/오류/빈 결과 동작은 유지했다. 비교안 전환은 같은 DOM에 `data-variant`만 바꾸므로 입력, disabled 상태, 타이머와 상태 메시지를 재생성하지 않는다.

## Playwright CLI 관찰

- 관찰 시각: 2026-10-14 12:19:27 KST (03:19:27 UTC)
- 도구: `playwright-cli` 0.1.22
- 브라우저: HeadlessChrome 152.0.0.0
- 세션: `beta-variant-paul` 하나만 사용했고 관찰 후 닫았다.
- 뷰포트: 1280×900, 320×450

| 뷰포트 | 안 | 문서 폭 (scroll/client) | 카드 x 범위 · 높이 | picker x/y 범위 |
| --- | --- | --- | --- | --- |
| 1280×900 | 여유형 | 1280 / 1280 | 176–1104 · 473px | x 541–739 · y 841–876 |
| 1280×900 | 균형형 | 1280 / 1280 | 176–1104 · 369px | x 541–739 · y 841–876 |
| 1280×900 | 압축형 | 1280 / 1280 | 176–1104 · 223px | x 541–739 · y 841–876 |
| 320×450 | 여유형 | 320 / 320 | 12–308 · 685px | x 61–259 · y 16–51 |
| 320×450 | 균형형 | 320 / 320 | 12–308 · 476px | x 61–259 · y 16–51 |
| 320×450 | 압축형 | 320 / 320 | 12–308 · 396px | x 61–259 · y 16–51 |

각 6개 조합은 빈 문서에서 새로 탐색해 초기 `scrollY=0`을 확인했다. 실제 `Tab` 입력으로 헤더 링크 2개, 검색, 메모, 카드 버튼 4개, 도움말, picker 버튼 3개 등 기대한 12개 대화형 요소에 모두 도달했다. 각 포커스의 `:focus-visible`과 2px 이상의 outline을 확인했고, 포커스 대상과 고정 picker가 겹치면 검사가 실패하도록 했다. 모든 조합에서 카드와 picker가 뷰포트 가로 범위 안에 있었고 문서 가로 넘침은 없었다.

포인터로 각 안의 메모, 카드 버튼 4개와 현재 picker 버튼을 실제 클릭했다. 320×450에서 스크롤 후에도 클릭이 가능했다. 모바일 picker를 상단으로 옮기기 전 메모 포커스 및 기준 화면과 겹치는 현상을 관찰해 상단 배치와 72px 포커스 안전 여백으로 수정했고, 수정 후 세 안 전체를 다시 관찰했다.

전환 전 문서를 260px 스크롤한 뒤 여유형에서 압축형으로 포인터 전환했을 때 `scrollY`는 260px에서 260px로 유지됐다.

### 상태 보존

| 시작 상태와 전환 | 관찰 결과 |
| --- | --- |
| 메모를 `회고 안건에 다시 올리기`, 검색을 `실패 회고`로 변경한 뒤 여유형 → 균형형 | 두 입력값 유지 |
| `메모 비우기` 실행 뒤 `→`로 균형형 → 압축형 | 메모의 빈 값과 `메모를 비웠습니다` 상태 유지 |
| `저장` 실행 직후 숫자 `1`로 압축형 → 여유형 | `저장 요청 중`, 저장 버튼 disabled, `저장 상태 비교 메모` 유지 |
| 1.1초 뒤 숫자 `2`로 여유형 → 균형형 | `저장 완료 S-72`, 저장 버튼 enabled, 피드백 `저장됨`, 메모 유지 |

추가로 헤더의 `자료함`과 `내 보관함`을 포인터로 눌렀을 때 각각 `#library`, `#saved`로 이동했다. `오류 예시`는 `저장하지 못했습니다. 다시 시도해 주세요.`, `빈 결과 예시`는 `검색 결과가 없습니다. 검색어를 바꿔 주세요.`를 표시했다. 마지막 실행의 콘솔 오류와 페이지 오류는 모두 0건이었다.

## 남은 미검증 범위

- 320×450 검사는 실제 좁은 데스크톱 viewport reflow이며 터치 기기 에뮬레이션이나 실제 손가락 탭은 아니다.
- 설치된 CLI에 브라우저 zoom 명령이 없어 200% 브라우저 확대는 별도로 실행하지 않았다. 요청된 320px 너비에서는 실제 레이아웃과 키보드 경로를 확인했다.
- 실제 스크린 리더 음성 출력은 확인하지 않았다. 브라우저 접근성 역할, accessible name, status live region과 자연스러운 Tab 경로는 Playwright snapshot 및 실행으로 확인했다.
