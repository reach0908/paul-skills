# 역할별 검증 범위

이 표는 역할마다 실행하거나 확인한 대표 가지와 남은 가지를 구분한다. 한 가지의 표본 통과를 전체 참조 파일의 모든 규칙 통과로 확대하지 않는다. 상세 판정은 결과 보고서와 실행 ID를 따른다. 실행을 마친 뒤 각 항목의 실제 관찰과 한계를 판정했다.

| 역할 | 실행 범위 | 검증하지 않은 주요 범위 | 판정 경계 |
| --- | --- | --- | --- |
| `interface-review` | Git 기준 변경 범위, 삭제 신호와 동등 대체, 공유 소비자 제한, 변경 없음, 원인별 분류, 읽기 전용 | 미추적 파일·rename·detached HEAD·remote PR·충돌 등 모든 Git 상태 조합; 실제 스크린리더 | r5와 연결 리뷰에서 원인·범위 확인 완료 |
| `variant` | 한 축의 비교, 실제 페이지 재사용, 선택 상태와 입력 유지, 짧은 화면 초점, 선택안 이관·정리 | 모든 시각 축·프레임워크 조합; 모든 키보드 경로; 실제 터치·보조공학 | 주관적 시각 수용 대기 |
| `state-machine` | 코드에서 상태 도출, 실제 컴포넌트 데이터 경계, 상태 전환·URL·reload, 일회성 정리 | 모든 프레임워크·서버 스트림·복합 동시성 | 대표 상태 계약 검토 완료 |
| `break` | 내용 길이·형태·수량·컨테이너·상태 경계, 실제 컴포넌트, 키보드, 소스 보존·정리 | 모든 문자 체계·고대비·입력 장치·환경 조합 | 대표 스트레스 계약 검토 완료 |
| `explain-interface` | DOM/CSS 계층, 복합 blur 원인, WAAPI·reduced motion, 측정·도출·가설 구분, 이미지 재구성 | 광범위 사이트 시스템 추출; canvas/WebGL; cross-origin CSS 실패; 브라우저 없이 네트워크 HTML 수집 | 로컬 관찰과 이미지 경로 검토 완료 |
| `better-accessibility` | 이름·네이티브 동작·폼 오류·중복 제출·모달·포커스 복원, 새 유효 관찰 검증 | 실제 VoiceOver/NVDA, 자막·미디어·드래그 대안, forced colors; 역할 전체의 확대 조합 | DOM/키보드 관찰은 보조공학 인증이 아님 |
| `better-colors` | 실제 계산 대비, 밝음·어두움, 경계 cascade, 토큰·상태 의미와 읽기 전용 보존 | 전체 OKLCH 팔레트 생성·광색역·gradient 보간·다수 브랜드 | 대표 색상 계약 검토 완료 |
| `better-layout` | 그룹·간격·좁은 폭, LTR/RTL, 실제 200% 확대의 모달 본문·행동 접근 | 모든 layout primitive·다국어 길이·모든 screen geometry | 대표 배치 계약 검토 완료 |
| `better-typography` | 계층·크기·숫자·긴 URL 복원·선택, 모바일 16px, 글자 확대 | 실제 iOS 입력 확대, 모든 variable/OpenType 축·웹폰트 로딩·언어; root font 확대와 native zoom은 별개 | 대표 타이포 계약 검토 완료 |
| `better-writing` | 용어·행동·오류·파괴적 확인·상태·빈 결과, 삭제·권한 상실 뒤 회복 안내 | 모든 로케일의 복수형·날짜·수·기존 번역 파이프라인; 사용자 이해도 | 현재 문구 수정 재시험 검토 완료 |
| `better-ui` | 중단 가능한 motion·reduce·theme·scroll containment, 선택 테두리 geometry와 정상 대조 | 모든 icon crossfade·stagger·enter/exit 라이브러리; 실제 frame/paint 비용·고주사율 장치 | geometry 수정 r3와 회귀 확인 완료 |
| `better-interface` | 6분야 원인별 종합·심각도·중복 통합·관찰 한계·읽기 전용 | 실제 대형 제품의 모든 화면·분야 간 결함 조합 | 현재 UI·문구 의존성 r4 확인 완료 |
| `build-design` | 로컬 이미지·평가용 디자인 데이터, 기존 토큰/동작 보존, 좌표·상태 비교 | 실제 Figma는 사용자 범위 밖; 대형 프레임워크·실제 API·모든 디자인 파일 | Markdown/브라우저 연결 확인 완료; 주관적 시각 수용 대기 |
| `information-architecture` | 기존 PM·명칭·객체·목적지·발견·필터·return, 권한 미결·기존 구조 보존 | 실사용 tree test·대규모 분류체계·운영 권한 구현 | 직접 작성: 원본 동등성 해당 없음 |
| `user-flow` | 성공과 pending 구분, 오류·취소·Retry·입력 보존, 미정 commit 경계·기존 전이 유지 | 서버 동시성·키 전달 복구·poll/push 계약·실제 사용자 성공 | 직접 작성: 원본 동등성 해당 없음; 문서 계약에 한정 |
| `wireframe` | 탐색·폼·오류·retry·receipt·reset, keyboard와 두 폭, Markdown 화면 ID, 내부 링크의 상태 보존 | 브랜드 시안·대규모 탐색·실제 백엔드·사용자 테스트 | 두 반복과 연결 실행, 내부 링크 수정 재시험 확인 완료 |
| `design-browser` | 전체 페이지·anchor 아래위·실제 키 입력·motion·source-only 증거 경계·성능 측정 | Aside 실제 비교; 동일 기기·동일 모델의 비용 효율 비교; 실사용 성능/INP | 두 반복·성능·전환 보완 확인. 짧은 중간 로딩 상태는 Paul 미포착 |

기본 과제는 17개 역할 모두 세 사례·두 조건·두 반복이다. 동일 실행 안의 세 사례는 문맥을 공유한다. 수정 후 실행은 노출 사례와 새 사례를 구별하며, 표본 수가 전체 입력 공간의 통계적 동등성을 뜻하지 않는다. 명시 호출의 결과와 호스트의 자동 발견·자동 선택은 다르며, 자동 발견은 검증하지 않았다.
