# 역할 평가에서 발견한 지침 보정

## 공유 소비자 수 계산

초기 `interface-review` 두 반복의 두 조건 모두 이름 없는 버튼 회귀, 새 버튼의 이름 누락, 공유 색상 토큰의 대비 회귀를 찾았다. 변경이 없는 과제에서는 범위를 임의로 늘리지 않았다. 소스 파일도 보존했다.

Paul 첫 반복은 공유 CSS를 원인 추적용으로 보고 화면 다섯 개를 추가로 검토했다. 나머지 세 실행은 공유 CSS 하나와 화면 네 개를 합쳐 다섯 소비자로 계산했다. 유효한 원본 지적을 잃지는 않았지만, 원본의 전체 다섯 소비자 제한을 일관되게 적용하지 못했다.

`interface-review/SKILL.md`에 중간 CSS나 컴포넌트도 상세 검토한 소비자 수에 포함한다는 한 문장을 추가했다. 출처 커밋과 호출 정책은 그대로 유지하고 로컬 digest와 결정 기록을 갱신했다.

기존 결과를 덮어쓰지 않는다. `prepare_budget_repair.py original|paul`은 노출된 변경 원인·공유 토큰 과제와 새 공유 버튼 초점 회귀 과제를 새 디렉터리에 준비한다. 새 과제의 판정 기준도 실행 전에 별도로 고정한다. 준비와 지침 수정은 개선 효과의 증거가 아니며, 재실행 결과로 판정한다.

## 검사기 과잉 제약

`variant-select-and-clean`의 초기 구조 검사는 `style.css` 전체 해시 보존을 요구했다. 실제 과제는 선택한 ledger 안을 제품 코드로 옮기는 작업이므로 그 안의 스타일 이동이 필요하다. 두 조건 모두 기존 CSS를 보존하고 선택된 두 규칙만 추가했다. 이 항목은 검사기의 과잉 제약으로 판정했다. 원래 검사와 실패 결과는 남겨두고, 실제 변경·토큰 보존·동작 증거를 별도로 검토한다.

## 짧은 화면에서 고정 막대가 초점을 가리는 문제

평가 전용 Chrome 프로필의 실제 페이지 확대 설정을 200%로 바꿨다. 1280×900 창에서 innerWidth 640, innerHeight 450, DPR 2가 반환됐고, CSS zoom과 visualViewport.scale은 1이었다. 이는 CSS 확대 시뮬레이션과 별도의 관찰이다.

첫 반복의 밀도 비교는 확대 상태에서도 입력과 주요 동작에 접근할 수 있었다. 하단 선택 막대는 640×900 창을 200%로 확대한 조건, 즉 논리적 320×450 화면에서 원본과 Paul 모두 검색 입력의 Tab 초점을 가렸다. 좌표와 elementFromPoint, 실제 Tab·클릭, 캡처를 함께 확인했다. 스크롤로 회복 가능한 경우와 초점이 처음 가려진다는 사실을 구분하며, 검색 자체가 영구적으로 불가능하다고 주장하지 않는다.

원본에도 있던 실패를 품질 기준으로 삼지 않는다. `variant`의 실제 페이지 확인 단계에 짧은 화면에서 인접 입력의 Tab 초점과 스크롤 후 포인터 접근을 확인하도록 추가했다. 초기 두 반복은 고정된 이전 지침으로 유지하고, 새 실행에서 노출된 과제와 독립 과제로 수정 효과를 확인한다. 재검증 전에는 이 역할의 전체 합격을 보류한다.

## 색상 평가 기준의 CSS 적용 오류

`better-colors-02`의 입력 경계 기준은 뒤에 선언된 `input` 규칙이 실제로 적용된다고 가정했다. 더 구체적인 `input:not([type=checkbox])`가 이겨 실제 밝은 경계 대비는 수정 전에도 5.546:1이었다. 원본과 Paul 모두 이를 올바르게 구분했다. 잘못 예상한 결함은 감점에서 제외하고, 최종 실제 경계가 기준을 충족하는지는 별도로 측정한다. 동결한 초기 rubric과 실제 관측을 함께 보존한다.

## 데이터 변경 후 빈 결과의 복구 안내

`better-writing` 첫 실행의 필수 문구 수정은 양쪽 모두 수행했다. 추가 상태를 검토하니 원본 결과는 마지막 문서 삭제 후 검색 안내를 숨겼지만, Paul은 문서가 남아 있지 않아도 검색어를 지우면 전체 문서를 볼 수 있다고 안내했다. 독립 브라우저 재현에서 삭제 후 검색과 지우기를 실행해 차이를 확인했다. 실제 삭제가 취소되었다는 뜻은 아니며, 데이터가 사라진 상태에 맞지 않는 복구 안내가 문제다.

`better-writing`의 빈 상태 규칙에 검색 결과 없음과 남은 데이터 또는 접근 가능한 데이터 없음을 구분하고, 데이터·권한 변경 뒤 인접 검색이나 필터의 복구 안내를 다시 확인하도록 추가했다. 지침 수정만으로 해결됐다고 판정하지 않는다. 노출된 삭제 과제와 새 권한 변경 과제를 재실행하며, 해당 규칙을 읽는 종합 리뷰와 변경 리뷰도 새 의존성으로 확인한다. 기본 반복의 고정된 이전 입력과 실패 증거는 보존한다.

## 빈 레이아웃 상자와 실제 콘텐츠 손실 구분

`better-interface-01`의 초기 기준은 460px 행 때문에 320px 화면에서 행동이 잘릴 것으로 예상했다. 실제 두 버튼의 오른쪽 끝은 188.56px 안에 있었고 캡션도 287px 안에 남았다. 넘친 부분은 빈 상자였다. 양쪽 실행 모두 이 차이를 구분했으며, 원시 좌표와 화면을 검토해 예상했던 HIGH 콘텐츠 손실을 평가에서 제외했다. 긴 번역과 확대에서의 안전성이 확인됐다는 뜻은 아니다.

## 외관 전환이 작업 상태를 초기화하는 문제

`variant` 두 번째 실행에서 원본은 선택 해제 후 다른 강조 안으로 바꿔도 0개 선택과 비활성 내보내기를 유지했다. Paul은 보고서에 공통 초기 상태로 돌아간다고 적었고 실제로 8개 선택 상태를 다시 만들었다. 초기화 사실을 숨기지는 않았지만, 시각적 강조만 바꾸는 과제에서 작업 상태도 바꿨다. 독립 브라우저 재현으로 두 조건의 차이를 확인했다. 이는 미리 기대한 지적 목록 밖에서 발견해 추가 검증한 결과다.

`variant`에 외관 전환 시 입력·선택·비활성·피드백 상태를 유지하고, 필요한 초기화는 별도 명시된 조작으로 제공하도록 보완했다. 기존 초점 수정 실행은 이전 입력 그대로 마치며, 현재 지침의 판정에는 노출된 작업 막대와 새 수량 선택 과제를 사용하는 별도 반복을 추가한다. 수정만으로 효과를 확정하지 않는다.

## 수정 후 관찰

초점 수정의 새 두 조건에서 상단 예약 요약과 하단 작업 막대를 실제 200% 확대의 640×450 및 320×450 화면으로 확인했다. 세 안씩 합계 24조건에서 표본 Tab 경로의 제어·라벨 중앙이 가려지지 않았고, 스크롤 후 포인터 입력과 실제 동작도 수행됐다. 원본도 이 실행에서 개선됐으므로 지침만의 인과 효과를 주장하지 않는다.

현재 상태 보존 지침의 별도 반복에서는 선택 해제한 0개 상태와 새 주문 카드의 수량 5권·선물 포장·견적 문구·외부 검색 입력이 모든 안 전환 뒤 유지됐다. 수량 1권·12권의 비활성 경계도 보존됐다. Paul은 위 두 확대 크기의 표본 초점 경로를 통과했다. 원본 일부 경로에서 다시 나타난 가림을 목표 수준으로 삼지는 않는다. 주관적 외관 수용과 실제 보조공학 검증은 별도다.

빈 상태 문구 수정의 새 반복에서 Paul은 문서가 사라진 뒤 검색어를 바꾸거나 지워도 복원 가능성을 안내하지 않았다. 새 권한 상실 과제도 데이터 삭제와 접근 상실을 구분했다. 양쪽 리뷰가 추가로 발견한 이전 성공 메시지의 잔존은 실제로 재현돼 유효한 지적으로 인정했다. 초기 기준이 예상한 깨끗한 화면이라는 이유로 이를 오탐 처리하지 않았다. 공유 문구 규칙을 쓰는 종합·변경 리뷰의 새 반복은 별도로 확인한다.

## 모달 닫힘 직후의 초점 경쟁

접근성 두 번째 반복의 보존 과제는 정상 화면을 의도했지만, `close` 이벤트에서 무조건 트리거로 초점을 돌리는 코드가 있었다. Paul은 모달을 닫은 뒤 폼으로 이동할 때 초점이 뒤늦게 이동하는 현상을 미확정 사항으로 남겼다. 독립 재현에서 두 조건의 같은 예제 모두 Escape 직후 입력과 제출 버튼으로 이동한 초점을 비동기 닫힘 이벤트가 다시 가져갔다. 원본은 이를 보고하지 않았다.

초점 이벤트 순서와 소스 원인을 확인했으므로 새 유효 관찰로 기록한다. 매우 빠른 자동 조작에서 관찰했으며 일반 사용자 속도의 발생 빈도를 증명한 것은 아니다. 연속 반복은 앞선 상태를 공유하므로 독립 표본 수로 세지 않는다. 실행자의 원래 보고서와 읽기 전용 예제는 그대로 보존한다.

## 검사 범위에서 브라우저 도구 기록 분리

앱 폴더에서 실행된 Playwright CLI가 `.playwright-cli/`에 남긴 도구 기록을 초기 검사기가 제품 파일 추가로 세었다. 초기 결과를 보존하고 해당 디렉터리만 별도 `toolArtifacts` 목록으로 분리했다. 다른 추가·변경·삭제 파일과 원래 앱 소스의 해시 검사는 유지한다. 이 조정은 제품 변경을 숨기는 예외가 아니다.

## 선택 테두리 전환의 작은 위치 이동

`better-ui` 두 번째 반복에서 원본은 선택 테두리 1px/2px 전환 때문에 이웃 필터가 2px 움직이는 LOW 지적을 남겼고 Paul은 놓쳤다. 독립 재현에서 두 조건의 같은 화면에 실제 위치·크기 변화가 있었다. 기능 실패로 격상하지 않지만, 유효한 낮은 심각도 지적도 추가 장점으로 상쇄하지 않는다.

선택 테두리의 두께가 변할 때 제어와 이웃의 크기·위치를 비교하고, 공간을 확보하며 의도된 선택 표현은 유지하도록 `better-ui`를 보강했다. 색만 바뀌거나 테두리 공간이 이미 확보된 경우에는 결함으로 삼지 않는다. 노출된 필터와 새 선택 UI를 재시험하고, 현재 UI·문구 규칙을 함께 사용하는 종합·변경 리뷰와 연결 과제는 새 입력으로 준비한다. 실행하지 않은 이전 준비물도 삭제하지 않는다.

수정 후 새 실행에서 Paul과 원본 모두 기존 2px 이동과 독립 선택 과제의 6px 이동을 찾고, 공간을 미리 확보한 확인서 버튼은 지적하지 않았다. 원래 제품 파일은 보존됐다. 별도의 모션 수정 산출물을 독립 재생해 중간 위치 반전, 이동 없는 감소 모션, 내부 스크롤 유지, 즉시 테마 전환을 확인했다. 두 실행자가 이동을 MEDIUM으로 표현했으나 평가자는 기존 2px 사례를 기능 실패가 입증되지 않은 LOW 관찰로 유지한다. 한 번의 새 비교가 모든 입력에서의 누락 방지나 지침 수정만의 인과 효과를 증명하지 않는다.

소비자 제한 보정의 현재 r5 실행에서 양쪽 모두 중간 CSS 1개와 화면 4개로 총 5개를 지켰다. 노출된 색상 토큰 과제와 새 공유 버튼 초점 과제의 유효한 원인을 찾고 미확장 화면 수를 기록했다. 두 조건이 추가로 찾은 강제 색상에서의 shadow 초점 표시 소실도 실제 Tab과 계산 스타일로 독립 확인했다. 일반 색상에서의 유효한 shadow 대체까지 잘못된 제거로 취급하지 않았다. 이 관찰은 Chrome의 강제 색상 에뮬레이션이며 Windows 실기기 검증은 아니다.

현재 공유 규칙을 사용하는 `better-interface` r4에서도 원본의 유효한 원인을 보존했다. 실제 콘텐츠가 보이는 빈 영역 넘침을 높은 심각도의 잘림으로 과장하지 않았고, 정상 과제에 불필요한 제품 수정을 하지 않았다. 지적 개수와 심각도 표현 차이 자체를 우열 점수로 쓰지 않는다.

## 브라우저 전환의 시작 상태 누락

`design-browser`의 두 기본 반복은 anchor 위아래와 최종 지연 콘텐츠를 관찰했지만, Paul이 미로딩 상태부터 전환을 기록하지 못했다. anchor 탐색 자체가 로딩을 유발할 수 있기 때문이다. 해당 결과는 전환 증거 부족으로 보존했다.

안전한 새 로컬 탐색으로 시작 상태와 행동 후 결과를 각각 기록하되 이미 로딩된 화면의 이전 상태를 만들어내지 않도록 보강했다. r4는 기존 과제와 새 스크롤 목록, 처음부터 로딩된 대조 화면을 사용했다. Paul은 기존 과제의 미로딩→표시 전환과 새 과제의 두 폭에서 0개→3개 전환을 기록했고 대조 화면에는 가짜 전환을 주장하지 않았다. 새 목록의 짧은 Loading 중간 상태는 Paul이 표본으로 잡지 못했다. 시작·결과 확인을 연속된 모든 상태 관찰로 확대하지 않는다.

이 변경은 직접 작성한 브라우저 절차에 적용한다. 다른 역할의 기존 결과와 연결 실행은 이전에 고정한 의존성으로 수행됐으며 새 전체 묶음으로 재실행했다고 표기하지 않는다. 동일한 라우팅·도구·출력 계약을 유지한 관찰 절차 수정의 근거는 별도 r4 결과다.

## 연결 과제의 본문 링크가 화면을 이탈하는 문제

IA→흐름→와이어프레임→구현→리뷰의 다섯 단계를 실행했다. 마지막 독립 리뷰는 상세에서 본문 링크를 키보드로 실행하면 해시 라우터가 목록으로 보내는 결함을 찾았다. 와이어프레임에서 생겨 충실한 구현에도 전달된 결함이다. 리뷰의 제한된 Approve 표기는 보존하지만, 평가자는 이 동작을 수정하기 전 연결 산출물의 완료를 인정하지 않는다.

`wireframe`에 화면 간 이동과 화면 안의 초점·스크롤 이동을 구분해 상태 보존을 확인하도록 추가했다. 기존 씨앗 화면 수정과 새 작업대 예약 화면을 별도 문맥에서 비교한다. 이전 다섯 단계의 산출물과 실패 기록은 덮어쓰지 않으며 수정된 로컬 미리보기와 검증은 별도로 남긴다.

재시험에서 양쪽 모두 기존 본문 링크를 수정하고 새 준비 섹션 링크를 올바르게 구현했다. 평가자가 두 크기·두 조건·두 과제의 8개 조합에서 실제 Tab·Shift+Tab·Enter로 입력·검증·pending 보존과 취소를 확인했다. 별도 수정 미리보기에도 같은 링크 수정을 적용하고, 리뷰에서 제안한 문서 제목과 이름 자동완성 목적을 추가했다. 원래 5단계 산출물은 보존했다. 수정 미리보기의 주요 흐름 재생은 이전 검증과 같은 결과였으며 화면 내 이동의 수정도 직접 확인했다. 실제 스크린리더나 저장된 자동완성 UI의 작동을 시험했다는 뜻은 아니다.
