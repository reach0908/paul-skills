# 씨앗 수령 서비스 정보구조 초안

- 상태: **초안, 후속 단계 작성에 사용할 수 있음**. 작성자 문서 점검을 마쳤으며 사용자 승인이나 사용성 검증을 의미하지 않는다.
- 기준 소스: [`brief.md`](../brief.md), 리비전 **SEED-PM-8**.
- 단계 요청: [`stages/01-ia.md`](../stages/01-ia.md).
- 적용 스킬: [information-architecture](../.agents/skills/information-architecture/SKILL.md).
- 작성일: 2026-10-12.

## 범위와 고정 결정

동네 정원 이용자가 적합한 씨앗 한 봉지를 찾고, 토요일 수령 정보를 확인하고, 예약 확정 후 자신의 수령 내역을 다시 찾는 범위다. 기존 `/seeds`, `/seeds/{seedId}`, `/my-pickups`와 전역 라벨 `Seeds`, `My pickups`를 유지한다. 이 문서는 콘텐츠의 소속과 탐색 관계만 결정한다. 예약의 상태 전이, 입력 검증, 화면 배치는 후속 단계가 다룬다.

초기 계절 필터는 `season=autumn`, 초기 수령 내역은 빈 목록이다. 씨앗의 고유 ID는 진입 경로와 관계없이 유지한다. 로그인이나 역할별 권한은 없으며, `My pickups`의 “내”는 이번 데모 실행에서 확정한 내역을 가리킨다. 계정 소유권이나 서버 저장을 뜻하지 않는다. 새로고침하면 처음 상태로 돌아오며 실제 재고 확보, 메시지 발송, 결제는 없다.

## 목적지

목적지 ID는 후속 흐름과 와이어프레임에서 그대로 참조한다. 특정 씨앗은 하나의 상세 목적지 유형 안에서 `seedId`로 구분한다.

| 목적지 ID | 표시 라벨 | 기존 경로 | 콘텐츠와 지원 과업 | 접근 조건 |
|---|---|---|---|---|
| D-SEEDS | Seeds | `/seeds` | 씨앗 목록, 씨앗을 구분할 이름, 계절 필터. 적합한 씨앗을 좁히고 상세를 찾는다. | 로그인 없이 접근. 필터는 목록 노출만 제한한다. |
| D-SEED-DETAIL | 해당 씨앗 이름 | `/seeds/{seedId}` | 해당 씨앗의 ID, 이름, 설명, 계절과 공통 수령 시간·장소. 선택한 씨앗과 수령 조건을 확인한다. | 알려진 씨앗 ID로 직접 접근 가능. 목록 필터와 무관하게 같은 상세를 사용한다. |
| D-MY-PICKUPS | My pickups | `/my-pickups` | 초기 빈 목록 또는 확정된 수령 내역 한 건. 참조번호, 신청 이름, 씨앗, 토요일 시간·장소를 다시 찾는다. | 항상 접근 가능. 예약 확정 전에도 빈 목적지로 존재한다. |

상세 인스턴스는 `D-SEED-DETAIL:BEAN-2`와 `D-SEED-DETAIL:SUN-5`로 식별한다. 씨앗 카테고리 페이지, 필터별 상세 사본, 별도 수령 내역 상세 경로는 추가하지 않는다.

## 콘텐츠와 분류의 소속

| 콘텐츠 | 정체성 및 속성 | 소속·관계 |
|---|---|---|
| 씨앗 BEAN-2 | 이름 `가을 강낭콩`, 계절 `autumn`, 설명 `작은 화분에서도 기를 수 있는 키 작은 강낭콩 품종입니다.` | D-SEEDS에서 발견하고 `/seeds/BEAN-2`에서 온전한 정보를 확인한다. 확정 내역은 이 씨앗 ID를 참조한다. |
| 씨앗 SUN-5 | 이름 `해바라기`, 계절 `summer`, 설명 `햇볕이 잘 드는 넓은 자리에서 자랍니다.` | D-SEEDS에서 발견하고 `/seeds/SUN-5`에서 온전한 정보를 확인한다. 확정 내역은 이 씨앗 ID를 참조한다. |
| 계절 분류 | 현재 인벤토리의 값 `autumn`, `summer` | D-SEEDS의 필터 속성이다. 독립 목적지나 권한 구분이 아니다. 필터의 기본값은 `autumn`이다. |
| 공통 수령 안내 | Saturday 10:00 to 12:00, North community garden desk | D-SEED-DETAIL과 D-MY-PICKUPS의 확정 내역에서 확인한다. 특정 씨앗만의 정보가 아니다. |
| 예약 작성 중 정보 | 선택한 씨앗 한 봉지와 신청 이름 | 선택한 씨앗에 연결되는 작업 정보다. 저장된 수령 내역으로 분류하지 않는다. 입력 위치와 상태별 노출은 후속 흐름·화면 문서에서 결정한다. |
| 확정된 수령 기록 | 참조번호 `SP-21`, 신청 이름, 선택한 씨앗, 공통 수령 시간·장소 | D-MY-PICKUPS에 속한다. 확정 결과에서도 같은 기록을 안내한다. 확정 결과의 표현 방식은 후속 단계가 결정한다. |
| 빈 수령 내역 안내 | 확정 기록이 없다는 정보 | D-MY-PICKUPS에 속한다. 접근 오류나 숨김 상태로 취급하지 않는다. |
| 데모 초기화 | 기존 라벨 `Reset demo` | 탐색 목적지가 아닌 데모 제어다. 초기 계절과 빈 수령 내역으로 되돌리는 범위를 유지하며 배치와 동작은 후속 단계가 다룬다. |

브리프에 날짜나 한국어 장소명이 없으므로 임의 날짜나 번역된 장소명을 확정하지 않는다. 토요일 10:00~12:00라는 시간 의미와 원문 장소 `North community garden desk`를 보존한다.

예약 검증·대기·실패·재시도 피드백은 작업 상태에 속한다. 별도 정보 목적지를 만들 이유로 삼지 않는다. 계정, 이메일, 결제, 재고 관리, 서버 저장 관련 콘텐츠는 명시적 범위 밖이다.

## 탐색과 복귀 관계

| 진입·출발 | 찾는 대상 | 탐색 관계와 보존할 맥락 |
|---|---|---|
| 어느 목적지에서든 | 씨앗 목록 | 전역 `Seeds`를 통해 D-SEEDS에 도달한다. |
| 어느 목적지에서든 | 자신의 수령 내역 | 전역 `My pickups`를 통해 D-MY-PICKUPS에 도달한다. 빈 목록이어도 경로를 유지한다. |
| D-SEEDS | 조건에 맞는 씨앗 | 계절 필터로 목록을 좁힌 뒤 해당 씨앗의 정규 D-SEED-DETAIL로 이동한다. |
| D-SEED-DETAIL | 선택 이전 씨앗 목록 | `Seeds`로 돌아갈 때 진입 전 계절 필터를 유지한다. `autumn`에서 BEAN-2를 열었다면 복귀 후에도 `autumn`이다. `summer`에도 같은 원칙을 적용한다. |
| 씨앗 상세 URL 직접 진입 | 동일 씨앗의 정보 | `/seeds/BEAN-2` 또는 `/seeds/SUN-5`는 목록과 같은 객체를 가리킨다. 직접 진입 때문에 씨앗 ID를 바꾸거나 복제하지 않는다. |
| 확정 결과를 확인한 이용자 | 수령 기록 다시 찾기 | 전역 `My pickups`로 D-MY-PICKUPS의 `SP-21`을 찾는다. 확정 결과에서도 이 목적지로 가는 맥락 연결을 후속 단계에 전달한다. |
| 빈 D-MY-PICKUPS | 씨앗 찾기 시작 | 전역 `Seeds`로 D-SEEDS에 도달한다. 별도 진입 페이지는 필요하지 않다. |

`summer` 씨앗은 초기 `autumn` 목록에서 필터로 가려진다. 접근이 금지된 것이 아니며, 계절을 바꾸거나 그 씨앗의 상세 경로로 직접 들어가면 찾을 수 있다. 검색 기능은 이번 브리프가 요구하지 않으므로 추가하지 않는다. 후속 작업에서 검색 진입이 생겨도 씨앗 상세의 정규 ID와 경로는 동일해야 한다.

좁은 너비에서도 `Seeds`와 `My pickups` 두 전역 목적지를 모두 찾을 수 있어야 한다. 씨앗 정체성, 공통 수령 안내, 확정 기록의 핵심 속성이 우선 정보다. 내비게이션 컴포넌트, 메뉴 형태, 구체적인 배치와 읽기 순서는 와이어프레임 단계가 결정한다.

## 작성자 검색 과업 점검

아래는 문서의 관계를 따라간 작성자 walkthrough이며 실제 사용자를 대상으로 한 조사나 브라우저 테스트가 아니다.

| 과업 | 문서상 경로 | 관찰과 한계 |
|---|---|---|
| 가을에 맞는 씨앗 찾기 | D-SEEDS, 초기 `autumn` → `가을 강낭콩` → D-SEED-DETAIL:BEAN-2 → Seeds | 이름·설명과 수령 안내의 소속을 찾을 수 있다. 복귀의 필터 유지 계약은 명시했으며 동작 검증은 아직 없다. |
| 초기 목록에 없는 해바라기 찾기 | D-SEEDS, `summer`로 좁힘 → `해바라기` → D-SEED-DETAIL:SUN-5 → Seeds | 숨겨진 이유는 필터다. 상세 정체성과 `summer` 복귀 맥락이 유지되어야 한다. 필터 컨트롤은 아직 정하지 않았다. |
| 직접 들어온 씨앗의 수령 조건 확인 | `/seeds/BEAN-2` → 같은 상세의 수령 안내 → Seeds | 상세가 목록 진입에 의존하지 않도록 정의했다. 이전 목록 방문이 없는 경우에는 초기 계절 `autumn`을 쓰는 가정을 아래에 명시했다. |
| 확정 후 자신의 수령 내역 다시 찾기 | 어떤 목적지에서든 My pickups → D-MY-PICKUPS → `SP-21` | 참조번호·이름·씨앗·시간·장소의 소속이 완전하다. 기록 생성은 확정에만 종속되며 상태 전이는 후속 범위다. |
| 확정 전에 수령 내역 찾기 | My pickups → 빈 D-MY-PICKUPS → Seeds | 빈 목록에서도 목적지와 다음 탐색 경로가 존재한다. 실패·취소를 확정 기록으로 간주하지 않는다. |

## 요구사항 추적과 후속 인계

| 요구사항 | 이 문서의 구조 결정 | 후속 확인 |
|---|---|---|
| I1 | 두 씨앗 ID·이름·설명을 그대로 보존하고, 씨앗 객체와 목록·상세·계절 필터를 분리했다. 선택은 한 봉지다. | 흐름·구현에서 선택 씨앗이 확정 내역까지 동일한지 확인한다. |
| I2 | D-SEEDS 복귀에 계절 맥락을 유지하고, 너비와 무관하게 두 전역 목적지를 유지한다. | 흐름에서 복귀 규칙, 화면과 구현에서 좁은 너비의 실제 접근을 확인한다. |
| I3 | 작성 중 정보와 상태 피드백을 확정 기록과 구분한다. | 이름 검증, 400ms 대기, 중복 제출 무시, 첫 실패, Retry와 Back은 흐름 단계가 브리프에서 직접 이어받는다. |
| I4 | 확정에만 SP-21을 연결한다. 수령 기록의 다섯 정보군과 초기 빈 목록의 소속을 명시했다. | 성공 전 Back·취소가 기록을 생성하지 않는지 흐름·구현에서 확인한다. |
| I5 | 권한 모델이나 실서비스 저장을 만들지 않고, 이번 데모의 내역으로 범위를 한정한다. | Reset demo, 새로고침 초기화, localStorage 미사용과 실제 외부 효과 없음은 구현에서 확인한다. |
| I6 | 좁은 너비의 두 목적지 접근과 핵심 콘텐츠 우선순위를 인계한다. | 1280×900 및 390×844의 화면 계층, 레이블, 키보드 포커스, 읽기 순서는 후속 화면·검증 범위다. |

기존 구조 변경안은 없다. 세 목적지로 모든 범위 내 콘텐츠와 검색 과업을 연결할 수 있다. 전역 라벨의 의미도 브리프에서 고정되어 있어 경쟁하는 명칭을 추가하지 않는다.

가정은 하나다. 목록 진입 이력이 없는 직접 상세 진입에서 `Seeds`로 돌아오면 초기값 `autumn`을 사용한다. 기존 목록 맥락이 있다면 그 계절을 유지하는 I2가 우선이다. 새로운 상품 정책이나 접근 권한 결정을 요구하는 가정은 아니다.

현재 구조를 막는 미해결 결정은 없다. 잘못된 씨앗 ID의 오류 경로, 전체 계절 옵션, 여러 수령 기록, 날짜 변경, 계정 소유권은 브리프에 없어 확장하지 않았다. 후속 단계는 이 문서의 목적지 ID를 사용하되, 예약 동작과 화면 결정의 원천으로 SEED-PM-8을 함께 읽어야 한다.
