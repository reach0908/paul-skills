## 과업, 확정된 사실과 설계 가정

행위자는 동네 정원 이용자다. 초기 `D-SEEDS`의 `season=autumn`에서 씨앗 한 봉지를 찾아 이름을 입력하고 모의 실패를 복구한다. 관찰 가능한 완료는 확정 결과와 `D-MY-PICKUPS` 양쪽에서 같은 `SP-21` 한 건을 다시 찾는 것이다. 예약을 누른 사실이나 대기 상태는 완료가 아니다.

브리프의 고정 정책은 이름 필수, 제출 뒤 400ms 대기, 대기 중 중복 제출 무시, 첫 모의 실패, Retry를 통한 확정, 성공 전에 기록을 만들지 않음, 초기화와 새로고침 시 빈 내역 복원이다. 실패·재시도·확정은 모두 로컬 시뮬레이션이라고 알린다. 실제 계정, 발송, 저장, 재고 약속과 localStorage는 없다.

다음은 미정 세부사항을 연결하기 위한 **설계 가정**이며 별도의 사용자 승인 사실이 아니다.

1. 이름의 앞뒤 공백을 제거한 값이 비어 있으면 유효하지 않다. 입력 중에는 원문을 보존하고, 확정 내역에는 앞뒤 공백만 제거한 값을 쓴다. 다른 이름 제한은 추가하지 않는다.
2. 첫 실패는 Reset demo 또는 새로고침 사이의 데모 실행 단위로 발생한다. 실제로 첫 실패가 표시되기 전 중단한 제출은 실패를 소비하지 않는다. 실패 후 Back으로 수정하고 다시 Submit해도 재시도로 취급한다.
3. Retry도 400ms 대기를 거쳐 확정한다. Back은 실패·검증 오류·대기 상태에서는 같은 씨앗의 입력 상태로 돌아가고, 입력 상태에서는 Seeds로 돌아간다. 전역 Seeds는 어느 상태에서나 목록으로 바로 간다.
4. 대기 중 Back 또는 다른 목적지 이동은 해당 시도를 취소하고 응답을 무효화한다. 취소 뒤 늦게 도착한 타이머 결과는 기록을 만들지 않는다. 입력한 이름, 씨앗과 필터는 유지한다.
5. 이 과업은 데모 실행당 한 건이다. 확정 후 씨앗 상세를 다시 찾아도 추가 제출은 제공하지 않고 기존 수령 내역으로 연결한다. 새 예약 시연은 Reset demo로 시작한다.

IA의 가정도 유지한다. 이전 목록 맥락이 없는 직접 상세 진입은 `autumn`을 복귀 필터로 쓴다. 기존 맥락이 있으면 해당 값을 유지한다. 이 흐름은 아래 가정으로 초안 작성 가능하며 실제 제품 정책 승인과 구분한다.

## 상태와 목적지

상태 변화 때문에 경로를 추가하지 않는다. 상세 상태의 `seedId`는 URL의 정규 ID이며 `BEAN-2`와 `SUN-5`를 진입 방식에 따라 바꾸지 않는다.

| 상태 ID | 목적지 / 경로 | 인식할 정보와 가능한 주요 행동 |
|---|---|---|
| `S-SEEDS` | `D-SEEDS`, `/seeds` | 현재 계절과 해당 씨앗 목록. 계절 변경, 상세 열기. |
| `S-EDIT` | `D-SEED-DETAIL`, `/seeds/{seedId}` | 선택 씨앗 한 봉지, 설명, 토요일 10:00~12:00, `North community garden desk`, 이름 입력. Submit, Back. |
| `S-INVALID` | 같은 상세 | 이름 필수 오류와 보존한 입력. 이름 수정, Submit, Back. |
| `S-PENDING-FIRST` | 같은 상세 | 모의 제출 처리 중이며 아직 미확정임을 알림. 반복 Submit 무시, Back 가능. |
| `S-FAILED` | 같은 상세 | 첫 모의 실패와 예약 미확정 안내. 보존한 이름·씨앗, Retry와 Back. |

모든 상태에서 전역 `Seeds`, `My pickups`, `Reset demo`에 도달할 수 있어야 한다. 좁은 너비에서도 두 목적지의 접근을 유지한다. 정보와 행동의 실제 배치는 후속 단계에서 정한다.

초안과 확정 내역은 현재 문서 실행의 메모리에만 존재한다. 탭 간 공유, 서버 전송, 브라우저 저장소, 계정별 내역은 없다. `SP-21`은 데모 참조번호이며 실제 재고 약속이 아니다. 실패, 취소 또는 Back 때문에 이미 있던 확정 기록을 임의로 취소하지 않는다.

기록의 씨앗 정체성은 `BEAN-2: 가을 강낭콩` 또는 `SUN-5: 해바라기`다. 설명은 IA와 브리프의 원문을 상세에서 그대로 사용한다. 확정 결과와 My pickups 모두 토요일 10:00~12:00 및 `North community garden desk`를 보여 준다. 날짜나 별도 장소명을 추정하지 않는다.

## 요구사항 추적과 다음 단계 인계

| 요구사항 | 흐름 근거 | 후속에서 확인할 것 |
|---|---|---|
| I2 | T02/T03/T14/T15, W07/W08, 전역 목적지 공통 규칙 | 390×844에서도 Seeds와 My pickups 접근, 필터 유지 |
| I3 | T04~T13, T17, W01~W06 | 이름 레이블·오류 연결, 400ms 실제 타이머, 중복 제출 무시, Retry와 Back, 초안 보존 |
| I4 | T12/T16/T18/T19, W02/W04/W06/W09 | 성공에서만 단일 SP-21 생성, 결과와 My pickups의 다섯 정보군 일치 |
| I5 | T20/T21, 데이터 보존 표, W10/W11 | 시뮬레이션 표시, Reset demo, 새로고침 초기화, 외부 효과와 localStorage 없음 |

화면 단계는 각 상태의 정보와 행동을 표시하되 새로운 경로를 만들 필요가 없다. 1280×900과 390×844에서 씨앗 정체성, 수령 조건, 현재 피드백, 다음 행동의 읽기 순서와 도달 가능성을 정한다. 이름 필드에는 레이블을, 오류에는 수정 연결을, 대기·실패·성공에는 인식 가능한 상태 안내를 제공하고 키보드 포커스를 확인해야 한다. 이 단계에서는 픽셀 배치나 컴포넌트를 결정하지 않았다.

알 수 없는 씨앗 ID, 실제 통신 오류, 여러 예약, 재고 소진, 날짜 변경은 브리프 밖이므로 상태를 추가하지 않았다. 현재 미해결 차단 항목은 없지만 위 다섯 설계 가정은 후속 인계 시 유지하거나 명시적으로 변경해야 한다. 실제 제품 정책, 브라우저 동작, 접근성, 사용자 수용 여부와 승인된 디자인과의 일치도는 아직 검증하지 않았다.
