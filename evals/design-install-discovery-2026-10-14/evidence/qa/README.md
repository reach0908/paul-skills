# 저장한 자료 브라우저 검증

## 결론

전체 요구사항은 통과하지 못했다.

- 저장 자료는 DOM과 접근성 스냅샷에서 정확히 3개 확인됐다.
- `첫 기능 정하기`, `변경 이력 남기기`는 1440px, 390px, 320px 모두에서 실제 키보드 조작으로 찾고, 상세를 열고, 닫을 수 있었다. 상세를 닫은 뒤 포커스도 원래 열기 버튼으로 돌아왔다.
- `완성한 화면 확인하기`는 세 폭 모두에서 실제 `Tab` 6회를 눌러도 포커스되지 않았다. 따라서 이 자료의 상세 열기/닫기는 키보드로 검증할 수 없었고 요구사항 실패다.
- 가로 오버플로는 1440px와 390px에서 없었다. 320px에서는 문서 `clientWidth=320px`, `scrollWidth=370px`로 50px의 가로 오버플로가 발생했다.

자동 검사 매트릭스는 기대한 12개 셀을 모두 완료했고, 8개 통과/4개 실패였다. 실패 4개는 세 폭의 세 번째 자료 키보드 사례 3개와 320px 오버플로 사례 1개다.

## 확인 범위와 환경

- URL: `http://127.0.0.1:48827/`
- 관찰 시각: `2026-10-14T00:33:49.820Z` (`2026-10-14 09:33:49.820 KST`)
- 도구: Playwright CLI `0.1.22`
- 브라우저: headless Chrome `152.0.7977.82`
- 세션: 사용자가 준비한 `saved-materials-prestarted`
- 뷰포트: `1440x900`, `390x900`, `320x900`
- 에뮬레이션: `resize`로 좁은 데스크톱 뷰포트만 구성했다. 터치 디바이스나 브라우저 줌은 에뮬레이션하지 않았다.
- 기대 자료 수: DOM과 무관하게 검사 코드에 3개를 고정하고, 각 사례 시작 시 정확히 3개인지 단언했다.
- 각 자료/폭 키보드 사례는 해시와 이전 포커스가 없는 새 탐색으로 시작했다. 실제 `Tab`, `Shift+Tab`, `Enter`를 사용했고, 포커스 표시, 상세 내용, 닫기 버튼 도달, 닫힘, 열기 버튼으로의 포커스 복귀를 확인했다.
- 가로 오버플로는 새 탐색 뒤 문서 `scrollWidth/clientWidth`, 자료 목록 경계, 카드 경계, 뷰포트를 벗어난 모든 보이는 하위 요소를 0px 허용 오차로 검사했다.
- 성공적으로 연 상세(첫 번째/두 번째 자료)의 문서 폭도 원시 결과에 기록했다. 세 번째 자료의 상세 상태는 키보드로 도달할 수 없어 확인하지 못했다.
- 마지막 페이지의 콘솔은 오류와 경고가 각각 0개였다.

## 확인된 문제

### 1. 세 번째 자료를 키보드로 찾거나 열 수 없음

세 폭 모두에서 포커스 경로가 첫 번째와 두 번째 열기 버튼만 순환했고, `완성한 화면 확인하기 열기`에는 도달하지 않았다. 검사기는 빈 목록이나 짧아진 목록이 통과하지 않도록 먼저 자료 수가 정확히 3개인지 확인한 뒤 최대 6회의 실제 `Tab`으로 제한 검색했고, 세 사례 모두 실패를 반환했다.

영향: 키보드 사용자는 저장된 자료 3개 중 하나의 상세를 열 수 없으므로 “3개 모두 찾고 상세 열기/닫기” 요구사항을 충족하지 못한다.

소스에서 세 번째 버튼에만 `tabindex="-1"`이 지정돼 있어 관찰된 탭 순서 제외의 원인으로 판단된다. 이는 런타임 관찰과 소스 확인을 결합한 추론이며 파일은 수정하지 않았다.

### 2. 320px에서 50px 가로 오버플로

320px에서 자료 목록과 각 카드의 경계는 `left=20px`, `right=370px`, `width=350px`였다. 문서 폭은 `clientWidth=320px`, `scrollWidth=370px`여서 오른쪽 50px가 뷰포트 밖으로 나간다. 뷰포트 캡처에서는 카드의 오른쪽 테두리와 여백이 잘린다.

영향: 320px 폭에서 사용자가 가로 스크롤을 해야 전체 카드 폭을 볼 수 있다.

소스의 `.cards { min-width: 350px }`와 `main`의 좌우 20px 패딩 조합이 측정값과 일치하므로 원인으로 판단된다. 이는 런타임 관찰과 소스 확인을 결합한 추론이며 파일은 수정하지 않았다.

## 재현

`saved-materials-prestarted` 세션을 `about:blank`에서 준비한 상태로 저장소 루트에서 실행한다.

```sh
playwright-cli -s=saved-materials-prestarted run-code --filename evidence/check-saved-materials.js
```

현재 구현에서는 실패 단언을 전파하므로 종료 코드는 `1`이고, 출력 시작은 `QA_ASSERTION_FAILURE`다. 검사는 실패 사례를 만난 뒤에도 전체 12개 셀을 완료하고 결과를 함께 반환한다.
