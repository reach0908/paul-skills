## 새 문맥의 관찰

일반 화면 검토 요청에는 스킬 이름이나 설치 경로를 넣지 않았다. 모델이 `better-interface`를 선택하고 6개 도메인 지침을 실제 설치 캐시에서 읽었다. 직접 호출 사례에는 `$paul-skills:interface-review working`만 추가했다. 관련 없는 산술 요청은 도구나 디자인 스킬을 사용하지 않고 `102`만 반환했다.

이름 없는 미커밋 변경 검토는 두 개의 독립 문맥에서 모두 호출 경계를 위반했다. 모델은 `better-interface`를 읽은 뒤, 자동 목록에 없는 `interface-review`를 미제공 또는 미설치로 해석하고 자체 diff 검토로 대체했다. 그 스킬은 실제로 설치되어 있었고 명시 호출도 성공했다. 호스트가 직접 호출 전용 스킬을 숨기는 기능과 모델의 후속 판단을 구별해야 한다.

`better-interface`의 2단계는 변경 검토 요청을 사용자에게 `interface-review`로 명시 호출하도록 안내하고, 스스로 변경 범위를 해석하지 않도록 규정한다. 두 실행 모두 실제 `git diff` 범위를 정하고 변경 판정을 내렸다. 발견한 키보드 회귀가 옳았다는 사실이 호출 계약 준수를 뜻하지는 않는다.

## 실행 환경과 실패 기록

Codex CLI 0.146.0을 사용했다. 데스크톱 설정에서 가져온 `gpt-6.1-sol`은 독립 CLI 요청에서 지원되지 않는 모델로 거부되었다. CLI의 `model/list`가 기본값으로 반환한 `gpt-5.6-sol`로 실행하고 `xhigh` 설정은 유지했다. 이 결과로 모델 우열을 판단하지 않는다.

처음 실행은 네트워크 제한으로 실패했다. 허용된 네트워크 실행으로 전환한 뒤 모델 호환성 거부를 확인했다. 두 종류의 실패 기록을 별도로 보존했다. 자동 승인 심사 거부는 없었다.

새 CLI 세션 내부에서 Chrome과 다른 설치된 브라우저를 직접 시작하는 경로는 샌드박스의 `SIGABRT`/`EPERM`으로 실패했다. 반복된 시작 실패 시도는 중단했다. 두 번째 새 브라우저 문맥에는 테스트 전용 `about:blank` 세션만 준비했고, 탐색 결과나 검사 코드는 넘기지 않았다. 따라서 이 재시험은 스킬 선택과 실제 검사 작성의 증거이며, 제한된 CLI 환경에서 브라우저를 처음부터 시작하는 경로의 통과 증거는 아니다.

## 정리와 남은 한계

시험용 인증 연결 두 개를 제거했고, 테스트용 48827 서버를 종료했다. 기존 4388 프로토타입은 건드리지 않았다. 전역 Paul 플러그인은 두 호스트 모두 0.2.0의 27개이며, 시험 플러그인·마켓플레이스가 전역 설정에 추가되지 않았다. [최종 확인](evidence/final-global-state.json).

실행 도중 전역 Codex 설정의 전체 해시는 일치와 불일치가 관찰됐다. 최종 확인 시 전역 모델은 시작 시점의 `gpt-6.1-sol`에서 `gpt-6-astra`로 바뀌어 있었다. 시험 스크립트는 임시 설정 파일에만 `gpt-5.6-sol`을 기록했다. 전역 모델 변경의 발생 주체는 조사하지 않았고, 무관한 설정을 되돌리지 않았다. 따라서 전체 전역 설정의 바이트 불변을 주장하지 않고 실제 Paul 설치 범위를 별도로 확인했다.

독립 CLI의 실제 모델은 `gpt-5.6-sol`이다. 데스크톱의 `gpt-6.1-sol` 새 채팅, Claude Code 모델 실행, 공개 마켓플레이스 배포 이후 설치는 미검증이다. 단일 일반 요청 두 패키지와 변경 경계 두 반복은 관찰한 사례의 증거이며 전체 자동 선택 정확도를 추정하는 통계 실험은 아니다.
