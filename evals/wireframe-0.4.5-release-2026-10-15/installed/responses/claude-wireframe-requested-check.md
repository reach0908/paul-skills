# S06 / gallery / r1 화면 명세와 첫인상 검토

검토 대상은 `index.html` r1(route `index.html`, state `gallery`)과 1040×800 캡처 `screen.png`입니다. 파일은 수정하지 않았고 브라우저와 참가자는 쓰지 않았습니다. 그래서 아래 내용은 소스와 스크린샷만 보고 판단한 결과입니다.

## 1. 화면 명세

| 항목 | 내용 |
|---|---|
| 목적 | 작품과 탐색 진입점을 알리는 갤러리 (BRIEF) |
| 처음 전할 메시지 | "ORBIT 작은 전시 014, 「불완전한 종이의 풍경」이라는 종이 콜라주 작품집" |
| 다음 행동 | 해당 없음. 갤러리라 전환 CTA는 두지 않습니다 (BRIEF). |
| 유지할 정보 | 전시명, 제목, 부제, 작품 미리보기 |
| 유지할 컨트롤 | `작품 목록`(#works), `작가 소개`(#artist) |

| 지킬 디자인 방향 | 종이 콜라주, 비대칭, 세리프(Georgia), 노랑/벽돌색 |
| 반응형 (소스 기준) | 600px 이하에서 `main`의 padding이 20px로 줄어듭니다. 다만 h1에 inline으로 `64px`가 들어가 있어 미디어 쿼리의 `30px`보다 우선합니다. 그래서 좁은 화면에서도 64px가 유지될 것으로 보입니다. 미리보기 블록은 180px 고정이고 `flex-wrap`으로 줄바꿈됩니다. 둘 다 실제 측정은 하지 않았습니다. |
| 목업 범위 | 이번 state만 구현되어 있습니다 (BRIEF). `#works`, `#artist` 대상은 소스에 없지만 다음 작업으로 남은 범위로 보고, 클릭 실패로 판단하지 않았습니다. |

## 2. 첫인상 3초 검토

| 방법 | 상태 |
|---|---|
| 작성자/AI 사전 점검 (시간 측정 없음, 의도를 알고 본 상태) | 실행 |
| 새 맥락의 AI 관찰 | `not_run` |
| 사람 대상 3초 관찰 | `not_run` |

**사전 점검으로 본 위계 (예측):**
- 노란 히어로와 큰 세리프 제목이 가장 먼저 눈에 들어옵니다. 의도한 메시지와 맞습니다.
- 그다음은 테두리가 굵은 미리보기 패널이고, 탐색 링크(y≈670)는 마지막입니다. 1040×800 캡처에서는 첫 화면 안에 보입니다.
- 오른쪽 여백과 비대칭은 승인된 디자인 방향이라 보완할 대상이 아닙니다.

**판정:** 3초 테스트를 "통과"했다고 할 수 없습니다. 사람 관찰을 하지 않았기 때문입니다.

## 3. 제안하는 개선 (승인된 디자인 방향 안에서)

1. **미리보기 블록에 작품 정보 연결 (MEDIUM, 의도 확인 필요).** 지금 세 블록은 빈 색 `div`입니다. 작품 제목이나 대체 텍스트가 없어서 스크린리더로는 "작품"이라는 정보가 전혀 전달되지 않습니다. 실제 작품 이미지가 들어갈 자리인지 정해 주세요. 맞다면 각 블록에 작품명 또는 `alt`를 넣고, `작품 목록`의 해당 항목으로 연결하는 것을 제안합니다.
2. **좁은 화면에서 h1 크기 확인.** inline `font-size:64px` 때문에 600px 이하에서도 제목이 줄어들지 않을 것으로 보입니다. 320px 폭에서 잘림이 생기는지 측정이 먼저 필요합니다. 잘림이 확인되면 inline 값을 클래스로 옮겨 미디어 쿼리가 적용되게 하면 됩니다.
3. **탐색 링크 강조는 지금은 바꾸지 않습니다.** 링크가 눈에 잘 띄지 않을 수 있다는 우려는 근거 없는 예측입니다. 관찰로 문제가 확인될 때만 손대고, CTA 버튼으로 바꾸지는 않습니다.

## 4. 확인 한계

- 키보드 이동, 포커스 표시, 링크 동작, 320px 폭, 200% 확대, RTL은 모두 확인하지 못했습니다(`Not verified`).
- 반응형 수치는 소스에서 계산한 값이고 실제 렌더링에서 확인한 값이 아닙니다.
- 사용자 수용 여부는 확인하지 않았습니다. 지금까지 확인된 것은 캡처에 렌더링된 화면뿐입니다.

- 미리보기 블록이 실제 작품 이미지 자리인지 여부
