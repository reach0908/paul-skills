Pocket Cards Cloud의 첫 실험은 **“문장을 실제로 보관할 수 있을 때, 사용자가 안내나 과제 없이 다시 찾아와 저장하는가”**를 확인하는 수요 실험으로 제안합니다. 이 가정이 틀리면 클라우드 보관함과 반복 사용 기능에 대한 다음 개발 투자를 멈추는 편이 맞습니다. 저장 화면은 확정된 상태로 유지합니다.

자료의 방문자 80명과 무료 알림 신청 18명은 소개에 대한 관심을 보여줍니다. 반복 사용 기록과 지불 자료는 없습니다. 작성자의 mock 저장 검사 local PASS는 실제 사용자의 저장, 보존, 재방문을 확인한 증거가 아닙니다. 따라서 첫 실험에서 확인할 것은 유료 수요나 화면 품질이 아니라 **자발적인 반복 저장**입니다.

**검증할 가정과 작은 실행 방법**

최근 2주 동안 문장을 두 번 이상 따로 저장한 사람에게, 자신의 실제 문장을 보관하고 다시 열어볼 수 있는 수동 카드 보관 서비스를 제공합니다. 기존 저장 사례를 한 개 확인해 참여 조건을 점검합니다. 무료 알림 신청자 중 해당 조건을 충족하는 사람을 우선 후보로 삼을 수 있지만, 신청자 명단에 접근할 수 있는지는 확인되지 않았습니다.

개발 없이 시작할 수 있도록 참여자에게 익숙한 제출 경로 하나와 개인별 보관 문서 하나를 사용합니다. 운영자는 제출된 문장을 원문 그대로 카드 단위로 기록하고, 참여자는 자신의 보관 문서를 다시 열어볼 수 있습니다. 이 전달 방식은 시험용이며, 확정된 카드 저장 화면의 시안을 변경하지 않습니다. 참여자 동의와 개인별 접근 권한이 확보된 상태에서 시작해야 합니다.

첫 안내에서는 제출 방법과 수동 처리 시간을 알려줍니다. 이후에는 저장할 문장이나 횟수를 지정하지 않고, 재방문 알림·매일의 과제·사용량에 따른 보상을 제공하지 않습니다. 참여자가 평소 발견한 문장을 스스로 맡기는 행동을 봅니다. 시작 안내에서 연습으로 제출한 문장은 판정에서 제외합니다.

운영자는 하루 두 번 정해진 시간에 제출분을 처리하고 처리 시각을 기록합니다. 실제 보관과 재열람이 가능한지 시작 전에 운영자 자료 한 건으로 확인합니다. 이 점검은 운영 준비 확인이며, 사용자 수요의 성공으로 세지 않습니다. 실제 저장이 되지 않는 mock만으로는 이 실험을 시작하지 않습니다.

기존 계측인 `landing_view`, `notify_signup`은 모집 유입 맥락에만 사용합니다. 새 분석 도구를 설치하지 않고, 다음 항목을 수동 기록합니다.

- 익명 참여자 번호, 참여 시작일, 자연 발생한 각 제출의 시각과 해당 보관 항목.
- 제출 경로와 보관함을 사용할 수 있었던 기간, 처리 지연·접근 실패·운영자의 개별 안내 여부.
- 마지막 날 한 번 확인한 기존 저장 도구 병행 여부와 자연스럽게 문장을 발견한 기회. 기회에 대한 답변은 자기보고로 구분합니다.

주 지표는 **유효 참여자 6명 중 서로 다른 3일 이상 실제 문장을 저장한 사람 수**입니다. 첫 자발적 저장 뒤 서로 다른 두 날에 다시 저장해야 반복 사용자로 셉니다. 운영자가 이용을 권유한 직후의 제출과 연습 제출은 제외합니다. 보관함 재열람은 부가 관찰이며, 이 결과만으로 별도의 재열람 수요를 검증했다고 판단하지 않습니다.

현재 자료에는 적합한 후보 수, 사용 가능한 전달·보관 도구, 운영자의 가용 시간이 없습니다. 위 숫자는 관측값이나 통계적으로 검증된 임계값이 아니라 **다음의 작은 개발 투자를 판단하기 위한 사전 제안**입니다. 실행 전에 이 한도와 아래 기준을 고정합니다.

**결과별 다음 결정**

먼저 기록의 유효성을 확인합니다. 참여자 모두에게 제출과 보관함 접근이 정상 제공되어야 하고, 제출 기록의 누락 여부를 확인할 수 있어야 합니다. 실제 미사용을 확인한 경우는 0으로 세지만, 관찰하지 못한 사용은 0으로 대체하지 않습니다. 다수에게 자연스러운 문장 발견 기회가 없었다는 근거가 나오면, 10일이라는 기간이 가정을 판단하기에 부족한 것으로 처리합니다.

| 결과 | 사전에 적용할 조건 | 다음 결정 |
| --- | --- | --- |
| 성공 | 유효한 6명 중 4명 이상이 서로 다른 3일 이상 자발적으로 저장 | 이 조건의 초기 사용자에게 반복 저장 가치가 있을 가능성이 지지됩니다. 확정된 화면을 유지한 채 실제 저장·보존·보관함 접근을 제공하는 최소 구현을 다음 투자 후보로 삼습니다. 구현 투자 범위는 별도로 정하고, 셀프서비스 환경에서 반복 사용을 다시 확인합니다. |
| 실패 | 유효한 6명 중 반복 사용자가 0~1명이고, 적어도 4명에게 여러 날 문장을 발견할 기회가 있었다는 자기보고가 있음 | 클라우드 기능 확대 투자를 보류합니다. 기존 도구를 계속 쓴 이유와 저장을 맡기지 않은 이유를 확인해 가정을 수정합니다. 이 작은 표본만으로 전체 시장의 수요 부재를 선언하지 않습니다. |
| 판단 보류 | 반복 사용자가 2~3명, 6명 모집 실패, 기록 누락, 반복 행동을 구분할 수 없는 개별 안내, 접근 장애, 또는 사용 기회 부족 | 개발 확대 근거로 사용하지 않습니다. 어느 증거가 부족한지 기록하고, 더 긴 기간·다른 참여 조건·실제 화면에서의 시험 중 필요한 변경 하나만 별도 제안합니다. |

4명 이상은 작은 다음 투자에 앞서 여러 사람의 반복 행동을 요구하려는 기준이고, 0~1명은 뚜렷한 약한 신호로 삼은 기준입니다. 사업의 손익이나 목표 유지율에서 계산한 수치는 아닙니다. 결과를 본 뒤 기준을 낮추거나 새 참가자로 분모를 바꾸지 않습니다.

기간이나 4시간의 운영 한도에 도달하면 종료합니다. 종료 시점에 유효성 조건이나 판정 조건을 충족하지 못하면 판단 보류로 남깁니다. 개인별 보관 자료가 잘못 공개되거나 저장·접근 장애가 발생하면 즉시 서비스를 중단해 원인을 처리하고, 영향을 받은 자료로 수요를 판정하지 않습니다.

이 실험의 가장 큰 한계는 수동 제출 경로와 운영자 존재가 실제 제품의 이용 부담과 다르다는 점입니다. 성공은 수동 서비스 조건에서의 반복 저장 신호이며, 확정된 화면의 사용성, 장기 유지율, 유료 전환 또는 클라우드 기술의 적합성까지 입증하지 않습니다. 실패 역시 제출 경로의 불편이나 짧은 관찰 기간으로 설명될 수 있습니다. 다음 구현 담당자에게는 확정된 저장 화면, 원문 보존·개인별 접근 규칙, 자발적 저장 날짜를 확인할 기록 요구, 이 실험의 결과와 전달 방식의 차이를 함께 넘깁니다.

현재 상태는 **계획 작성 완료, 실행 전**입니다. 모집·연락·유료 호출·설정 변경은 수행하지 않았으며, 이 계획 자체를 실행 승인으로 보지 않습니다.
