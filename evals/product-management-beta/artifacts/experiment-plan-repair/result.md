# Pocket Cards Cloud 첫 실험 계획

다음 개발 투자 전에 확인할 가장 중요한 미확인은 **현재 문장을 저장하는 사람들이 Pocket Cards Cloud에서 자기 문장을 여러 날에 걸쳐 자발적으로 다시 저장하는가**다. 이를 수요 실험으로 검증한다. 카드 저장 화면은 그대로 사용한다.

80명의 랜딩 방문자 중 18명이 무료 알림을 신청했다. 이 기록은 관심의 근거지만 반복 사용이나 지불 의향을 보여주지는 않는다. 작성자의 mock 저장 검사 local PASS도 실제 사용과 데이터 보존을 증명하지 않는다. 반복 사용 근거가 없는 상태에서 정식 서비스 개발에 크게 투자하면, 작동하지만 다시 찾지 않는 도구를 만들 수 있다.

## 가설과 투자 결정

**가설:** 최근에도 문장을 따로 저장해 온 사용자 6명에게 실제 저장이 되는 테스트 버전을 제공하면, 4명 이상이 첫 안내일을 제외한 7일 동안 최소 2개의 서로 다른 날에 자기 문장을 자발적으로 저장한다.

6명과 4명이라는 기준은 통계적 검증값이 아니다. 작은 초기 투자에 앞서 여러 사람에게서 반복 행동이 나타나는지 확인하기 위한 **제안된 탐색 기준**이다. 이 기준으로 전체 이용자의 유지율을 추정하지 않는다.

이 실험이 바꿀 결정은 “정식 서비스의 계정·클라우드 저장 등 본개발에 들어가기 전에, 실제 저장이 가능한 제한적 MVP와 다음 검증에 투자할 것인가”다. 성공해도 정식 출시나 유료화가 검증되는 것은 아니다.

## 가장 작은 실행 방식

1. **실행 전 저장을 확인한다.** 고정된 저장 화면으로 입력한 문장이 화면을 닫고 다시 열어도 보존되는지 확인한다. 필요한 경우 화면 뒤의 저장 처리를 수동으로 보조하는 테스트 버전을 준비한다. mock 성공 응답만으로 실험을 시작하지 않는다. 기존 자료만으로 실제 저장 기능의 준비 여부는 알 수 없다.
2. **기존 알림 신청자 중 6명을 모집한다.** 최근 7일 안에 자기 필요로 문장을 2회 이상 저장한 경험이 있는 사람을 대상으로 한다. 가능하면 기존 메모 등의 저장 날짜를 본인이 확인하게 하고, 문장 내용 자체는 수집하지 않는다. 무료 알림 신청만으로 적합한 참가자라고 간주하지 않는다. 모집과 연락은 별도 실행 승인이 필요하다.
3. **첫날 접근 방법만 안내한다.** 본인이 가진 실제 문장으로 한 번 저장할 수 있게 한다. 안내 중 저장은 반복 사용에 포함하지 않는다. 접근 가능한 시간, 저장 확인 방법, 실제 데이터 보존 여부를 알려준다.
4. **이후 7일은 자유롭게 사용하게 한다.** 저장할 문장을 주거나 저장 과제를 부여하지 않는다. 복귀 알림, 매일의 연락, 사용 횟수에 따른 보상은 두지 않는다. 다른 저장 도구도 계속 사용할 수 있다.
5. **자발적 재사용과 장애를 기록한다.** 참가자별 익명 식별자, 실제 저장 시각, 저장 성공 여부, 운영자의 안내·연락 여부, 접근 장애만 수동 기록한다. 기존 `landing_view`, `notify_signup`은 반복 사용을 측정하지 못하므로 이번 판정에 사용하지 않는다. 새 분석 도구를 설치할 필요는 없다.
6. **종료 후 짧게 이유를 확인한다.** 다시 저장한 계기, 저장하지 않은 이유, 기존 도구를 계속 쓴 이유를 묻는다. 이 설명은 다음 수정의 단서로 사용하고, “앞으로 쓰겠다”는 답변으로 행동 기준을 대체하지 않는다.

비교 기준은 참가자가 이미 사용하던 저장 방식이다. 최근 저장 경험은 참가자 선정과 맥락 파악에 사용한다. 과거 기록과 이번 사용 횟수의 차이를 제품 효과로 단정하지 않는다. 신규 제품의 반복 사용 기준선은 아직 없다.

## 제안하는 실행 상한

| 항목 | 제안 | 근거와 현재 상태 |
| --- | --- | --- |
| 표본 | 적합한 참가자 6명, 한 집단 | 사람마다 다른 사용 계기를 관찰할 작은 편의표본. 모집 가능 여부는 미확인이다. |
| 모집 | 최대 12명에게 초대, 최대 7일 | 기존 신청자 18명 안에서 모집을 제한한다. 6명을 확보하지 못하면 시작하지 않고 모집 불충분으로 남긴다. |
| 관찰 기간 | 안내 다음 날부터 7일 | 평일과 주말을 포함하고 서로 다른 날의 복귀 기회를 준다. 장기 습관을 검증하는 기간은 아니다. |
| 현금 비용 | 0원 | 기존 자원과 수동 기록을 전제로 한다. 유료 호출·도구·모집비가 필요해지면 실행을 멈추고 비용 제안을 다시 만든다. |
| 운영 공수 | 총 8시간 이내 | 준비 2시간, 모집·운영·종료 확인 4시간, 해석 2시간의 제안이다. 실제 저장 준비가 이 범위 안에 가능한지는 미확인이다. |
| 시도 수 | 참가자 집단 1회 | 중간 결과에 따라 참가자를 추가하거나 기간을 늘리지 않는다. |

모든 수량은 자료에 없으므로 제안이다. 실행 전에 이 범위와 판정 기준을 확정한다. 현재 승인된 실행 예산으로 취급하지 않는다.

## 판정과 다음 결정

반복 사용자란 안내일 이후 **서로 다른 2일 이상에 자기 필요로 실제 문장을 저장한 사람**이다. 같은 날의 여러 저장, 안내 중 저장, 운영자가 요청한 저장, mock 성공은 포함하지 않는다. 분모는 처음 등록한 6명으로 고정하고, 사용하지 않은 사람을 빼지 않는다.

| 결과 | 미리 정한 조건 | 다음 결정 |
| --- | --- | --- |
| 성공 | 6명 모두 7일간 접근할 수 있었고 기록이 완전하며, 4명 이상이 반복 사용자 | 이 사용자군의 짧은 기간 내 반복 저장 가설을 제한적으로 지지한다. 제한적 MVP 개발과 더 긴 기간의 검증을 제안한다. 저장한 문장을 다시 찾아 쓰는 가치, 일반 사용자 수요, 지불 의향은 별도로 확인한다. |
| 실패 | 동일하게 유효한 관찰 조건에서 반복 사용자가 0~1명 | 현재 가치 제안으로 본개발 투자를 보류한다. 비사용 이유에서 기존 도구 대비 가치 부족인지 사용 기회 부족인지 확인하고, 바꿀 가설 하나를 제안한다. 화면 재디자인을 자동 처방하지 않는다. |
| 판단 불가 | 유효한 관찰에서 반복 사용자가 2~3명 | 본개발 투자를 늘리지 않는다. 사용·비사용 사례를 근거로 다음 실험 질문 하나를 제안한다. 이번 결과를 성공으로 바꾸지 않는다. |
| 판단 불가 | 6명 미확보, 철회, 관찰 누락, 실제 저장 확인 실패, 사용을 막는 장애 등으로 전체 관찰이 유효하지 않음 | 누락이나 장애를 수요 실패로 해석하지 않는다. 영향을 받은 사람과 기간을 기록하고, 원인을 해결한 새 계획만 별도로 제안한다. |

저장 유실이나 반복 사용을 막는 장애가 확인되면 실험을 중단한다. 모집 기간, 관찰 기간, 비용 또는 공수 상한에 도달하면 평가를 끝낸다. 상한 안에서 판정할 근거를 확보하지 못한 경우는 판단 불가이며, 재모집·연장·추가 시도는 새로운 결정이다.

## 다음 역할에 전달할 입력

고정된 제품 조건은 **카드 저장 화면을 유지한다**는 것이다. 다음 제작 역할에는 이 화면에서 실제 저장과 보존을 확인할 수 있는 최소 테스트 버전, 참가자별 저장 시각·장애의 수동 관찰 방법, 위 판정 기준을 전달한다. 이 문서가 첫 실험 계획 v1이다.

6명 제한, 7일 접근, 수동 보조, 복귀 알림 없음은 실험 운영을 위한 제안이며 실제 제품의 정책이나 요구사항으로 확정하지 않는다. 현재 남은 준비상의 공백은 실제 저장 수단의 가용성이다. 준비 공수 안에서 해결할 수 없다면 수요 실험을 시작하지 않고 필요한 최소 제작 범위부터 제시한다.

이 문서에서는 모집·연락·유료 호출·설정 변경을 실행하지 않았다. 현재 산출물은 실행 계획이며, 반복 사용 결과는 아직 없다.
