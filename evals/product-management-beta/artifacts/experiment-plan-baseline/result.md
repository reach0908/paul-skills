# Pocket Cards Cloud 첫 실험 계획

첫 개발 투자는 **사용자가 안내나 독촉 없이 돌아와 자기 문장을 반복해서 저장하는지**를 확인한 뒤 결정한다. 정해진 카드 저장 화면을 유지하고, 클라우드 확장이나 화면 재설계는 이번 실험에 넣지 않는다.

## 지금 확인할 중요한 미확인 하나

> 평소 다시 보고 싶은 문장을 자주 만나는 사람이 첫 저장을 경험한 뒤, 7일 안에 서로 다른 두 날에 자발적으로 돌아와 새 문장을 저장할까?

방문자 80명 중 무료 알림 신청자는 18명이다. 이는 관심의 증거지만 실제 사용이나 반복 사용의 증거는 아니다. 작성자의 mock 저장 검사 local PASS도 실제 사용자가 저장을 끝낼 수 있다는 근거는 아니다. 지불 의향은 아직 확인하지 않는다.

## 실행 범위 제안

아직 정하지 않은 표본·기간·비용·시도 수는 다음을 첫 실행안으로 제안한다. 실제 모집과 실행 전에 확정한다.

| 항목 | 첫 실행안 |
|---|---|
| 대상 | 최근 일주일에 다시 보고 싶은 문장을 3번 이상 만났고, 지금은 메모·스크린샷 등으로 보관하는 사람 |
| 인원 | 참여에 동의한 6명. 기존 알림 신청자는 후보일 뿐, 참여 동의를 받았다고 간주하지 않는다 |
| 기간 | 참가자별 첫 저장 이후 7일. 모집 완료 후 같은 날 시작하면 운영이 단순하다 |
| 시도 수 | 1회. 결과가 애매하다고 자동으로 표본이나 기간을 늘리지 않는다 |
| 비용 | 현금 지출 0원, 유료 API 호출 0회. 준비 작업 반나절, 최초 관찰·종료 확인은 각 15분 이내로 제한 |
| 범위 | 기존 화면으로 저장·재열람이 가능한 최소 체험판과 필요한 기록만 사용 |

이 대상에서의 결과만 해석한다. 알림 신청자 위주로 모집하면 관심이 높은 사람에 편향될 수 있다.

## 진행 방법

1. **체험판의 준비 상태를 먼저 확인한다.** 자기 문장을 저장하고, 화면을 닫았다가 다시 열어도 저장 내용이 남아 있어야 한다. 현재 자료만으로는 이 기능이 있다고 확인할 수 없다. 기존 구현을 점검하고, 부족한 기능을 반나절 안에 연결할 수 없다면 실험을 시작하지 않는다. 클라우드 개발을 먼저 끝내는 방식으로 범위를 넓히지 않는다.

2. **첫 저장을 짧게 관찰한다.** 참가자가 실제로 보관하고 싶은 자기 문장 하나를 설명이나 조작 도움 없이 저장하도록 한다. 도움 여부와 실패 지점을 기록한다. 최초 저장은 반복 사용 지표에서 제외한다. 6명 중 최소 5명이 도움 없이 완료하지 못하면 반복 사용 판정을 보류한다. 접근·저장 문제를 좁혀 고치는 것이 먼저다.

3. **7일 동안 실제 생활에서 사용하게 둔다.** “다시 보고 싶은 문장을 만나면 필요할 때 사용하세요”라고 한 번 안내한다. 일일 과제, 저장 횟수 목표, 리마인더, 중간 만족도 연락은 하지 않는다. 참가자에게 아래의 내부 판정 기준을 목표로 제시하지 않는다.

4. **종료 시 기록과 이유를 함께 확인한다.** 저장 이력에서 날짜를 확인하고, 다시 사용한 이유 또는 사용하지 않은 이유를 짧게 묻는다. 특히 문장을 만날 기회가 있었는지, 기존 도구를 대신 썼는지, 접근이나 저장이 막혔는지 구분한다. 회고에서 “계속 쓸 것 같다”는 답만으로 반복 사용을 인정하지 않는다.

## 기록과 판정 기준

주요 지표는 **첫 저장 후 24시간 이상 지난 시점부터, 서로 다른 두 날짜에 새 문장을 자발적으로 저장한 참가자 수 / 6명**이다. 첫날 연속 저장이나 운영자의 안내 직후 저장은 포함하지 않는다. 재열람은 맥락을 이해하는 보조 기록으로만 사용한다.

기존 `landing_view`, `notify_signup`으로는 이 지표를 측정할 수 없다. 새 분석 도구를 설치하는 대신, 참가자의 동의를 받아 체험판의 최소 저장 기록이나 종료 시 확인 가능한 저장 이력을 사용한다. 필요한 정보는 익명 참가자 번호, 저장 성공 시각, 최초 저장 때 도움 여부뿐이다. 문장 원문은 수집하지 않아도 된다. 종료 때 어떤 기록을 확인할지 시작 전에 정한다.

기록이 누락되거나 체험판 장애가 발생한 사람은 ‘미사용’으로 단정하지 않는다. 6명 모두의 상태를 확인할 수 없으면 아래 기준으로 개발 투자를 승인하지 않고, 관측이 불완전했다고 보고한다.

| 관측 결과 | 다음 결정 |
|---|---|
| 3명 이상이 반복 사용 기준 충족 | 짧은 기간의 반복 사용 신호가 있다. 다음 개발은 돌아온 사용자의 실제 불편 하나를 해결하는 작은 범위로 제한한다. 전면적인 클라우드 개발을 확정하지 않는다 |
| 1~2명만 충족 | 넓은 대상에 대한 개발 투자를 보류한다. 반복한 사람과 그렇지 않은 사람의 사용 상황을 비교해 대상이나 사용 계기를 하나로 좁힌다. 다음 실험은 새 범위를 정한 뒤 별도로 결정한다 |
| 0명이 충족하고, 저장할 기회와 정상 접근이 확인됨 | 현재 대상과 사용 방식으로는 반복 사용 근거가 없다. 클라우드 기능 확장을 중단하고, 기존 저장 도구에서 바꿀 만큼 해결할 문제가 있는지 다시 검토한다 |
| 최초 저장 실패, 기록 누락, 체험판 장애 또는 문장을 만날 기회 부족 | 반복 사용에 대한 결론을 내리지 않는다. 확인된 실행 문제나 대상 조건을 수정한 뒤 재실험 여부를 결정한다 |

‘3명’은 작은 개발 투자를 계속할지 판단하기 위한 임시 기준이다. 표본 6명의 결과로 시장 전체의 유지율을 추정하거나 통계적 유의성을 주장하지 않는다. 실행 전 기준을 확정하고, 결과를 본 뒤 유리하게 바꾸지 않는다.

이 실험으로 확인할 수 있는 것은 해당 대상의 **7일 동안의 자발적 반복 저장**이다. 장기 유지, 결제, 클라우드 동기화의 필요성은 여전히 미확인이다. 이 문서는 계획이며 모집·연락·유료 호출·설정 변경은 실행하지 않았다.
