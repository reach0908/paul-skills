# Installed entry-point smoke protocol

The complete trial plugin contains 44 promoted skills. Nine new Codex CLI contexts use `gpt-5.6-sol` with `xhigh`, matching the prior comparisons. Four prompts omit skill names and request the preparation phase of IA, task-flow, wireframe and supplied-design work. Four explicitly invoke the user-only component roles and ask for their role boundary. A ninth explicitly invokes the router and asks for the new design sequence.

This checks installed discovery, exact body loading and invocation boundaries, not another implementation-quality comparison. Each context is read-only and requests no browser work or product changes. The full implementation and browser evidence remains in the earlier unchanged-candidate trials.

Pass requires process completion, the target installed body actually read or injected, the four automatic new roles in the supplied catalog, all five design user-only roles excluded from automatic selection, and unchanged task inputs. Natural prompts must not read any user-only design body. Explicit prompts must receive the exact installed target body. Router output must cover the four-stage sequence and distinguish the component workbench from task planning.

Budget: nine primary contexts. Preserve every failure. Up to two additional contexts may clarify a host or collection problem; never replace or hide an original failure. Raw host traces stay local; publish only bounded prompts, hashes, command evidence and summaries after approval.
