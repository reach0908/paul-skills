# 남은 디자인 스킬 8개 정식 승격

2026-10-14 KST. 사용자가 “남은 8개 모두 정식 승격 진행해줘. 관련 문서와 패키지도 맞추고, 설치·자동 발견 검증까지 마무리해줘”라고 명시 승인했다. 이 기록은 그 승인에 따른 승격과 배포를 다룬다.

## 승인 범위와 동일성

| 호출 방식 | 새 정식 스킬 |
| --- | --- |
| 자동 또는 직접 호출 | information-architecture, user-flow, wireframe, build-design |
| 사용자 직접 호출만 | state-machine, break, explain-interface, variant |

디자인은 기존 9개에서 17개, 전체 플러그인은 36개에서 44개가 된다. 마지막 [보완·재비교·단계 전달 검증](../design-beta-hardening-2026-10-14/REPORT.md)의 파일 30개를 내용 변경 없이 `skills/design/`으로 옮겼다. [승인본 해시](approved-files.json)와 [패키지 확인 코드](verify_package.py)가 파일 전체, 출처와 호출 정책의 동일성을 확인한다.

IA·user-flow·wireframe은 직접 작성한 원본이다. 나머지 5개는 Jakub 원본의 adaptation이며 고정 원본 `d574cc8a576dc24256ad38268b8d03d86724a1b3`과의 비교 결과를 유지한다. 승격 때문에 원본 revision이나 reconciliation 기준을 진전시키지 않았다. `ask-matt`의 새 경로 안내만 별도의 local decision과 digest로 기록했다.

## 문서와 패키지

루트·디자인·베타 목록, plugin manifest, 출처 경로를 맞췄다. 8개 인간용 문서와 `ask-matt`의 계획·화면·구현·컴포넌트 작업대 경로를 연결했다. 역할 간 목적지·상태 ID와 미결 사항 전달을 안내하고, 직접 호출 전용 4개를 자동 단계로 바꾸지 않았다.

문서의 질문은 이번 대화의 원자적 역할, 로컬 작업, Figma 불사용, 원본 유지, 닫기·복원 및 stress fixture 요구에서 가져왔다. 관련 공개 GitHub 이슈 검색 결과는 없었다. 이미 확인한 개인 위키·사전 폴더는 사용하지 않았다. 기존 설치 문구는 그대로 유지한다.

이전 수정 Changeset은 최종 배포 상태를 설명하는 minor Changeset에 통합했다. 과거 평가 기록과 실행 입력은 당시의 베타 경로·판정을 그대로 보존한다. 별도 PM 베타 PR #10과 기존 `.playwright-cli/` 작업은 이번 범위 밖이다.

## 검증

- 저장소 검사: 출처 기록 56개, 정식 경로 44개, 테스트 38개 통과.
- `claude plugin validate . --strict` 통과. Claude 모델 실행 증거와는 구별한다.
- 승인한 스킬 파일 30개와 원본 기록이 동일하다. 문서·라우터·명시 호출 정책도 확인한다.
- 임시 `CODEX_HOME`에 실제 marketplace/plugin 설치를 수행했다. 44개 모두 활성 상태로 발견했고 정식 스킬 파일 173개가 원본과 일치했다. [시험 설치 기록](evidence/trial-installation.json).
- 이전 모델 산출물 1개의 Markdown 줄바꿈·EOF 공백은 원본 해시 보존을 위해 해당 파일에만 공백 예외를 지정했다. 다른 스킬·코드 검사는 유지한다.
- 설치 후 실제 자연어·명시 호출은 아래 릴리스 기록에서 별도로 확정한다.

## 릴리스와 설치

**로컬 승격과 시험 설치는 완료했다. 공개 발행과 일상 전역 갱신은 아직 하지 않았다.** [Changeset 계획](evidence/version-plan.json)은 0.3.0에서 0.4.0 minor 발행을 제시한다. 실제 시험 설치 버전은 `0.4.0-trial.20261014`이며 원본 44개 경로와 파일 173개를 그대로 패키징했다. 일상 Codex와 Claude Code 캐시 manifest는 모두 0.3.0, 정식 스킬 36개로 확인했다.

원격 push·PR 생성은 자동 승인 심사에서 차단됐다. 평가 산출물·스크린샷을 포함한 구체적인 공개 payload에 대한 승인이 확인되지 않았다는 이유다. 차단된 호출은 실행되지 않았고 우회 게시하지 않았다. [차단 기록](evidence/approval-block.json), [검토할 공개 범위](PUBLICATION.md). 공개 승인 후 승격 PR, 버전 PR, 태그, 전역 설치와 새 카탈로그를 순서대로 검증한다.

## 시험 설치의 새 문맥 검증

[실행 전 프로토콜](PROTOCOL.md)에 따라 새 Codex CLI 문맥 9개를 사용했다. 모델은 이전 비교와 같은 `gpt-5.6-sol`, 추론은 `xhigh`다. 설치 경로는 임시 CODEX_HOME이고 스킬을 프로젝트 폴더로 직접 복사해 발견을 대신하지 않았다. 인증 연결은 실행 종료 후 제거했다.

| 검사 | 결과 |
| --- | --- |
| 스킬 이름 없는 IA·flow·wireframe·build 준비 요청 | 4/4 해당 설치 본문 자동 선택 및 실제 읽기 |
| 직접 호출 전용 4개 명시 요청 | 4/4 설치 파일과 동일한 본문이 호스트에서 주입 |
| 명시한 ask-matt 경로 안내 | 1/1 네 단계와 컴포넌트 작업대 경계를 안내 |
| 각 문맥의 자동 목록 | 새 자동 역할 4개 노출, 사용자 전용 디자인 역할 5개 제외 |
| 자연어 요청의 사용자 전용 본문 로딩 | 0회 |
| 입력 파일 변경 | 0개 |

[9/9 설치·진입점 결과](evidence/smoke-summary.json)와 사례별 입력, 읽은 스킬, 본문 해시, 명령·출력 해시를 보존한다. 역할 설명과 준비만 요청했으므로 9개의 구현 품질 시험으로 세지 않는다. 원시 로그는 로컬 `.scratch/design-final-promotion-20261014/`에 있으며 공개 자료에 인증값은 포함하지 않는다.

설명 품질의 한계도 관찰됐다. 모든 시험 폴더에 동일한 파일을 넣어 wireframe 준비 과제에도 승인 구현 명세의 “구조 유지” 제약이 노출됐고, 모델은 이를 화면 상태 확장은 가능하다는 뜻으로 재해석했다. 일부 이웃 역할 설명도 state-machine을 전이 설계까지 맡는 것처럼 넓게 요약했다. 실제 파일 변경이나 해당 스킬의 실행은 없었지만, 설치 통과가 모든 준비 설명의 정확성을 보증하지 않는 사례다. 기존 단계 전달과 동작 증거를 이 요약 응답으로 대체하지 않았다.

## 판단의 한계

앞선 원본 비교와 실제 전달 체인의 결과는 해당 로컬 반응형 웹 과제에 한정한다. 이번 승격은 검증 범위와 남은 한계를 알고 내린 사용자 승인이다. 모든 입력에서 원본 이상이라는 통계적 보증, 네이티브·실제 보조기술 전체 인증, Figma 작업 및 Claude Code 모델 실행을 주장하지 않는다. 기존 데스크톱 대화가 이미 받은 스킬 목록과 새 설치본의 발견은 별도다.
