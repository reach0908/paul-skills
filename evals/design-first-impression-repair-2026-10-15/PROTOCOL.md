# First-impression repair comparison

Registered before native execution. This is a new experiment authorized after the previous report, not a replacement phase or an amendment to its failed attempts.

## Question and arms

Does the repair preserve approved brand composition and partial prototype scope while completing all six owner loads in an authorized interface audit?

- Baseline: PR #26 at `eb1977505c0a385a7608f19861962b660f575dfc`, including the previously failing first-impression procedure.
- Candidate: the working skill and manifest tree frozen in `freeze.json` before any trial. Only the first-impression procedure, interface audit procedure and report format change behavior. The entry skill, six owner skills and invocation policy stay identical to baseline.
- These arms are compared with each other. The older main-versus-first-candidate trials keep their original report, failures and evidence unchanged.

## Execution

Eight matched cases in `cases.json`: original brand, landing, missing screenshot, warning, required navigation control, staged referral, reading, original brand repeated in a fresh session. Identical task, artifact bytes and tools per pair. Pair order is fixed; arm submission order alternates. At most two native sessions run concurrently. Each session starts without conversation history in a fresh neutral directory and loads one session-local plugin. No expected answer, prior failure, repair description or grading rubric is supplied to the model.

Original fixtures are copied byte for byte. The required-navigation control reuses the brand source and screenshot, with a new brief explicitly requiring both in-document paths in the delivered implementation. This changes the product contract, not the visual evidence. The repeated brand case is a separate fresh attempt, not a retry of a failure.

Use the installed Claude Code host and its inherited configured model with explicit `low` effort, as in the prior completed profile. Record the actual host/model from native initialization; if either varies across a pair, retain but do not treat it as matched. The per-session time limit is 240 seconds and native cost threshold is USD 1.00. That threshold may be exceeded by the last request. Reserve USD 2.80 before starting a pair and stop before the aggregate reservation would exceed USD 16.00. Unknown timeout cost is reserved at USD 1.00. Stop after two execution failures. Do not change model, effort, prompts or candidate after freezing; any later repair needs a separate record. Retain every started attempt and mark unstarted work `not_run`.

Only Skill, Read, Glob and Grep are allowed, with strict MCP isolation, disabled hooks and memory, no session persistence and no global settings change. No browser or participant runs are available in the trials. A 500-word final-answer constraint does not change the required review procedure. Raw streams remain ignored locally; publish scoped receipts, verbatim final responses with portable path aliases and their hashes. Do not publish system prompts, thinking, signatures or unrelated settings.

## Decision criteria, fixed before execution

1. **Brand restraint:** in the two original-brand runs, do not block on destinations outside the supplied prototype state or propose aesthetic filling/normalization without concrete task evidence. Source facts, unobserved interactions and predicted risks stay distinct. Approved identity and no conversion CTA remain intact. Supported navigation-visibility findings are allowed; keeping the composition is allowed.
2. **Required-path control:** still identify the source-proven absent required targets as actionable in the explicit delivery contract. Do not claim a click was observed. A prototype label is not blanket immunity.
3. **Owner execution:** landing, warning and missing-evidence audits must successfully invoke all six installed owners, in order, before artifact or optional first-impression inspection. A direct full-body read is a valid fallback only if the host lacks a Skill tool. Tool receipts, not the response's self-report, decide this. Missing visual evidence does not waive owner loading and owner loading alone does not prove visual verification.
4. **Evidence and preservation:** do not invent timed human/fresh-observer results, current screenshots in the missing case, or implemented fixes. Preserve warnings, policy, controls and brand direction. Separate possible risks from confirmed ranked defects.
5. **Routing controls:** a staged change request ends in the explicit `interface-review staged` referral with no artifact/domain/audit inspection. Standalone reading review does not add a CTA or orchestrate all six domains.

All criteria applicable to each completed case must hold for a candidate full-workflow pass. Record native completion separately from behavioral outcome. Do not infer success for an incomplete, budget-stopped or unrun attempt. Compare paired outcomes by case; this small regression suite cannot establish statistical superiority or universal reliability.

## Review and integrity

The implementing maintainer grades final responses unblinded against the criteria and records quotes/locations plus response hashes. Mechanical collection checks native completion, plugin selection, owner calls, full reference reads and input preservation. This is not independent human usability testing.

Freeze the runner, protocol, prompts, fixture bytes and both plugin trees. Bind every receipt to that freeze and its final response. Verify all old evaluation paths against their Git blob at the baseline commit, without rerunning its source-drift verifier against the changed candidate. Record original-checkout HEAD/status and content hashes of its unrelated untracked files, and the user settings digest before and after. Validate the repository and plugin manifests separately from behavioral results.
