# 첫인상 보완 1차: 브랜드 판정과 담당 스킬 호출

**브랜드 과잉 제안과 여섯 담당 호출 누락은 보완됐지만, 새로 요구한 호출 순서는 3건 모두 실패했다. 전면 통과로 기록하지 않는다.** 16회 모두 native 완료했고, 수정 전후 8쌍을 비교했다. 후속 진입 순서 수정은 [별도 보고서](../design-first-impression-order-2026-10-15/REPORT.md)에 남긴다.

## 비교 대상

- 기존판: PR #26의 `eb1977505c0a385a7608f19861962b660f575dfc`.
- 첫 보완판: `1ea79a4487b67e2de322dc3a9ce646a9d9a4c364`. 실행 전에 `freeze.json`으로 고정한 전체 스킬·manifest와 이 커밋의 내용이 동일하다.
- 동작 변경: `better-layout/first-impression.md`, `better-interface/audit-procedure.md`, `better-interface/review-format.md` 세 파일. 원래 여섯 담당 본문과 진입점은 이 단계에서 변경하지 않았다.
- 실제 호스트/model: receipts의 Claude Code 및 `claude-opus-5-5`, explicit low. 양쪽 입력·모델·호스트가 같은 완료 쌍만 비교했다.
- [사전 프로토콜](PROTOCOL.md), [실행 입력](cases.json), [고정 해시](freeze.json), [원 응답](responses/), [호출 증거](receipts/), [해시와 연결된 정성 판정](manual-review.json).

| 사례 | 기존판 | 첫 보완판 |

| 경고 통합 리뷰 | 담당 호출 0/6 | 담당 호출 6/6. 절차와 화면을 함께 먼저 읽어 순서 기준 실패 |

이 재실행의 기존 브랜드판은 HIGH Block을 반복하지 않았지만, 승인 범위에 없는 상호작용/캡션 추가는 반복했다. 이전 평가의 Block 실패는 [원 보고서](../design-first-impression-2026-10-15/REPORT.md)에 그대로 남아 있다. 과거 실패를 이번 실행에서 재현한 것처럼 쓰지 않는다.

등록한 기준 전체를 만족한 사례는 기존판 3/8, 첫 보완판 5/8이다. 첫 보완판의 브랜드 보존은 2/2, 필수 경로 결함 탐지는 1/1, 여섯 담당 호출 자체는 3/3이다. **담당 호출을 artifact 검사보다 앞세우는 기준은 0/3**이다. 자기 보고 대신 성공한 Skill 결과와 호출 순서로 판정했다. 비교를 위해 수치로 묶었지만 통계적 우수성이나 전반적인 디자인 품질 점수는 아니다.

## 실패와 후속 수정의 근거

세 통합 리뷰 모두 첫 도구 배치에 감사 절차와 BRIEF/화면 자료를 함께 넣었다. 절차 안에 추가한 지침은 그 배치가 끝나야 읽히므로, 여섯 스킬을 모두 부르더라도 선행 화면 읽기를 막지 못했다. 이 실패에 한해 진입점에서 절차를 별도 도구 행동으로 읽도록 수정하고 네 쌍의 후속 비교를 등록했다. 이 단계의 입력, 응답, freeze와 실패 판정은 바꾸지 않는다.

경고 문구의 심각도가 기존판 HIGH에서 보완판 MEDIUM으로 바뀌는 등 개별 판단 차이도 남는다. 여섯 스킬 호출 성공이 모든 도메인 규칙의 완전한 적용이나 정확한 심각도 보정을 증명하지 않는다. 답변의 간결화로 영역별 근거 표현 수준도 달랐으며, 이번 기준은 표의 모양을 점수화하지 않는다.

## 검증과 보존

- 16/16 native 완료, 8 matched pairs. 보고 비용 USD 3.7111494, 시간·비용 제한 실패와 미시작 사례 없음.
- 두 번의 브랜드 보존, 필수 경로 대조, staged 진입을 실제 응답으로 확인했다. 조건부 첫인상 참조는 해당 14/14 실행에서 전체 줄 읽기가 확인됐다.
- 원래 평가 디렉터리의 **110개 파일이 `eb19775`와 byte 일치**한다. 기존 실패 기록을 수정하지 않았다.
- 원본 checkout의 HEAD, dirty 상태, untracked 내용, 사용자 Claude 설정 digest가 그대로다.
- `npm run check`: 38 tests 통과. 두 manifest strict validation과 수정 스킬 quick validation 통과. 증거 검사 6 tests 통과. 무결성은 [VERIFICATION.json](VERIFICATION.json), 정성 결과는 [RESULTS.json](RESULTS.json)로 구분한다.
- 후속 수정 후에도 이 단계의 소스는 현재 checkout이 아니라 `candidate-source.json`의 고정 커밋으로 검증한다. 검증 코드 변경으로 실패를 성공 처리하지 않는다.

정성 평가는 구현 담당자의 비블라인드 판정이다. 사람 3초 관찰, fresh AI 관찰자, 실제 브라우저 상호작용, 구현 후 재확인, 자동 발견은 미실행이다. 작은 합성 회귀 사례이며 사용성·전환율·릴리스 승인 근거가 아니다.
