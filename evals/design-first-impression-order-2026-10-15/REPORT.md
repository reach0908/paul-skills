# 첫인상 워크플로우 보완 결과와 진입 순서 비교

**요청한 두 문제를 보완했다.** 승인된 브랜드의 구도와 부분 프로토타입 범위를 존중하고, 통합 리뷰에서는 감사 절차를 단독으로 읽은 뒤 여섯 담당 스킬을 먼저 호출한다. 이번 후속 비교는 최종 보완판 4/4, 직전판 2/4로 등록 기준을 충족했다. 기존 실패는 삭제하거나 성공으로 바꾸지 않았다.

## 최종 변경

```text
현재 화면 감사 / 명시적으로 허용된 변경 리뷰 handoff
  → 감사 절차를 단독으로 읽기
  → 접근성 → 레이아웃 → 문구 → 타이포그래피 → 색상 → UI 호출
  → 화면·소스 검사와 필요한 첫인상 참조
  → 구현 범위·관찰 종류·근거에 따른 판단
```

- `better-layout/first-impression.md`: 승인된 비대칭·여백을 바꾸려면 구체적인 과업 근거가 필요하다. 부분 시안의 범위 밖 목적지, 소스로 확인한 필수 구현 누락, 실제 클릭 관찰을 구별한다. 불확실한 위험은 심각도 표와 차단 판정에서 분리한다.
- `better-interface/audit-procedure.md`: 여섯 담당을 먼저 호출하고 성공한 도구 결과로 로드를 확인한다. 화면이 없거나 답변이 짧아도 호출을 생략하지 않는다. 실제 요구 범위의 결함은 계속 지적한다.
- `better-interface/review-format.md`: 담당 호출 성공과 화면 검증을 구별한다. 담당을 불러오지 못했으면 감사 미완료와 이유를 보고하고 승인하지 않는다.
- `better-interface/SKILL.md`: 허용된 감사 절차를 화면 자료와 한 번에 읽지 않도록 진입 한 문단을 보완했다. staged 등 변경 리뷰의 직접 호출 경계는 유지한다.

이번 후속 작업의 동작 변경은 위 네 파일이다. PR 전체는 앞서 합의한 다섯 파일에 `better-interface/SKILL.md` 진입 순서 수정이 추가된다. docs, Changeset, provenance와 평가 증거를 동기화했고, 여섯 담당의 개별 규칙·manifest·호출 정책·버전은 유지했다. router의 역할 연결도 바뀌지 않아 수정하지 않았다.

### 이번 네 쌍

| 사례 | 직전판 | 최종판 |
| --- | --- | --- |
| 랜딩 | 화면을 먼저 읽고 여섯 담당 호출 | 절차 → 여섯 담당 → 화면/참조. 요금·동의 조건 유지 |
| 현재 화면 없음 | BRIEF를 먼저 읽고 여섯 담당 호출 | 여섯 담당을 먼저 호출. 이후 실제 화면 검증 부재와 unknown/not_run 명시 |
| 모바일 경고 | 이번 실행은 순서 준수 | 순서 준수. 기록 보존 정책, 경고와 두 버튼 유지 |
| staged | 명령 안내로 종료, tool calls 0 | 같은 직접 호출 경계 유지, tool calls 0 |

브랜드·읽기 단독 경로의 본문과 참조는 1차 보완판과 최종판이 byte-identical하다. 그 결과는 1차 평가에 연결하고, 최종 plugin 전체로 여덟 사례를 다시 실행했다고 쓰지 않는다. 첫 브랜드 재평가에서 기존판은 과거의 HIGH Block을 재현하지 않았지만, 약속하지 않은 작품 링크/캡션 추가를 두 번 반복했다. 보완판은 두 번 모두 구도를 유지했고, 필수 경로 대조에서는 실제 누락을 HIGH로 유지했다.

## 증거와 검증

- [사전 프로토콜](PROTOCOL.md), [입력](cases.json), [freeze](freeze.json), [native receipts](receipts/), [원 응답](responses/), [정성 검토](manual-review.json), [결과](RESULTS.json), [무결성](VERIFICATION.json).
- 두 새 비교는 모두 Claude Code **2.1.300**, 실제 **claude-opus-5-5**, explicit **low**, 동일한 읽기 전용 도구와 500단어 제약으로 실행했다. 실제 successful Skill 결과와 파일 읽기 순서를 검사했다. 전체 참조 읽기는 줄 단위로 확인했다. 자기 보고만으로 호출 성공을 판단하지 않았다.
- 새 실행 총 **24/24 완료**, phase별 8쌍과 4쌍. 보고 비용 합계 **USD 6.5987652**, 사전 USD 16 한도 이내. 미시작·시간 초과·비용 초과 시도 없음. 비용은 native receipt의 보고값이며 별도 청구서 확인은 하지 않았다.
- 1차: 기존판 USD 1.5159078 / 보완판 USD 2.1952416. 후속: 직전판 USD 1.441274 / 최종판 USD 1.4463418. 호출 충실도 증가를 토큰·비용 절감으로 주장하지 않는다.
- `npm run check` 38 tests, 두 manifest strict validation, 스킬 quick validation 통과. 두 평가 디렉터리에서 증거 검증 6 tests씩 통과. 이는 스킬 품질/사용자 검증과 별개다.
- 원래 평가 **110개 파일**을 `eb19775`의 Git blob과 비교해 모두 일치함을 확인했다. 원본 checkout의 HEAD·dirty 상태·untracked 파일 내용과 사용자 설정 digest도 동일하다. 초기 실패 5건, 브랜드 실패, 담당 누락, 새로 확인한 순서 실패를 모두 유지한다.

## 확인 한계와 PR 상태

이 결과는 구현 담당자의 비블라인드 정성 검토와 도구 증거를 결합한 작은 합성 회귀 평가다. 개별 경고의 심각도와 영역별 설명에는 실행 간 차이가 남는다. 여섯 스킬 호출 성공이 모든 규칙의 완전한 적용이나 일관된 심각도 판정을 증명하지 않는다. 전체 디자인 품질 우위나 효과 크기도 추정하지 않는다.

사람 3초 테스트, 독립 AI 첫인상 관찰자, 실브라우저 상호작용, 실제 화면 수정 후 재검증, Codex native 실행, 자동 발견과 명시적 change-review handoff 전체 실행은 이번 후속에서 미실행이다. 결과는 PR #26에 반영하며 Draft 상태를 유지한다. 병합·릴리스·전역 설치는 이 작업의 결과에 포함하지 않는다.
