# 원본과 Paul의 가벼운 리뷰 비교

2026-10-10. **핵심 문제 검출에서는 이번 예제의 차이가 없었지만, 원본만 보고한 LOW 항목이 있어 전체 동등 이상 판정은 보류한다.** 두 실행의 `Block`은 예제 화면에 대한 판정이며, 스킬 품질 시험의 PASS/FAIL과는 다른 값이다.

## 같은 과제, 다른 스킬

합성 한국어 읽기 목록 ‘갈피’를 `better-interface`와 6개 owning domain 스킬로 검토했다. 원본은 Jakub `d574cc8a576dc24256ad38268b8d03d86724a1b3`, Paul은 이번 실행의 파일 해시로 고정한 현행 베타다. Paul 조건에는 `design-browser`도 포함됐다.

- 두 fixture와 요청의 해시가 동일하며, 종료 후 스킬·앱·요청 파일이 그대로임을 다시 확인했다.
- 새 에이전트 문맥에서 동일하게 상속된 모델/설정을 사용했다. 정확한 모델 식별자·effort·토큰·비용은 도구에서 노출되지 않아 알 수 없다. 별도 모델 변경은 없었다.
- 공통 도구는 Microsoft Playwright CLI 0.1.22, 관측 브라우저 버전은 152.0.7977.82였다.
- 대상 크기는 1280×900, 390×844, 320×844. 성공·실패·빈 상태·삭제·키보드·동작 줄이기·긴 문자열을 검토했다.
- 실행은 각 조건 1회, 각각 약 7분과 45개 CLI 호출의 범위로 제한했다. 원본과 Paul은 서로의 출력과 평가 기준을 받지 않았다.
- 자동 스킬 발견은 검증하지 않았다. 명시 경로를 읽는 새 하위 에이전트이며 호스트의 카탈로그와 파일 시스템은 공유한다.

판정 담당자는 두 보고서와 소스, 구조화된 브라우저 관찰을 대조했다. 핵심 동작은 별도 Playwright 세션으로 재확인했다. [전체 해시·조건·출력 기록](results-2026-10-10-comparison.json)에 실행을 고정했다.

두 결과 모두 reduced-motion 무시, 상태 알림/오류 연결 누락, 중복 저장, 삭제 후 포커스 손실, 긴 URL 넘침, 기존·신규 아이콘 불일치도 보고했다. 프로젝트가 명시한 평면 스타일이나 시스템 글꼴을 취향만으로 문제 삼지 않았다. 입력 placeholder, 모의 서버, 실제 스크린리더 시험의 한계도 양쪽이 구분했다.

원본은 **HIGH 8, MEDIUM 4, LOW 2**, Paul은 **HIGH 9, MEDIUM 4, LOW 1**로 각각 14행을 보고했다. 이 숫자는 품질 순위가 아니다. 원본은 카드 최소 폭과 긴 URL을 한 행으로 합쳤고 Paul은 별도 원인으로 나눴기 때문에 HIGH 개수가 다르다.

### 원본에만 있던 항목

원본은 변하는 `#count`의 `font-variant-numeric`이 `normal`인 점을 LOW로 보고했지만, Paul은 보고하지 않았다. 이 규칙은 양쪽 typography 스킬에 모두 보존되어 있다. 따라서 규칙 삭제로 인한 손실은 아니며, 이번 실행의 누락이 반복되는지는 아직 모른다.

별도 관찰에서 같은 14px 시스템 글꼴로 만든 측정 문자열의 폭은 `1개` 18.469px, `4개` 20.984px였다. `11개`와 `88개`도 24.813px와 29.703px로 달랐다. 이는 숫자가 고정 폭이 아니라는 확인이며, 사용자 과업 실패나 유의한 성능 저하를 증명하지는 않는다. 원본의 LOW 항목을 정당한 세부 지침 검출로 인정하고 Paul의 누락으로 남겼다.

**이번 과제의 결론:** 확인된 HIGH 원본 항목의 누락은 없었다. 그러나 원본의 유효한 세부 항목 1개가 빠졌으므로 사용자가 요구한 전체 품질 하한을 충족했다고 선언하지 않는다. 스킬 변경의 인과 효과나 일반적인 열세도 한 번의 실행으로 단정하지 않는다. 판정 상태는 `전체 동등 이상 보류, 세부 항목 누락 관찰`이다.

## 실행 품질과 한계

| 기록 | 원본 | Paul |
| --- | --- | --- |
| 기록된 실행 시간 | 약 324초 | 약 366초 |
| 기록된 CLI 호출 | 15회 | 도움말/버전 포함 20회 |
| 실패 CLI 명령 | 3회 | 5회 |
| 저장한 스크린샷 | 16개 | 13개 |
| 코드·스킬 변경 | 없음 | 없음 |
| 토큰·비용 | 알 수 없음 | 알 수 없음 |

시간은 각 에이전트의 기록 시작점이 완전히 같지 않고, 공유 호스트에서 병렬 실행했으며 브라우저 세션/권한 재시도도 포함한다. 효율 우위로 해석하지 않는다. 두 조건 모두 최초 세션 재접속 문제와 `console.log` 반환 누락을 겪어 같은 쉘에서 open/run/close하고 `return`으로 결과를 남겼다. 일부 중간 원문 로그는 최종 시도로 덮어썼지만 실패·재시도 이력은 실행 JSON에 남겼다.

판정 담당자도 초기 출력 반환 실패를 보존하고 다시 수집했다. 두 번째 캡처는 이전 상태가 남아 있어 초기 화면 캡처를 별도 파일로 다시 저장했다. 입력 라벨의 기대 문구는 자체 브라우저 확인 후, 두 보고서를 읽기 전에 ‘이름 없음’에서 ‘지속 라벨 없음’으로 정정했다. 원본의 더 정확한 결과를 오답 처리하지 않도록 이 정정을 기록했다.

실제 스크린리더, 200% 확대, 네이티브 모바일, 터치, 다중 브라우저, 자동 접근성 전체 감사는 수행하지 않았다. 무스킬 조건, 반복 실행, 독립 과제와 사람의 시각 품질 평가는 없다. 이 시험은 화면 리뷰이며 생성된 디자인이나 `build-design`의 구현 품질을 측정하지 않았다.

## 검증 상태를 적용할 범위

- `better-interface`와 6개 better-*의 **이 합성 화면 리뷰**에 한정한 비교 실행 근거가 생겼다. 독립 역할 전체의 동등성은 미검증이다.
- `design-browser`의 현행 Playwright 경로를 Paul 실행이 읽고 사용했다. Aside 경로·성능 측정·도구 간 비교는 미검증이다.
- `build-design`, `variant`, `state-machine`, `break`, `interface-review`, `explain-interface`의 역할 실행은 이 시험에 포함되지 않았다.
- IA·user-flow·wireframe의 앞선 합성 실행은 별도 기록이며 이번 결과로 소급 승인하지 않는다.

현행 스킬 지침을 이번 정답에 맞추어 수정하지 않았다. 다음 비교는 숫자·날짜·표 등 독립 콘텐츠를 포함해 누락이 재현되는지 확인하고, 발견되면 가장 작은 원인을 수정한 뒤 원본과 다시 비교해야 한다. [품질 기준](quality-floor.md)에 따라 비교 전·후의 실패를 모두 보존한다.
