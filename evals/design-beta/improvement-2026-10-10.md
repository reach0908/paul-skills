# 디자인 스킬 품질 보완과 재검증

이 기록은 [첫 비교](comparison-2026-10-10.md) 이후의 수정과 실행을 다룬다. 이전 누락과 실행 파일은 그대로 보존한다. 합격 범위는 실제 비교한 과제와 역할에 한정하며, 베타 전체의 승격을 뜻하지 않는다.

**최종 v4는 검증한 리뷰 2개와 이미지 구현 1개에서 원본 하한을 통과했다.** 추가한 Markdown-only 입력도 별도 명세 과제를 통과했다. 17개 전체의 역할 동등성, 실제 사용자 수용이나 승격을 선언하지 않는다.

숫자 고정 폭 규칙을 정답처럼 반복 추가하지 않았다. 누락의 반복 원인이 입증된 것은 아니므로, 규칙 점검의 완료 조건과 최종 보고의 보존을 보강하는 가설을 실제 실행으로 확인한다. 도메인 규칙과 호출 정책, 원본 import/review 리비전은 유지한다.

첫 수정본은 숫자 누락을 해소했지만, 이전 실행까지 대조하면 양쪽에 포커스 전환의 공통 누락이 남았다. 두 번째 수정본은 포커스를 관찰했으나 Tab으로 복구 가능하다는 이유로 과업 연속성 비용을 보고하지 않았고, 중복 제출도 미검증으로 남겼다. 세 번째 수정본은 이 둘의 실행 완료 조건을 보완했다. 앞선 수정본의 실행을 최종본의 실행으로 바꿔 기록하지 않는다.

세 번째 수정본은 기존 읽기 목록의 유효한 발견 15개를 모두 포착했다. 숫자 항목은 15행 상한으로 표 밖에 요약됐으며 실행 JSON에 위치와 측정 근거가 남았다. 다만 내보내기 화면에서는 의미 있는 도형의 대비가 또 빠졌다. 네 번째 수정본은 색상 측정 범위를 명확히 하고, 같은 요소나 같은 수정안이라는 이유만으로 독립 원인을 합치지 않도록 했다.

## 검증 설계

기존 읽기 목록을 원본과 수정 Paul에 다시 맡긴다. 별도로 내보내기 기록 화면을 새 문맥의 원본·Paul 에이전트에게 맡긴다. 두 조건의 요청·앱 파일은 같고, 도구는 Playwright CLI로 고정하며 상속 모델/설정에 별도 override를 주지 않는다. 정확한 모델 ID, 토큰, 비용은 노출되지 않는 경우 알 수 없음으로 남긴다.

새 과제에는 기존 문제를 알려주지 않고, 정상·사용 불가 행동, 성공·실패·재시도, 키보드와 반응형·타이포그래피를 검토하게 한다. 제품이 의도한 평면 스타일, 한국어 행동 이름, 직선 따옴표와 세 점은 불필요한 교정 여부를 확인하는 대조 조건이다. 원본만 발견한 항목은 독립 근거로 유효성을 판단하며 건수로 승자를 정하지 않는다.

Markdown-only 구현은 별도 후보 실행이다. 없는 이미지에 대한 충실도 주장을 하지 말라는 지시가 실행 요청에도 포함되므로 그 보고 문구는 완전한 blind 평가가 아니다. 실제 구현 치수·상태 보존과 불필요한 Figma 의존 여부를 관찰한다. 이것만으로 원본의 이미지/Figma 구현 역할과 동등하다고 판정하지 않는다.

원본도 지원하는 이미지 입력은 별도 원본·Paul 구현으로 비교한다. 판정자가 만든 동일한 1280px·390px 기준 이미지와 동일한 시작 코드를 제공하고 CSS 한 파일만 수정하게 했다. 기준 이미지는 후보 출력에서 추출하지 않았다. 최종 v4 리뷰는 입력과 환경이 그대로인 원본 r5-a/r6-a 및 이전 유효한 발견을 비교 기준으로 재사용한다. 원본을 새로 실행했다고 기록하지 않는다. 이미지 구현에 쓰인 build-design과 design-browser는 v4에서도 내용이 같다.

읽기 목록은 상태 알림과 필드 오류 연결을 별도 행으로 보고했다. 숫자 항목은 15행 상한으로 상세 표 밖에 요약했고, 실제 `#count`의 `fontVariantNumeric: normal`은 관찰 JSON에 남았다. 이를 누락으로 숨기거나 표 안의 행으로 부풀려 세지 않았다. 내보내기 화면은 동작하는 busy guard와 버튼의 pending 상태 미노출을 구분했다. 새 권고의 개수로 기존 발견의 누락을 상쇄하지 않았다.

판정자는 이미지 구현 두 조건과 Markdown 구현을 별도 Playwright 세션에서 다시 조작했다. 양쪽 이미지 구현은 같은 기존 토큰 조합으로 제목 줄높이를 31.2px 추정에서 32px로 반올림했다. 사전 허용 범위 2px 이내이며 차이를 양쪽 보고서에 공개했다. 실제 픽셀 동일성이나 픽셀 차이 점수는 주장하지 않는다. 색상은 기존 토큰을 보존했고, 초기 화면의 시각 비교와 실제 geometry를 확인했다.

판정자는 별도 Playwright 세션에서 삭제 직후 Enter로 다음 삭제가 진행되지 않으며, Tab 한 번이 필요하고, 빈 목록에서 입력으로 돌아오려면 Tab 두 번이 필요한 것을 확인했다. 이는 전체 키보드 차단과 구분되는 연속성 비용이다. 실제 화면낭독기 발화 실패로 확대 해석하지 않는다. [로컬 재현 및 반환값](../../.scratch/design-quality-improvement-20261010/judge/focus-results.txt)을 보존했다.

검증용 화면 자체의 `Block` 판정과 스킬 비교의 합격 여부는 다르다. 두 예제는 의도적으로 결함을 포함하며, 결함을 찾아 `Block`으로 보고하는 것이 과제다.

## 저장소 검증과 남은 한계

- `npm run check`: 36개 테스트 통과. 56개 스킬 기록과 27개 promoted 경로의 출처·호출 구성이 일치.
- `claude plugin validate . --strict`, 변경 스킬 7개의 형식 검사, `git diff --check`: 통과.
- 고정 원본 해시 65/65, adaptation digest 13/13, 호출 정책과 MIT 고지 13/13 보존. 원본 파일은 46개 동일·18개 수정·삭제 0개. [현재 감사](source-audit-2026-10-10-repair.json).

수정 버전들을 하나의 최종본 반복 실행으로 합산하지 않는다. 최종 v4 리뷰는 두 개발 과제에서 각각 한 번 실행했고, 이미지 구현도 단순한 한 화면이다. 숨겨 둔 평가 세트나 통계적 비열등성 검정이 아니다. 정확한 모델 ID와 토큰·비용은 알 수 없고, 자동 스킬 발견은 시험하지 않았다. 원본의 모든 결과를 맹목적으로 정답으로 삼지 않고, 개별 근거와 실제 과업 영향을 확인했다.

17개 전체의 연결, 각 도메인의 독립 실행, Figma 및 복잡한 다중 화면 구현, 명시 호출 5개 스킬의 산출물, IA·user-flow·wireframe의 비교 품질은 이번 합격 범위가 아니다. 실제 스크린리더·실기기·브라우저 확대도 완전 검증하지 않았다. 전용 모션 설계·디자인 시스템 구축·성능 QA를 이 결과로 인증하지 않는다.

사용자 검증과 명시적 승격 승인 전까지 17개 후보는 `in-progress/`에 둔다. 이번에는 설치·승격·커밋·푸시·배포를 하지 않았다. 다음 검증 단위는 명시 호출 역할들의 실제 과제와 복잡한 구현 과제이며, 각 과제에도 같은 원본 하한을 적용한다.
