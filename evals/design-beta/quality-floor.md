# Original quality is the minimum

The user set the first acceptance rule on 2026-10-10: every forked, cloned or benchmark-derived design capability must produce results at least as good as its relevant original. Local convenience, Korean support and additional features matter only after preserving that baseline. This is an acceptance requirement, not a claim that the current beta has met it.

## Choose a fair baseline

For a direct adaptation, use the actual original skill and its required references at the registered immutable revision. Preserve notices and record every changed, added or removed file. A current upstream update requires a separate reviewed baseline; this evaluation does not silently advance source revisions.

For combined or selectively adopted work, compare each inherited capability against its owning source on an applicable task. Judge the composition and handoffs separately. For independently authored work with conceptual influences, name the closest applicable source workflow when one exists, and compare only the overlapping capability. If no equivalent source exists, use the task's observable contract and a no-skill control; record source parity as not applicable, not passed.

An original file hash proves source identity. A retained rule proves instruction preservation. Neither proves equal outcomes. An original's independently verified error is also not a target to imitate; record it and check both results against the user's task.

## Compare actual use

Before dispatch, fix the task and evaluator-owned acceptance criteria. Keep the model/settings, tools, access, time budget, fixture, initial state and requested outputs equivalent. Isolate arm contexts, record automatic discovery limits, and withhold rubrics and other outputs from executors. Preserve failed attempts, interventions, missing telemetry and exact input/output hashes.

Use the smallest realistic task that exercises the changed behavior. A review trial measures review, not implementation. A happy path measures that path, not every state. Include independent tasks and repeat runs before claiming parity across a role. A three-arm no-skill/original/Paul comparison can establish the value of the skill separately from the cost of adaptation; a two-arm test measures only the adaptation question.

Assess outcomes in this order:

1. Required task completion, behavior and state coverage.
2. Correctness, important missed findings, unsupported findings and evidence fidelity.
3. Accessibility, responsive usability and scope preservation.
4. Visual fidelity or visual quality where the task produces a design, with human review.
5. Recoverability, repeatability, time and measured resource cost.

A critical issue found by the original and missed by Paul blocks acceptance. Cosmetic gains cannot compensate. New regressions, unsupported completion claims and broken original capabilities also block acceptance. For less clear tradeoffs, report paired findings and obtain a human decision instead of hiding them in an aggregate score. Missing cost data stays unknown.

## Record a bounded decision

| Status | Meaning |
| --- | --- |
| Not compared | No applicable paired execution exists. |
| Regression observed | A confirmed outcome is worse than the baseline; adoption/promotion is blocked for that capability. |
| No regression observed in this case | The executed case met the criteria; other tasks and repeatability remain unverified. |
| Role parity supported | Repeated representative and independent tasks support the declared role, with no unresolved critical regression and human acceptance where needed. |

Every decision names the source revision, candidate digest, task, executed behaviors and limits. If a regression appears, preserve its failing evidence, repair the smallest responsible difference, and rerun that case plus an independent case. Do not silently replace a failed attempt with the repaired result.

Keep unproven adaptations in beta. Promotion additionally requires the existing explicit user approval and packaging process. A package PASS, more detailed prompt, copied reference, positive model review or one passing example cannot satisfy the overall quality floor.
