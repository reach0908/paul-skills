# Paul Skills 0.4.3 정식 배포와 전역 적용 검증

**0.4.3 정식 패치를 발행했고 Codex와 Claude의 사용자 전역 설치를 갱신했습니다.** 양쪽의 스킬 파일 174개와 플러그인 명세 1개가 정식 태그와 일치합니다. 전체 정식 스킬은 44개, 디자인 스킬은 17개입니다.

**새 CLI 세션 12개에서 색상 답변의 일관성 기준은 모두 통과했습니다. 호출과 필수 참조 읽기까지 포함한 종합 결과는 Codex 5/6, Claude 5/6입니다.** Codex 한 건은 대비 참조 문서를 읽지 않았고, Claude 한 건은 자동으로 스킬을 호출하지 않았습니다. 배포와 설치는 완료됐지만 모든 실행 경로가 통과했다는 판정은 하지 않습니다.

시험은 2026-10-14에 준비·시작했고 보고서는 한국 시간 2026-10-15에 마무리했습니다. 폴더 날짜는 준비 날짜를 유지합니다.

## 패치와 시험 범위

이번 패치는 `better-colors`가 계산한 색상쌍, 실제 렌더링 검증, 미확인 사항을 구분하고 마지막 요약에도 그 상태를 유지하도록 보완합니다. 모든 스킬 파일 174개는 [배포 전 검증한 후보](../design-color-evidence-2026-10-14/REPORT.md)와 같습니다. 플러그인 버전 명세만 0.4.3으로 달라졌습니다. 원본 출처의 고정 리비전을 변경하지 않았습니다.

실제 전역 설치를 사용해 호스트별 여섯 사례를 한 번씩 실행했습니다. Codex의 임시 HOME 설정이나 Claude의 플러그인 디렉터리 덮어쓰기를 사용하지 않았습니다. 각 사례는 별개의 CLI 세션과 중립적인 임시 폴더에서 실행했고, 질문·판정 코드·프로토콜은 실행 전에 고정했습니다. 질문은 배포 전 후보 시험과 동일합니다.

| 사례 | Codex | Claude |
| --- | --- | --- |
| 최초 색상 계획 요청, 동일 질문 세 번 | 3/3 | 3/3 |
| 사용자 사진 위 반투명 배경, 자동 호출 | 1/1 | 0/1: 스킬 미호출 |
| 합성 조건을 모두 준 폼 색상 검토, 명시 호출 | 0/1: 참조 읽기 누락 | 1/1 |
| staged 글꼴·색상 리뷰의 호출 경계 | 1/1 | 1/1 |
| **종합** | **5/6** | **5/6** |

답변 내용만 평가하면 각 6/6입니다. 응답 의미 판정은 유지보수 에이전트가 고정 기준에 따라 전체 답변을 읽고 수행했으며, 독립적인 사람의 블라인드 평가가 아닙니다. 주어진 합성 조건에서 계산 가능한 것을 실제 화면 검증과 구분했고, 측정하지 않은 화면을 통과로 보고하지 않았습니다. 명시 폼 검토에서는 활성 placeholder와 readonly의 대비 요구, 실제 disabled의 예외, APCA의 보조 역할을 구분했습니다. 이 의미 평가는 모든 디자인 조언이 정확하다는 보증이 아닙니다. Claude의 한 준비 답변에 있었던 테마 방식 병행에 대한 과도한 일반화도 별도 부수 관찰로 기록했습니다.

두 호스트의 자동 발견 목록에는 디자인 12개가 모두 있었고, Claude의 명시 호출 목록에는 17개가 모두 있었습니다. 사용자 전용 스킬의 무단 실행은 없었습니다. staged 사례는 양쪽 모두 `better-interface`만 읽고 명시적인 `interface-review staged` 명령을 제공했습니다. 실제 변경 리뷰까지 실행한 시험은 아닙니다.

## 남은 실패와 해석

### Codex: 필수 대비 참조 읽기 증거 없음

`installed-resolved`에서는 정식 0.4.3의 `better-colors/SKILL.md`가 명시 호출로 주입됐지만, `contrast.md`를 읽는 도구 호출이 없었습니다. 답변의 기준 구분이 맞더라도 참조 문서 전체를 읽었다고 간주하지 않습니다. 고정 프로토콜이 요구하는 `contrast_reference_fully_read`는 실패로 남겼습니다. [세션 증거](codex/installed-resolved.json).

이 세션의 [Codex 알림](host-notices.json)에는 스킬 설명이 문맥 예산에 맞춰 축약됐다는 안내가 있었습니다. 실제 자동 발견 목록은 올바르게 전달됐고, 명시 스킬 본문도 주입됐습니다. 안내와 참조 누락 사이의 인과관계는 확인하지 못했습니다. 설치 실패나 구버전 로드로 설명할 근거는 없습니다.

### Claude: 이미지 배경 질문에서 자동 호출 누락

`installed-unknown`에서는 정식 플러그인이 활성화되고 자동 발견 목록에 `better-colors`가 있었지만, 파일 목록을 한 번 조회한 뒤 Skill 호출 없이 답했습니다. 조건부 대비 계산과 남은 검증의 설명은 의미 기준을 통과했으나, 요청에 맞는 스킬을 실제로 선택·로드한 증거가 없어 `expected_skill_invoked_and_loaded`는 실패입니다. [세션 증거](claude/installed-unknown.json).

Claude의 별도 명시 호출에서는 수정된 스킬과 `contrast.md` 전체를 읽었고 적용 기준도 지켰습니다. 명시 호출의 성공은 자동 호출 실패를 대체하지 않습니다. 이번 패치는 발견 설명을 변경하지 않았고 배포 전 같은 질문은 통과했지만, 이것만으로 원인이나 발생률을 확정할 수는 없습니다.

두 실패를 성공할 때까지 재실행하지 않았습니다. 남은 보완의 우선순위는 이미지·투명도 대비 질문의 자동 선택과, 대비 기준을 답할 때 관련 참조를 실제로 읽는 경로입니다. 그 보완은 추가 원인 확인과 고정된 비교 시험이 필요합니다. 이번 배포 보고 과정에서 스킬을 추가로 수정하거나 0.4.4를 발행하지 않았습니다.

## 증거 검사와 보존

- 패키지 검사 38개, 증거 검증기 테스트 14개, 엄격한 플러그인 검사를 통과했습니다.
- 설치 경로·버전·활성 상태, 전체 파일 해시, 고유 세션 12개, 입력 파일 보존, 응답 해시에 결속된 의미 판정을 확인했습니다.
- 최초 증거 검증기는 모든 사례에서 원문·참조 로드가 성공해야 무결성 검사를 끝낼 수 있었습니다. 실패한 실행도 정확히 기록됐는지 검사하도록 증거 검증기만 보완했습니다. 원본 코드와 해시를 보존했고, 질문·모델 실행·판정기·합격 조건은 바꾸지 않았습니다. 두 사례의 실패 판정은 그대로입니다. [보완 기록](verification-amendment.json).
- 0.4.2의 Codex 모순 답변과 배포 전 Claude 기준 답변의 실패는 원문·실패 판정·해시를 그대로 보존했습니다. [보존 증거](preserved-history.json).
- 원시 대화·인증·전체 설정은 비공개 `.scratch`에만 있습니다. 공개 파일에는 합성 질문, 정제한 답변, 필요한 호출 기록, 해시와 판정만 담았습니다.

```bash
python3 evals/design-color-0.4.3-release-2026-10-14/verify_evidence.py
python3 -m unittest discover -s evals/design-color-0.4.3-release-2026-10-14 -p 'test_*.py' -v
```

무결성 검사 결과는 `integrity_pass: true`, `installation_verified: true`, `source_application_passed: 10/12`, `source_application_verified: false`, `full_sample_passed: false`입니다. 이 검사는 로컬 정식 태그와 기록된 0.4.3 설치 캐시가 남아 있는 환경에서 실행합니다. 설치 증거 재수집 스크립트는 공개하지 않은 원시 설치 조회 기록이 필요합니다.

## 비용과 적용 한계

Codex CLI 0.146.0에서 gpt-5.6-sol/xhigh, Claude Code 2.1.296에서 claude-opus-5-5/xhigh를 사용했습니다. 각 세션의 시간 제한은 360초, Claude 비용 상한은 1달러였습니다. Claude 여섯 세션의 보고 비용 합계는 **USD 2.0759344**이며 실제 청구액과 Codex 비용은 알 수 없습니다. 환경 실패·제한 시간 초과·모델 재실행은 없었습니다.

이 결과는 수정본의 배포·전역 설치와 좁은 회귀 표본에 대한 것입니다. 기존 Codex 모순은 동일 질문을 세 번 실행한 이번 표본에서도 재현되지 않았지만, 확률적 오류가 제거됐다고 주장하지 않습니다. 디자인 17개 역할의 품질 동등성을 새로 검증하거나 실제 제품 화면의 대비를 측정한 시험도 아닙니다.

설치된 수정본을 사용하는 새 CLI 세션은 확인했습니다. 이미 열려 있던 대화의 스킬 문맥이나 데스크톱 UI 전체가 즉시 갱신됐다고 주장하지 않습니다. 다음 작업은 새 대화에서 시작하는 것이 적용 범위를 명확히 합니다. [공식 플러그인 안내](https://learn.chatgpt.com/docs/plugins).
